# 体系外の解釈文書はビューと定め、刻印で参照時点を義務づける

## 背景

外部の独立レビュー（2026-07-28）が、監査 error 0 の状態で README の主張3件
（要求数・Hook イベント数・検査数）の古びを指した。README は分類の記録で
「非文書」であり、依存グラフのノードにならず、どの検査も主張を読まない。
検査が配線された主張（test_meta が見る plugin/README の技能一覧）だけが鮮度を
保った。分類の記録（ADR-021）は「見た」の記録であって「監視する」の宣言では
なく、正本を解釈して書かれた文書と、正本と無関係な文書（CHANGELOG（変更履歴
ファイル）等）が同じ「非文書」に落ちる。解釈文書の将来は書いた時点では
分からず（メモが後日昇格・転載される）、参照時点（どの正本の・いつの状態を
見て書いたか）は書いた瞬間にしか安く採れない。[R2][R8]

## 却下した選択肢

- 数値の主張だけをレジストリと突き合わせる検査を作る。列挙できる断片にしか
  効かず、解釈の本文には一般化しない。
- README を投影へ昇格する。解釈は読者に合わせて人が書くもので、モデルから
  再描画できない（ADR-029 が投影化を却下した理由はここでも生きる）。
- git の履歴から参照時点を導出する。体系は履歴を持たず（ADR-064）、ファイルが
  体系の外へ複製された時点で出所が失われる。ファイルの中の刻印だけが内容と
  共に移動する。
- 公開文書だけに義務を絞り、メモは期限だけにする。メモの昇格は止められず、
  刻印の欠落は事後に復元できない。義務は分類に対して一律とし、強制の重さだけ
  を公開面に寄せる。

## 決定

体系外の解釈文書の類型「ビュー」を定める。ビューは、正本をある時点で人向けに
解釈した体系外の文書であり、手で保守し、刻印を必ず持つ。

- 分類の記録（`.md-intake`、書式の正本は ICD-005）に第四の分類「ビュー」を
  足す（`パス: ビュー`）。照合は完全一致をプレフィクスより優先する。
- 刻印はファイル内の一行
  `<!-- doctrine:view src=<出所> as-of=<版> date=<YYYY-MM-DD> refs=<id,…> -->`
  とする。`src` と `date` は必須、`as-of` は出所の版（本リポジトリでは
  plugin.json の版）、`refs`（参照した文書 id の列挙）は任意。
- 用語辞書で「ビュー」を投影の禁止同義語から外し、独立の承認語にする
  （投影＝機械が描画する、ビュー＝人が解釈する）。「刻印」も承認語にする。
- 検出は三層に配線する。①リンタ: ビューと分類された文書の編集で刻印が
  無ければ助言する（拒否しない）。②監査（view_stale）: 刻印の欠落は warn、
  `refs` の参照先が刻印の `date` より新しい・現行でない・実在しないは
  advisory、`refs` 無しなら現行文書の `updated` の最大値と比べて advisory。
  ③リリース整合の門: 公開ビュー（README.md・plugin/README.md・
  CONTRIBUTING.md（寄稿の方針ファイル））の `as-of` が版番号の正本と
  食い違えば止める（リリースごとの再確認の義務）。
- CLAUDE.md（Claude Code が読む根の案内ファイル）と AGENTS.md（他の
  エージェント向けの根の案内ファイル）は ADR-029 のまま変えない。「知識を
  集めない。入口だけを示す」の規範が主張の混入を防ぐため、刻印は課さない。
- `spec/doctrine.ja.md` はビューにしない。解釈ではなく出所（正本）であり、
  その鮮度はリリースの手順（PROC-001）が受け持つ。

## 帰結

- README・CONTRIBUTING・plugin/README をビューへ再分類し、初期の刻印を打つ。
  README の古びた主張3件はこの変更で直す（CHANGE-004）。
- 監査の検査群に view_stale が加わる（ICD-005・SPEC-011 の検査数が動く）。
- 刻印は内容の正しさを保証しない。保証するのは「参照時点から正本が動いた」
  ことの検出だけである（コードの指紋と同じ規律。DECIDED-001 事実10）。
- 「投影」の意味で「ビュー」と書く誤用は、用語チェッカーでは今後捕まらない
  （承認語になったため）。二語の区別は用語辞書の定義と doc-review に委ねる。
- ビューを「非文書」へ再分類すれば義務を逃れられる。この骨抜きは機械では
  判定できず、WATCH-001 で監視し docs-curate の定例に委ねる。
