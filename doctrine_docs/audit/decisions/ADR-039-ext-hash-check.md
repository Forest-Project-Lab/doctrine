# EXT の hash 検査を実装し、hash 指定を沈黙で素通りさせない

## 背景

EXT（外部アンカー）の検査方法として、仕様 §3.2 とテンプレートは exists・hash・review_by の三つを提示していた。しかし監査は exists だけを実装し、`検査: hash` を**警告一つ出さず飛ばして**いた（#70）。さらに旧コードは `if "exists" not in check: continue` としていたため、hash を選ぶと exists 検査も効かず、対象ファイルを削除しても error が出ない——exists より弱い状態へ静かに劣化していた。

利用者が「内容の指紋で追われている」と信じて hash を選んでも、実際は何も検査されない。これは仕様と実装の齟齬であり、沈黙する形なので R11（沈黙する故障の禁止）の精神に反する。リポジトリ内が正本の静的データ（CSV 等）が変わっても依存文書へ伝播しない穴（#76 関連）の一因でもあった。

## 却下した選択肢

- **hash を仕様・テンプレートから落として §7 に「未実装」と明記する**: 機能を減らす方向。CSV 等のデータ変化を追う需要は実在し（EXT の主目的の一つ）、標準ライブラリ `hashlib` だけで実装できるため、落とすより実装する。
- **外部の指紋台帳に期待値を持つ**: 正本の二重化。EXT 文書自身に期待値を書くのが最小。

## 決定

`hashlib.sha256` で hash 検査を実装する。EXT 本文に `- 指紋: sha256:<64桁>` を書くと、監査が対象ファイルの sha256 を計算して照合する。

- 対象の不在: exists でも hash でも error（最も重い）。hash が exists を無効化しない。
- 指紋一致: 無言。
- 指紋不一致: warn（内容が変わった。依存文書の追随を確かめ、確認後に指紋を更新する）。
- `検査: hash` だが `指紋:` の行が無い: warn（検査できない。期待値を書くか exists にする）。決して沈黙で素通りしない。
- URL 対象は従来どおり通信しない（ADR-031）。

テンプレート `ext.md.tmpl` に `- 指紋:` 欄を足す（hash を選ぶときだけ書く）。検査名は既存の `ext_anchor_broken` のまま（重大度は不在=error、指紋不一致・期待値なし=warn。ICD-005 の表と整合）。

## 帰結

- CSV 等リポジトリ内データの内容変化が、EXT の hash で検出できる（変化→warn→依存 SPEC の追随を促す）。
- hash 指定の沈黙劣化が消える（R11 準拠）。
- 期待値の更新は人手（内容変化を確認してから指紋を書き換える）。自動更新はしない（変化の看過を防ぐため）。
- チャンク読みで大きなファイルでもメモリを食わない。標準ライブラリのみ。
