# 投影の列挙は各行の最初の id だけから採る

## 背景

投影ドリフト検査（SPEC-011）は「Overview に列挙された id 集合」と現行文書集合の差を error で指す。この「列挙」の判定が、投影の本文に現れる**すべての** id トークンを数えていた（`_body_id_refs`。参照検出との共用）。

2026-08-03 の実測で偽陽性が出た。後継の ADR が題名に先行決定の id を含むと（「（◯◯を置換）」という自然な題名）、Overview の題名セルにその id が写り、検査が「現行でない文書が載っている」と誤って咎めた。列挙とは行を与えられることであって、他の行の題名に名が出ることではない。用語チェッカーが語の途中の一致で咎めた欠陥（ADR-082）と同じ、「照合が意図より広い」類型である。

## 却下した選択肢

**`_body_id_refs` 自体を絞る。** この関数は dead link の検出と、受理 ADR の着地検査の参照集合にも使われる。そこでは自由文の中の id も参照として数えるのが正しく、絞れば別の検査が緩む。共用の器を一つの場の都合で変えない。

**後継の題名に旧 id を書かない規約で回避し続ける。** 実際に一度この回避を行ったが、規約は忘れられうるし、後継 ADR の自然な題名を禁じる負担が残り続ける。照合の側を意図に合わせるのが正道である。

**何もしない。** 後継による置換（ADR-044 の正規の道）を使うたびに偽陽性が再発しうる。

## 決定

**投影（Overview・ICD 一覧）の「列挙された id 集合」は、各行の最初の id トークンだけから採る。行の後方（題名セルなど）に現れる id は列挙ではない。**

一覧形式（`- SPEC-001`）でも表形式（先頭のセルに id、後のセルに題名）でも、行の主は行頭側の id であり、後方の id は写り込みである。判定は投影ドリフト検査専用の抽出器が持ち、参照検出の共用器（`_body_id_refs`）は変えない。

## 帰結

- 実装は `docs-audit.py` に投影専用の抽出器を足し、Overview・ICD 一覧の二箇所の呼び出しだけを差し替える。
- 受入は TEST-011 が凍結する——題名に現行でない id を含む行が偽陽性を生まないこと、行を与えられた現行でない id が引き続き error であること。
- WATCH-001 に一項を足す（題名の中の id を「載っている」と読む取り違えを戻さない）。
- 保証限界: 投影の散文の行に id が現れれば、その行の最初の id は列挙と数えられる。描画器は散文に id を書かないので実害は無いが、判定は行単位であり文脈は読まない。
