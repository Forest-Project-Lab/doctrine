# 期限が唯一の見張りなら、期限は短くする

## 背景

外部アンカー（EXT）は統治木の外への依存を登録する（ADR-026）。四本あり、**そのうち三本は
機械が常時見張っている**。アンカー自身がそう書いている。

| アンカー | 対象 | 検査 |
|---|---|---|
| EXT-002 | `.claude/settings.json` | `exists` |
| EXT-003 | `spec/doctrine.ja.md` | `hash`（内容の指紋） |
| EXT-004 | `.github/workflows/checks.yml` | `exists` |
| **EXT-001** | `実行環境の仕様(ファイルではない)` | **`review_by のみ`** |

`EXT-001` だけは機械が何も見ていない。**`review_by` が唯一の見張りである。**
にもかかわらず、四本すべてが同じ期限（`2026-10-26`。更新から約3ヶ月）を持っていた。
**唯一の見張りである一本が、形式に過ぎない三本と同じ寛容さを与えられていた。**

**実測。** 2026-08-02 の一日で、`EXT-001` が指す実行環境の仕様について三件の反証が出た。

| 反証 | 内容 |
|---|---|
| ADR-077 | `additionalContext` を運ぶ事象に `PreCompact` は含まれない |
| ADR-078 | 事象は7個ではなく30個ある |
| ADR-080 | settings 由来の hooks は live reload される（固定されない） |

`ADR-032` は自ら「実行環境がこの挙動を変えたら、`EXT-001` の再検証で拾い、本 ADR を置換
する」と書いていた。置換は起きたが、**拾ったのは定例ではなく外部レビューだった**。期日の
約3ヶ月前である。定例は一度も先に捉えていない。

## 却下した選択肢

**四本すべての期限を短くする。** 三本は機械が常時見張っており、対象が消えれば即座に error に
なる。期限を短くしても点検の手間が増えるだけで、何も守られない。**見張りの有無で分けるのが
筋である。**

**外部の仕様変更を機械で検知する。** 通信しない（確定事実7）。統治はリポジトリの中で閉じる
（`NONGOAL-001`）。できないことを増やさない。

**期限の超過を待たずに督促する。** 超過の検査（`review_by_overrun`）は既にある。問題は超過の
検出ではなく、**超過するまでの窓が長すぎる**ことである。

**「変化速度」を宣言させ、速度ごとに上限を持つ。** 速度は書き手の見立てであり、機械には
検められない。見立てを増やすより、**既に書かれている事実（何が見張っているか）から導く**
ほうが確かである。アンカーは既に `検査:` の行でそれを宣言している。

## 決定

**`検査: review_by のみ` と宣言したアンカー —— すなわち機械が何も見ていないアンカー ——
には、期限について二段の要求を課す。**

1. **`review_by` が無いのは誤り（error）。** 唯一の見張りが不在なら、その境界は沈黙して
   開いている（確定事実12 と同じ形）。
2. **`review_by` が `updated` から30日を超えるのは警告（warn）。** 唯一の見張りが緩い。

機械が見張っているアンカー（`exists`・`hash`）には課さない。対象が消えれば即座に error に
なるので、期限は補助にすぎない。

**段を分ける理由**: 見張りの不在は事実であり機械で判じられる。30日という数は**見立てで
あって測って出した値ではない**（下記の保証限界）。事実には error を、見立てには warn を
当てる。

## 帰結

- 唯一の見張りが緩いアンカーが、監査の要約に出る。セッション冒頭の注入がそれを運ぶ。
- 見張りの区別が、書き手の宣言（`検査:` の行）から自動で導かれる。新しい欄を増やさない。
- 保証限界: **30日は見立てである。** 実測では反証が更新から約5〜7日で届いており、30日でも
  定例が先に捉えたことにはならない。この決定が縮めるのは窓であって、**先に捉えることを
  保証しない**。数を測って出せるだけの実績がまだ無い。
- 保証限界: 警告は拒否ではない。無視できる。無視され続けるなら段を上げる（それは次の決定）。
- 保証限界: 外部の仕様変更そのものは検知しない（通信しない）。この決定が扱うのは
  **こちらの点検の間隔**だけである。
