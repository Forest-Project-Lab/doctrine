# 壊れた日付をその名で咎める。鮮度の検査に古びと言わせない

日付の解釈そのものは ADR-099 が正本化した（越境の id は辺で指さず、本文で参照する）。
こちらは**解せなかったときに何と言うか**を決める。

## 背景

`updated` の値が日付でなくても、**どの検査もそれを「日付が壊れている」とは言わない。**
実測した（`updated: 2026-13-45` を持つ現行の仕様）。

| 経路 | 何と言うか |
|---|---|
| ファイル単位のリンタ | **一件も言わない** |
| 全件監査 | `stale_current`（**陳腐化の疑い**） |

**検出ではなく取り違えである。** 読み手は「更新が古い」と読むが、実際は「日付が壊れている」。
直す先が違う。出所は二箇所にある。

- `_is_stale` が「日付不明なら真（古び扱い）」と決めている（`stale_draft`・
  `stale_proposed`・`orphan` が使う）。
- `stale_current` が「解せないなら超過」と書いている。

**同じ取り違えを、もう一つ見つけた。** 壊れた `review_by` は、
`review_by_overrun`（超過）という名で誤り（error）になっていた。

```text
review_by_overrun (error): review_by の日付形式が壊れている: 2026-13-45
```

**形式の誤りは超過ではない。** 名が事実を語っていない。

そして測ると、**`updated` と `created` は形すら検められていなかった**（`review_by` だけが
形を検められ、しかし誤った名で報されていた）。いまの木に不正な日付は **0 件**である。

## 却下した選択肢

**`stale_current` の文言を直すだけ（報告が挙げた案）。** 取り違えは消えるが、
**壊れた日付そのものは依然として所見にならない。** そして `stale_draft`・
`stale_proposed`・`orphan` の取り違えは残る。

**形だけ見て実在を見ない。** `2026-02-30` が通る。正本は実在まで見るので、そこで止める
理由が無い。

**壊れた日付も引き続き「古び」として報せる（安全側の保持）。** 一つの欠陥が二つの名前で
出る。**名が二つあると、直す先が分からない。** 安全側は保たれる —— 壊れた日付は
誤り（error）で必ず出るので、黙って見過ごされることはない。**より重い側で、より正確な
名前で報せる。**

**`review_by` の形式の誤りを `review_by_overrun` に残す。** 名が事実を語らない状態を
残すことになる。**壊れた日付は、鍵に依らず一つの名前で報せる。**

**ファイル単位のリンタだけに置く。** 呼び手は全件のリンタを回していない（ADR-098 と
同じ理由）。報告された実害が直らない置き方はしない。

## 決定

**壊れた日付を `bad_date` の名で咎める。鮮度の検査は、日付が読めないときに古びと言わない。**

1. **新しい検査 `bad_date`（error）を置く。** 節点の `updated`・`review_by` の値が
   正本で解せなければ挙げる。値をそのまま添える。
2. **`review_by` の形式の誤りを `review_by_overrun` から外す。** あちらは**超過だけ**を
   見る。名が事実を語る形へ戻す。
3. **鮮度の検査は、日付が読めないときに黙る。** `_is_stale` は解せない値で偽を返し
   （`stale_draft`・`stale_proposed`・`orphan` が鳴らなくなる）、`stale_current` も同様に
   飛ばす。**一つの欠陥は一つの名前で出す。** 安全側は `bad_date` が保つ。
4. **ファイル単位のリンタも同じ正本で検める。** `updated`・`review_by` は誤り（error）、
   `created` は警告（warn。必須キーではない）。**節点は `created` を運ばないので、
   監査は `created` を見ない**（ADR-098 と同じ非対称であり、同じく明記する）。
5. **重さの配分は見立てである。** `updated` が読めないと鮮度の判定が全部倒れるので
   誤り、`created` は機械の判定に使われないので警告とした。**測って出した数ではない。**

## 帰結

- 壊れた日付が、その名で一度だけ報される。直す先が名前で分かる。
- `review_by_overrun` が超過だけを意味するようになる。
- 保証限界: **解せることは、正しいことではない。** `updated: 1970-01-01` は解せるので
  通る。**日付が事実かは見ない。**
- 保証限界: **鮮度の検査が鳴らなくなる範囲が増える。** 壊れた日付の文書は、
  `bad_date` を直すまで孤児にも陳腐化にも数えられない。**順序としてそれが正しい**
  （読めない日付で古びを判ずるのは、読めない証拠で判ずることである）。
- 保証限界: `created` はリンタだけが見る（節点に無い。確定事実3）。
- 保証限界: 時刻を含む値（要約の `generated_at`）はこの検査の対象にしない。
  フロントマターの日付の鍵だけを見る。
