# 孤児は「放置」を測る。予定した見直しの日は二重に数えない

## 背景

孤児の検査は三条件の連言である（ADR-008）。逆参照ゼロ・陳腐化・再現可能がすべて揃ったとき、取り除きの候補として error を出す。

その「陳腐化」に二つの引き金が入っていた。`updated` が閾値（既定 180 日）より古いことと、`review_by` を過ぎたことである。

2026-08-09 の独立再監査が、この二つ目の帰結を実測した。継続的結合は監査へ固定日を渡さないので壁時計を読む。RESEARCH-002 と RESEARCH-003 は `review_by` が 2026-11-09 で、どちらも逆参照ゼロである。したがって **2026-11-10 に、誰も何も変えていないのに `main` が赤くなる**。日付を八点掃引して二分探索で特定した（11-09 は error 0、11-10 は error 2）。`updated` 起因の陳腐化はどちらも 2027-02-05 まで来ないので、赤の原因は `review_by` だけである。

これは戻してはならない事項の第11項が凍結した形と同じである（2026-08-03 に、誰も何も変えていないのに `main` が赤くなった）。しかも火種を置いたのは、その形を直す作業そのものだった —— RESEARCH の状態の巻き戻しの際に `review_by` を三件へ付与した。

調べると、`review_by` の超過には**専用の検査が既に在った**。`review_by_overrun`（warn）である。孤児が error で同じ事実を数えると、一つの事実が二つの検査から二度出る。重さも違う。

## 却下した選択肢

- **証拠庫（`llm_context: never`）を孤児の対象から外す**。一度実装して測ったところ、この木では孤児の検査の覆いが **0 件**になった（`llm_context: never` は 4 件すべて RESEARCH、`reproducible: true` は 0 件）。検査が二度と発火しない。所有者が一度これを選んだが、この実測を示して選び直した。
- **継続的結合の監査へ固定日を渡す**。`review_by` の意味が消える。期限は暦で進むから意味を持つ。
- **該当の 2 件を期限前に `archived` へ移す**。今回の赤は消えるが、同じ形は次の `review_by` でまた起きる。対症療法である。
- **孤児の重さを warn へ落とす**。取り除きの候補が門を閉じなくなる。放置の検出という本来の役目まで弱まる。

## 決定

孤児の陳腐化は `updated` だけで判ずる。`review_by` の超過を陳腐化の引き金にしない。

二つは測っているものが違う。`review_by` は「予定した見直しの日が来た」という**暦の出来事**であり、`updated` の古さは「誰にも引かれないまま**放置されている**」という状態である。孤児が測るのは後者だけとする。

`review_by` の信号は消えない。専用の検査 `review_by_overrun`（warn）が従来どおり届ける。

## 帰結

- 実測（同じ日付掃引を修正後に回した）: 2026-11-10 は error 0・warn 16（超過の信号は warn で届いている）。2027-02-05 は error 2 —— 180 日の放置は従来どおり孤児として立つ。**覆いは失われない。**
- 門は変更の可否を判ずる装置であって、暦の管理装置ではない。時で起きる整理の促しは warn の側から届ける。
- 同じ事実を二つの検査が別々の重さで数える形が、他にも在るかもしれない。本 ADR は孤児と `review_by` の一組だけを解く。
