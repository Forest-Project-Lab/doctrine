# 監査の検査群を枠と検査モジュールへ分割する — 方針と、分割で変えないものの凍結

## 背景

docs-audit.py は約 1,600 行・30 検査の単一ファイルに育ち、コード検算（ADR-068）が肥大の advisory を自分に出している。検査を足すたびに同じファイルが太る成長曲線は明らかで、固着する前に分割の方針を決める。ただし監査は体系の要であり、分割そのものが挙動を揺らせば本末転倒になる。先に「変えないもの」を凍結してから、移送を小さな変更の列で行う。

## 却下した選択肢

- **動的な読み込み（検査のプラグイン化）**: 検査が黙って読み込まれない故障の面が生まれる。沈黙する検証器の禁止（R11・checks_run）に正面から反する。取り込みは静的な import に限る。
- **検査のクラス階層化**: 共通の形は関数と共有コアで足りている。クラスは重複の削減に効く箇所だけ（オブジェクト指向の限定。ADR-047）で、階層の導入は抽象の先取りになる。
- **一括の大移送**: 一度に全部を動かすと、差分がレビュー不能になり、挙動の凍結（テスト全緑のまま）を検えにくい。一回の変更で一モジュール（一系統）だけを移す。
- **分割しない（現状維持）**: 肥大の advisory を自分で無視し続けることは、検算の権威を自分で削ぐ。

## 決定

1. **形は「枠＋検査モジュール群」とする。** docs-audit.py は枠（引数・グラフ構築・要約の組み立て・書き出し）に痩せ、検査関数は系統別のモジュール（例: 構造・鮮度・投影・体系外・追跡）へ移す。モジュールは共有コアと同じ `_` 名で `plugin/scripts/` に平置きし、静的に import する（動的読み込みをしない）。
2. **分割で変えないものを凍結する。** 検査の名前と重大度（`AUDIT_CHECKS`・ICD-005 の表）・`checks_run` の契約・要約スキーマ・所見の整列順（決定性）・列挙添字と転記表の試験・SPEC-011 が指紋で結ぶ範囲（検査一覧は枠に残す）。分割の各段はテスト全緑・監査全緑のまま行い、これらのどれかを変える変更は分割ではなく別の決定として裁く。
3. **移送は一回の変更で一系統だけとする。** 各段で code-audit の肥大 advisory が減っていくことを進捗の証跡とする。
4. **分割先も検算の対象に含める。** code-audit（ADR-068）の対象は `plugin/scripts` 直下の平置きを前提としており、新モジュールも自動的に import 境界・重複・肥大の検査下に入る。

## 帰結

- 肥大の兆候（advisory）に対して、体系が自分の規範どおりに応答する道筋が決まる。
- 実装は本決定に従う後続の小さな変更の列で行う（本 ADR は方針と凍結のみ。移送の各段は決定を含まないため、変更フローの軽い経路で回せる。ADR-051）。
- 既知の限界: 分割は肥大の症状への応答であり、検査の複雑さそのものは減らない。一関数の肥大（例: 追跡の検査）は移送後も残り、その整理は別の判断になる。
