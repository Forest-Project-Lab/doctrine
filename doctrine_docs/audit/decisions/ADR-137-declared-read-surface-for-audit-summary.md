# 監査要約の読み口を宣言する — 外部利用者は CLI の返す値だけに依存する

## 背景

doctrine-lens の System Map Phase 2（issue #212）は、宣言済み CLI の実測をモデルへ重ねる
overlay の入力として、追跡索引・依存グラフ（ICD-002）に加えて監査要約（`docs-audit/1`）を
挙げ、doctrine 側の意見を求めた。要約のスキーマは ICD-005 が正本化しているが、**外部の
利用者がどの経路で要約を受け取ってよいかは宣言されていない**。体系の内側では、要約は
`.claude/.cache/last-audit.json` を介して context ドメインへ渡るが、実行時状態は契約の
外である（ICD-002 が追跡索引について同じ線を既に引いている。DECIDED-001 事実12）。
宣言なき消費は、実装の内部形が黙った契約になる —— 追跡索引で一度踏んだ形である
（CHANGE-007）。

## 却下した選択肢

- **`.claude/.cache/last-audit.json` を外部契約にする。** 実行時状態であり、置き場も
  書き込みの時機も体系の内部事情で変わる。DECIDED-001 事実12 と ICD-002 の既存の線に
  反する。
- **外部利用者向けの仲介ファイルを新設する。** 第二の受け渡し口は第二の正本になる。
  CLI の返す値というすでに在る決定論の口で足りる。
- **ICD-002 へ相互参照を足す。** 監査の契約の正本は audit の ICD である。二箇所に列挙を
  持つとドリフトする（各ドメインの入口はそのドメインの ICD が持つ、の原則のまま）。
- **何もしない。** lens が cache を直読みするか、宣言なき消費が始まる。

## 決定

外部の利用者（表示製品を含む）は、`docs-audit.py --root <統治木> --json` を実行して
返る値（要約スキーマ `docs-audit/1`）**だけ**に依存してよい。`--today YYYY-MM-DD` を
渡せば同じ入力から毎回同じ結果になる（決定論の口）。`.claude/.cache` の直読みは
これまでどおり契約の外に置く。この宣言を ICD-005 のデータ契約へ書く。

## 帰結

- lens の overlay は、監査要約を「宣言済み CLI の実測」として正々堂々と入力にできる
  （#212 の合意台帳の第4版・第2項の閉じた列挙と整合）。
- 要約に何を載せるかの正本は従来どおり ICD-005（検査群の増減は `checks_run` から導く。
  散文の件数を持たない）。
- 保証限界: 宣言するのは受け取りの経路だけであり、要約の内容の解釈（どの所見を
  どう表示するか）は利用者側の判断に残る。
