# 出所の門は、出所ごとの機械の判定を五値で読み口に載せる

## 背景

doctrine-lens が #294 第5信で挙げた（欠けの5番）。`map-draft-check/1` は所見
（findings）と機械検証不能（unverifiable）の二つの一覧を返すが、**検めて通った出所は
どこにも現れない**。読み手は「この出所は機械が辿れた」を出せず、書き手の自己申告
（Source の `verdict`）をそのまま描くしかない —— 第5信はこれを「捏造」の実体と呼び、
「機械検証不能」を「所見なし」と混ぜて量を過小に報じた実害（10 件と報じた量が強い門
では 40 件だった）も挙げている。あわせて、返す値が測った木の版を名乗らない（複数の
木を測るため `trace-index/1` の単一の `source_revision` の形が合わない）。

## 却下した選択肢

- **スキーマ名を map-draft-check/2 へ上げる。** 既存の鍵の意味は一つも変えない。欄の
  追加は互換であり、版上げは読み手の追随を強いるだけ（確定事実13）。
- **書き手の `verdict` の語彙（present・silent）へ機械の判定を割り当てる。** 主張と
  判定は別の物。同じ語彙に畳むと「確認したと書いた」と「機械が確かめた」の区別が
  消える —— 第5信が器の `unverifiable` 追加で潰したのと同じ「欠落を正常値へ変換する」
  形になる。
- **検証済みの出所だけを新しい一覧に返す。** 検めて通らなかった側（検証不能・食い違い）
  が一覧から消え、読み手が全出所を覆うには三つの一覧の突き合わせが要る。出所ごとに
  一つの判定を返すほうが読み手の再構成を要しない。
- **最上位に単一の `source_revision` を置く。** 測る木が複数在るとき、どの木の版かが
  曖昧になる。単一の木でも `repos` の一項として返し、形を一つに保つ。

## 決定

1. **`map-draft-check/1` に `sources` の一覧を足す。** provenance の各出所につき一項、
   `{where, source, locator, claimed, verdict, reasons}` を返す。`claimed` は書き手の
   自己申告（Source の `verdict` の値）、`verdict` は機械の判定であり、両者を混ぜない。
   模型の中の出現順で返す。アンカー（値を担わない。指し先の記述）は対象外で、その判定は
   従来どおり findings と unverifiable に載る。
2. **機械の判定は五値とする。**
   - `verified`: 機械が辿り、検めた全てが一致した（検めの実績が最低一つ在る）。
   - `mismatched`: 機械が辿り、少なくとも一つが食い違った（この出所の所見が在る）。
   - `mixed`: 一部は一致したが、一部は機械検証の道が無かった（例: 引用は本文に在ったが
     `@rev` は浅い複製で照合できない）。
   - `unverifiable`: 機械検証の道が一つも無かった（URL・束ねられていない接頭・錨の
     無い locator）。
   - `malformed`: 出所そのものが形を成さない（`source` が空・文字列でない）。
   「機械検証不能」を「所見なし」と混ぜない —— `verified` は検めの実績を要し、既定値では
   ない。`reasons` には該当する所見・検証不能の文言を写す（無ければ空の一覧）。
3. **測った木の版は `repos` の一覧で返す。** 各項は `{prefix, source_revision,
   source_dirty}`（旧形の単一 `--repo` は `prefix` を null にする）。ローカル経路は
   載せない —— 利用者の局所的な経路を表示へ漏らさない（`docs-audit/1` の `root` と
   逆向きの、同じ配慮）。あわせて `generator` と `totals` の `by_verdict` を足す。
4. **既存の鍵（findings・unverifiable・totals の既存の欄）は動かさない。** 欄の追加
   だけであり、スキーマ名の版は上げない（確定事実13）。ICD-007 の外部条項の宣言を
   拡張する。

## 帰結

- SPEC-029 に `sources`・五値・`repos`・`generator` の形が載り、TEST-029 が受入を持つ。
- 読み手（表示製品）は「実測」と「書き手の主張」を機械の言葉で分けられる。lens 側の
  `verdict: "present"` の自己申告を検め直す口がこれになる。
- 器の `unverifiable`（lens が Source の enum へ足すと予告した値）とこの五値は別の層で
  ある —— 前者は書き手が「辿れなかった」と申告する語、後者は機械が判じた語。両方が
  揃うと、申告と判定の食い違いも読める。
- 保証限界: 判定は機械が辿れた範囲に限る。引用が主旨を正しく写しているか（意味）は
  判じない（SPEC-029 の射程のまま）。五値は出所（provenance）にだけ付き、アンカーには
  付かない。
