# map-draft-check は複数リポジトリの出所を受ける — 黙る後勝ちを廃し、口を外部条項として宣言する

## 背景

出所検証の門（map-draft-check。SPEC-029）は `--repo` と `--repo-prefix` を各一つしか
受けない。二つのリポジトリにまたがる意味モデル（doctrine と lens の対はまさにこれ）では、
必ずどちらかの接頭の出所が機械検証不能になる —— 外部の実測で、機械検証不能 10 件のうち
5 件がこの形だった（issue #212 第3信・#294 の洗い出し。権限は ADR-151）。さらに現行の
引数の読みは、同じフラグを二度渡すと**黙って後の値が勝つ** —— 誤りを飲み込む口である。
あわせて、この門の返す値（`map-draft-check/1`）は SPEC-029 に形があるだけで、ICD の
外部条項が無い。対象リポジトリでの起草の検収は外部がこの門を叩くので、宣言なき消費に
なっている（依存グラフで踏んだ形と同じ。ADR-153 の背景）。

## 却下した選択肢

- **リポジトリごとに一回ずつ走らせ、和集合で覆う運用で済ませる。** 走らせ分の突合を
  消費者側の手作業に残す。応急の運用としては成立する（是正が届くまでの近道）が、
  恒久の答えにはしない。
- **接頭と経路の対応を設定ファイルで渡す。** 引数で足りるものに新しいファイル形式を
  発明しない。
- **黙る後勝ちを残す。** 誤って二度渡した呼び手に、片方が捨てられたことを告げない口は、
  境界が沈黙して開く形（確定事実12）と同族である。

## 決定

1. `--repo` を `--repo <接頭>=<経路>` の形で**反復可**にする。接頭ごとに出所をその
   リポジトリで解決し、どの接頭にも合わない出所は従来どおり機械検証不能へ回す。
2. 旧形（`--repo <経路>` 一つ＋任意の `--repo-prefix <接頭>`）は後方互換で残す。
   旧形と新形の混在、同じ接頭の二度渡し、`=` 無しの `--repo` の二度渡しは、
   **黙って後勝ちにせず使い方の誤り（終了コード 2）に倒す**。
3. `--trace-json` も `--trace-json <接頭>=<経路>` の反復を受ける（無指定の接頭は、
   従来どおり対応するリポジトリで `trace-index.py` を子プロセス実行して読む）。
   アンカーと追跡索引の突合（SPEC-029 の検査 `D4_ANCHOR_UNMATCHED`）は、接頭の合う
   リポジトリの索引に対して行う。
4. この門の返す値（`map-draft-check/1`）を ICD-007 の外部条項として宣言する。形の正本は
   SPEC-029 のまま動かさない。進化の規約は確定事実13（ADR-152）に従う。

## 帰結

- 二リポジトリの模型で「原理的に検証不能」だった側の出所が検証の道を得る。
  機械検証不能の欄は「検証の道が本当に無いもの」だけを数えるようになる。
- 呼び手の誤りは黙って飲み込まれず、使い方の誤りとして返る。
- 保証限界: 検めるのは出所の実在まで（SPEC-029 の射程のまま）。引用が主張を支持するかは
  この門では測れない。リポジトリ間の模型の器（層B）の設計は本決定の外である。
