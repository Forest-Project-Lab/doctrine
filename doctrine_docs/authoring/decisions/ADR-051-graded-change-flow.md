# 変更フローの段数は、規模ではなく決定を含むか否かで分ける

## 背景

`change-impact` は、どんな変更にも14段を求める。保証限界にも「順序を省けるか（省けない。順序は必須）」と書いてある。誤字の直し、言い回しの調整、リンクの張り替え、投影の描き直しにも、`CHANGE` の起票・`IMPACT`・`ADR` が要ることになる。

これは迂回の動機を作る。NONGOAL 第4項が認めるとおり、ガードが起動しない経路で書かれた文書は止められない。使う人が体系の外へ出る理由を、体系自身が用意してはならない。近縁の仕様駆動の道具でも、新規作成の経路は整う一方、既存の仕様を直す経路が重すぎて使われないという同じ形の不具合が繰り返し報告されている。

一方で、段を省いてよい理由を「小さいから」に置くと壊れる。既定値を一つ変える一行が決定であることは普通にあり、規模と決定の有無は相関しない。

## 却下した選択肢

- **規模（変えた行数・ファイル数）で分ける**: 閾値は必ず誤る。一行の既定値の変更が決定であることも、大量の言い換えが決定を一つも含まないこともある。規模は決定の有無を測る物差しではない。
- **現状のまま全変更に14段を課す**: 迂回率が上がる。統治を通らない変更が増えれば、予防も検出も届かなくなる。重さで守っているつもりが、体系の外に穴を開ける。
- **軽い経路でも `CHANGE` だけは起票させる**: 「何を変えたか」は git が既に持つ。二重の台帳を作らない方針（ADR-034 と同じ形）に反し、軽くした意味も薄れる。

## 決定

`change-impact` の段数を、変更が**決定を含むか否か**で二つに分ける。規模では分けない。

- **決定を含む変更**: 規模に依らず14段を全て回す。選べる案が複数あり、その一つを選んだなら、それは決定である。既定値・上限・順序・型・境界の変更は、一行でも決定を含む。
- **決定を含まない変更**（誤字・言い回し・書式・リンクの張り替え・投影の描き直し・`updated` の更新）: `CHANGE`・`IMPACT`・`ADR` を要さない。影響の列挙（dep-graph の前向きと逆向き）と更新順序（現行 `SPEC` → 実装 → テスト → 投影）は残す。列挙は安く、変更耐性（`[R4]`）の中核だからである。
- 途中で決定を含むと分かったら、その場で14段へ戻す。軽い経路を通ったこと自体は記録しない（記録させれば軽くした意味が消える）。

不変条件の強制は、どちらの経路でも変わらない。降格の可否は削除安全ガードが、越境依存は ICD 依存ガードが、記録されなかった事項は全件監査が見る。これらはフックと CI の層にあり、技能がどちらの経路を通ったかを見ていない。軽い経路が省くのは記録の段であって、強制ではない。

## 帰結

- 誤字の直しに `ADR` を求めなくなる。統治を迂回する動機が一つ減る。
- 予防の強さは変わらない。ガードと監査は経路に依らず効くため、軽い経路は違反の通り道にならない。
- 既知の限界: 「決定を含むか」の判定は意味の判断であり、機械では閉じない（NONGOAL 第1項・第7項と同じ構造）。誤って軽い経路を通った決定は、監査の adr_not_landed では拾えない（`ADR` そのものが無いため）。会話知識の捕捉（`[R12]`）の終端の確認が最後の網になる。
