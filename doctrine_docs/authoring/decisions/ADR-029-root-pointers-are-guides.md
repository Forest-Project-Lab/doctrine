# CLAUDE.md と AGENTS.md は投影ではなく案内と定める

## 背景

両ファイルは冒頭で「これは投影。手で保守しない」と自称するが、投影の一覧(spec §3.9 の 4 種)に無く、`render-projection.py` の描画先でも監査の投影ドリフト検査の対象でもない。誰も描画せず誰もずれを検出しない「自称投影」であり、`.md-intake` の免除根拠(「仕様が投影と定める固定名」)も宙に浮いていた。

## 却下した選択肢

- 正式に投影へ加える(描画器とドリフト検査を作る): 中身は数行の入口の列挙であり、描画器の費用に見合わない。投影の種類を足すのは ADR で決める(ADR-016)が、ここでは足さないと決める。
- 自称のまま放置する: 「手で保守しない」と書かれたファイルを手でしか保守できない矛盾が残る。

## 決定

CLAUDE.md と AGENTS.md の位置づけを「案内」(手で保守する、最小の入口)と定める。両ファイル・仕様・scaffold の文言から「投影」の自称を外し、「知識を集めない。入口だけを示す」の規範は保つ。`.md-intake` の免除根拠は「仕様が案内と定める固定名」に読み替える。あわせて案内に統治の生存期待(セッション冒頭に契約の注入が無ければ統治は死んでいる)の一行を置く(R11。プラグインが死んでも生き残る唯一の伝達路のため)。

## 帰結

- 「投影=描画し直せる派生表示」(ADR-016)の語の意味が守られる。
- 案内の中身の変更は手の編集であり、リンタの用語助言だけが効く(従来どおり)。
- scaffold の雛形(SPEC-015)の文言を合わせる。
