# 走査は勘定を返し、触れた対象を必ず分類する（保存則）

## 背景

走査（`_tracescan.scan_tree`）は dot ディレクトリ・`node_modules`・`.md`・バイナリを黙って除外し、報告するのは上限超過だけだった。実測では、印を持つ 5 ファイルのうち 4 つが無言で消え、所見はゼロだった。除外の経路を敵対的に枚挙すると 29 種あり、うち報告されるのは 3 種だけだった。名前付きパイプが走査の根の配下にあると、大きさの検査を通過した後の `open` が戻らず、**走査全体が永久に停止する**ことも実測した（「決して例外を外へ出さない」という保証の外側で止まる）。

これは体系自身が三箇所で掲げる原則に反する。黙って切り詰めない（SPEC-011）。沈黙する検証器の禁止（`checks_run`、[R11]）。空欄のセルが構造的に存在できない状態を保つ（SPEC-025）。先行事例の調査（RESEARCH-003 類型2）でも、走査の視界の外が「未カバー」でなく「不可視」になり全数性が崩れる故障は、調べた全系統で観測された。

完全性は閉じた集合に対してしか言えない。除外規則が集合を開いている以上、「未分類ゼロ」とは言えない。機械が言えるのは保存則 — **触れた対象の全数が分類の和に一致し、何も黙って消えない** — までである。

## 却下した選択肢

- **全ファイルの台帳（管理済み・管理外の宣言）を持つ**: git には依存できず（DECIDED-001 事実7）、台帳は走査の完全性を超えられない。勘定が先。ファイル単位の宣言は、必要になったときに別の ADR で裁く。
- **除外を所見として一件ずつ挙げる**: 成熟したリポジトリでは除外が数千件になり、雑音が麻痺を生む（RESEARCH-003 類型11: 疑義の洪水は一括クリアという逃げ道を生んだ）。件数は常時、内訳は求めに応じて。
- **新しい監査検査（warn/error）を足す**: 版を上げただけで、既存の緑の監査が赤に変わる。導入の初日に警告を浴びせない原則（ADR-056）と衝突する。勘定は要約に載せ、所見は増やさない。閾値や義務化は使用実績を見て別の ADR で裁く。
- **印なしファイルの一覧を要約へ載せる**: 一覧は規模に比例して肥え、常時投入の上限（DECIDED-001 事実6）を圧す。件数だけを常時報告し、一覧は問い合わせのたびに導出する（ADR-055 と同じ原理）。

## 決定

1. **除外規則の正本表 `EXCLUSION_RULES` を `_tracescan` に置く。** 除外はこの表の規則 id を経由してだけ起こる。規則はディレクトリ単位の刈り（配下は未到達）とファイル単位の分類に分かれる。
2. **`scan_tree` は（範囲・所見・勘定）の三つを返す。** 勘定は、触れたファイル数（reached_files）・寄与（annotated_files。範囲を一つ以上返した）・印なし（unmarked_files。読めたが範囲を一つも返さない — 入れ忘れが住む場所）・除外（excluded。ファイル規則 id ごとの件数）・刈り（pruned_dirs。ディレクトリ規則 id ごとの本数）・打ち切り（truncated）を持つ。**全規則の枠を 0 件でも必ず含める**（SPEC-025 の空欄を許さない原則）。
3. **保存則を試験が凍結する**: reached_files ＝ annotated_files ＋ unmarked_files ＋ Σ excluded。
4. **通常ファイル以外は開かない。** 開く前に stat し、名前付きパイプ・ソケット・デバイスは nonregular に分類する。これが永久停止の経路を除く。読めないディレクトリ・降下しないシンボリックリンクも、黙らず規則 id で数える。
5. **監査は走査が走ったとき、要約に `trace_coverage` を載せる。** 検査所見は増やさない（既存の緑は緑のまま。段階導入）。要約の schema は据え置く — 読み手（注入・鼓動）は未知のキーを無視する前方寛容を既に持つ。
6. **`trace-index` に勘定の問い合わせを足す。** 既定は件数、指定した項の一覧（印なし・規則 id ごとの除外・刈り）はその場で導出する（保存しない。ADR-055）。
7. **統治木が走査の根と重なる呼び方でも規則で刈る。** 従来は根と統治木が同一のとき配下の一部が走査される穴があった（実測）。包含で判じて閉じる。

## 帰結

- 「走査が何を見て何を見なかったか」が、数として毎回の監査に残る。印なしの件数は、触った所から紐づけるラチェット運用の進捗計になる。
- 既存の利用者の監査は版を上げても緑のまま。変わるのは要約にキーが一つ増えることだけ。
- `scan_tree` の返り値が 2 要素から 3 要素になる。呼び手はプラグイン内（監査・trace-index・テスト）だけであり、外部契約ではない（IMPL-021 に記す）。
- 既知の限界: 勘定の全数性は「走査が触れた範囲」に対してである。上限打ち切りの先・シンボリックリンクの先・読めないディレクトリの配下は、未到達の本数までしか言えない。印なしの中の「入れ忘れ」と「管理外の意思」の区別は機械にはできず、名指しの一覧を人が査読する。綴りの揺れた印（打ったつもりの無音）は印なしに紛れる — その検出は次の ADR で足す。
