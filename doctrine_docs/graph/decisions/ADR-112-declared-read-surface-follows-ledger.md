# 読み口の宣言を現行の合意台帳へ追随させる（初版の決定を置換）

## 背景

ADR-111 は、issue #204 の合意台帳 v2（「v」は版、「v2-n」は台帳の項番号）を固定点として、System View 構想への doctrine 側の応答（スキーマ不変・読み口の宣言）を記録した。その直後、俯瞰レビューが v2 の内部不整合5点を指し、台帳は v3（第3版）を経て v3.1（自己完結版）へ置換され、**所有者が 2026-08-03 に P1（画面区分）・P2（実験ブランチ方式）・台帳 v3 を明示 ACK（承諾の表明）した**（沈黙による承認ではない。以後の正本は v3.1）。

ADR-111 の操作的な決定（スキーマ不変・`trace-index-api` の ICD 宣言・規範文書の複製の非コミット化）は v3.1 でもすべて成立しており、所有者も変更取り込み依頼 #205 の内容を承認した。古びたのは記録の側である——(1) 固定点が v2 のまま。(2) 検証の裁きを「v2-3 の硬い門（二値・被験者数に依存しない条件のみ）」と性格づけたが、これは被験者 0 人でも「重大誤読 0 件」が真になる空虚な真を含んでいた（俯瞰レビューの第2指摘）。(3) 保証状態の対応（v2-9 の `claimed` ↔ 検証戦略）が ADR-081 の原文と食い違っていた（同第1指摘。検証戦略は方法を持つので、対応は `planned` が正確）。

不変性ガードにより ADR-111 は編集できない。正規の直し方（ADR-044: マージ済みの ADR は後継で置換する）に従い、本 ADR が置換する。

## 却下した選択肢

**ADR-111 を直接編集する。** 不変性ガードが拒む（本日の作業でも実測で三度拒まれた）。carve-out を広げれば決定の書き換えを見逃す穴になる（ADR-044 が却下済み）。

**変更取り込み依頼 #205 を取り消す。** 操作的決定は v3.1 でも全て成立しており、取り消しは ICD 宣言と `.gitignore` という争点の無い価値まで巻き戻す。doctrine-lens 側の競合査定・所有者の裁定とも「取り消し不要」で一致した。

**何もしない。** 決定記録が置換済みの台帳を固定点として指し続け、記録と正本の食い違いが残る。空虚な真を含む門の性格づけを残せば、「発火しない門を緑と呼ぶ」欠陥類型を記録の側に温存する。

## 決定

**ADR-111 の操作的決定を維持したまま、記録を台帳 v3.1 へ追随させる。**

1. 固定点は合意台帳 v3.1（自己完結版。所有者が 2026-08-03 に明示 ACK）とする。
2. 検証の裁きは v3-3 の三層ゲートが持つ——M 層（機械・常時実行可能）、H 層（人間による重大誤読の検査）、O 層（観測指標）。**H 層は、人間試験が未実施のあいだ合格ではなく `UNASSESSED`（未評価）であり、`UNASSESSED` のまま製品統合（移管）の判断を出さない。**
3. 保証状態は事前分析 §6.3 の七状態を正本とし、ADR-081 の「検証戦略」に対応するのは `planned`（検証方法・予定はあるが結果がない）である。`claimed` は主張のみ（方法も証拠もない）。状態の統合・再定義をしない。
4. P1・P2・台帳 v3 が所有者により明示 ACK されたことを記録する。人間の沈黙を承認へ変換しない（v3.1 B 節）。
5. doctrine が差し出す範囲——スキーマ不変・ICD 宣言済みの読み口・tag と SHA（コミットを一意に指す指紋）で固定した参照点まで——は ADR-111 から変わらない。凍結の解除は、意味モデルが最低二回改訂され、M 層を通過し、H 層が `UNASSESSED` でなく合格した後、根拠 ADR の置換によってのみ行う（v3-7）。

## 帰結

- ADR-111 は `superseded_by: ADR-112` を付し superseded へ遷移する。ICD-002 の宣言・`.gitignore`・分類の記録は操作的内容が不変のため変更せず、ICD の根拠参照だけを本 ADR へ更新する。
- 保証限界: 本 ADR は記録の追随であり、System View 構想の成立（Phase 0–1 の検証の合否）については引き続き何も言わない。裁きは v3-3 の三層ゲートが持つ。
- 保証限界: Phase 0 の開始は所有者の開始条件一覧（v3.1 G 節）の完了による。本 ADR が満たすのは「doctrine 側 ADR-111 の v3.1 追随」と「doctrine 側の監査完了」の二項だけである。
