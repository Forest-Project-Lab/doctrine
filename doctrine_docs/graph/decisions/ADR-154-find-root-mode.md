# 統治木の発見を CLI から問えるようにする — dep-graph に find-root の口を足す

## 背景

「この作業フォルダは doctrine で管理されているか」を、外部の消費者が自前の再実装で
判じている（issue #294 の観測。権限は ADR-151）。発見の規則の正本は ADR-022（既定名
`doctrine_docs/`、`docs/` は `_system` を持つときだけ、親への遡りは SPEC-019）だが、
CLI から問える口が無いため、規則を写した実装が消費者ごとに増える。写しは上流が規則を
変えた日に黙って古びる。

## 却下した選択肢

- **規則が固定であることを宣言して、消費者の再実装を許す。** 固定の宣言も規則の写しも、
  変えた日に古びる点は同じである。問い合わせの口なら答えは常に体系の側から出る。
- **専用の新しいスクリプトを足す。** 入口が増えるだけで、宣言も配布も試験も一式増える。
  dep-graph は既に根の解決を内蔵しており（`--root` 省略時の遡り）、同じ解決を口にするだけでよい。
- **docs-audit の実行で代用する。** 全件監査は数秒掛かる（INC-039 の実測で 8〜9.5 秒）。
  発見だけの問いに全件走査の値段を付けない。

## 決定

`dep-graph.py` にモード `--find-root [開始位置]` を足し、ICD-002 に宣言する。

1. 開始位置（省略時は作業ディレクトリ）から ADR-022 の規則で統治木を探し、`result` に
   見つけた統治木の**絶対パス**を返す。グラフは組まない（走査の値段を払わせない）。
2. 見つからなければ `result` は null、終了コードは既存の規約どおり 3。
3. この口だけは絶対パスを返す —— 自分の機械の統治木を見つけるための口であり、機械を
   またいで共有する成果物ではない（trace-index の `root` が名前だけである理由〔ADR-055〕とは
   問いが違う）。
4. 規則の正本は ADR-022 のまま動かさない。この口は規則を写さず、同じ実装
   （登録簿の遡り）を呼ぶ。

## 帰結

- 消費者は発見の規則を再実装せずに済み、規則が変わっても問い合わせの答えが追随する。
- 発見できないことと統治木が壊れていることが、終了コード（3）と所見で区別できる。
- 保証限界: 返すのは場所だけであり、その木が健全かどうかは監査の領分。
