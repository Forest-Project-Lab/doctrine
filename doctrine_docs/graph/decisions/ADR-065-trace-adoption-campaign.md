# 紐づけの整理をキャンペーンで駆動し、進捗の停滞を名指しする

## 背景

初回導入の点検には推進力が要る。体系外の `.md` には既に専用の推進（移行キャンペーン。毎セッション先頭1件・統治率つき。ADR-034）があるのに、紐づけ（コード⇄仕様）には「見える化と触ったときの促し」しか無く、**まとまった整理を駆動するものが無い** — 非対称だった。放置すると進捗計の数字が景色になり、通知疲れの一種に堕ちる。

さらに、進捗計が動いていないことを誰も判じない。「印なし 71」が何回の監査でも同じ値なら、それはラチェットが回っていない兆候だが、数字の表示だけでは兆候として立たない。

出口は三つ揃った（印の対で結ぶ／仕様側で「コード対応なし」を宣言する（ADR-061）／ファイル側で exempt を宣言する（ADR-067））。一件ずつの処理が自己完結で書ける前提が整っている。

## 却下した選択肢

- **鼓動が統治木を走査して未宣言の仕様を探す**: 鼓動は毎会話走るので全木の走査をしない制約（SPEC-021）に反する。監査が要約に「次の一件」を運ぶ — 台帳は導出で持ち、鼓動は読むだけ。
- **未宣言の一覧を要約に載せる**: 一覧は規模に比例して肥え、注入の上限を圧す（ADR-058 の却下と同じ）。運ぶのは次の一件の id と残り件数だけ。
- **印なしファイルのキャンペーンを先に回す**: 印なしは母数が大きく、一件の判断が仕様の存否に依存する。仕様側（未宣言）は有限で小さく、宣言が済めばコード側の扱いが各仕様の判断に従属する。文書側の閉包から回すのが検算の構造に沿う。コード側は勘定とドリルダウンと編集時の促し（ADR-063）に残す。
- **停滞を新しい監査検査（所見）にする**: 停滞はコーパスの欠陥ではなく運用の兆候であり、合否や検査一覧を動かす話ではない。要約の中の数（streak）と、注入・キャンペーン文の強調に留める。
- **キャンペーンの促し枠を新設する**: 鼓動の「最も重い一件だけ」の規律を壊す。既存の移行キャンペーンの枠を順送りにする — 体系外 `.md` が残るうちはそちら、無くなれば紐づけへ。導入の位相（文書の整理 → 紐づけの整理）とも一致する。

## 決定

1. **監査が「次の一件」を運ぶ。** 走査が走ったとき、現行の SPEC で節を持たないものの先頭（id の整列順）を `spec_coverage.next_undeclared` として要約に載せる。無ければ載せない。
2. **鼓動のキャンペーン枠を順送りにする。** 体系外 `.md` の移行キャンペーンが出す物が無いとき、`next_undeclared` があれば紐づけキャンペーンを出す: その仕様の id・残り件数・三つの出口（指紋の記録／コード対応なしの宣言／関係するコードが使い捨てなら exempt）を一件分の自己完結文で促す。セッションに一度の規律は既存のまま。
3. **停滞を数える。** 監査は直前の要約（同じ読み取りコア）と比べ、印なしと未宣言の和が変わらない監査が続いた回数を `trace_coverage.stagnation_streak` として要約に載せる。値が動けば 0 に戻る。
4. **停滞は注入が名指しする。** streak が 3 以上のとき、冒頭の進捗計の行に「進捗が N 回の監査で動いていない」を添える。所見にはしない（合否不変）。
5. **文中に運ぶ id は書式で検める。** 注入・鼓動が要約から受け取る id は、登録簿の書式に一致するときだけ文面に載せる（要約は攻撃者制御になりうる。ADR-040 の境界と同じ扱い）。

## 帰結

- 初回導入の位相が閉じる: 文書の整理（既存キャンペーン）→ 紐づけの整理（本キャンペーン）が同じ枠で順に回り、毎セッション一件ずつ進む。undeclared が 0 になった体系では、ADR-061 が保留した無宣言の義務化を別 ADR で安全に裁ける。
- 停滞が兆候として立つ: 数字が景色になったことを体系自身が言う。
- 既知の限界: キャンペーンは着手の一押しであり、網羅は勘定が持つ。停滞の判定は「和が同値」だけを見る（増減が打ち消し合う偽静止は見分けない — 珍しく、害も小さい）。初回監査より前には何も出ない。体系外 `.md` が大量に残る間、紐づけキャンペーンは順番を待つ（位相の意図どおり）。
