# 悉皆トレースモード — 「未分類」を残高にする opt-in

## 背景

注釈は任意である（ADR-054）。この既定は導入の敷居を下げるが、「印なし」が
「まだ実践を始めていない」と「入れ忘れ」と「意図した管理外」のどれなのかを
誰にも言わせない。追跡のグラフを消費する応用（要求→設計→実装→試験の
ドリルダウン・依存の可視化）は、全ノードが「結線済み」か「理由つき管理外」で
ある時にだけ信頼できる。航空宇宙の追跡規律（要求↔設計↔コード↔試験の双方向
追跡を出荷の条件とする）が信頼されるのも「未分類が存在しない」からである。
自宅の実測では印なし62件 — 内訳はスクリプト12・試験29・テンプレート21・
JSON 配線2・法的文書1で、後三者は注釈をファイルに書き込めない（テンプレートは
生成先へ写り込み、JSON は注釈を持てず、法的文書は改変しない）。

## 却下した選択肢

- **印なしをファイルごとに warn にする**: 62件が62行の雑音になる。残高は一件で
  告げ、一覧は求めに応じて導出する（ADR-055 の導出の線）。
- **error の門にする**: 実践が安定する前に硬直する。新しいファイルを足すだけの
  貢献者を CI が止め、出口の学習を強いる。warn で運用し、門への昇格は実践が
  落ち着いてからの別の決定とする。
- **走査器に拡張子の組み込み除外を足す**: .json 等を機械が黙って除外すると
  「管理外の意思の宣言」が消え、保存則の意味が薄まる。除外は理由つきの宣言で
  行う。
- **すべての適用除外を設定側へ集約する**: ファイルに書ける媒体まで設定へ集めると
  影の台帳になる。書ける媒体は in-file の宣言（ADR-067）が正であり、設定側は
  媒体の制約がある場合に限る。
- **自動で注釈を張る**: 意味の対応付けは人の判断（NONGOAL 第1項と同じ線）。

## 決定

1. **悉皆モードは opt-in の設定とする。** `_system/.context-config.json` の
   `trace_mode: "exhaustive"`。未設定の既定は現状のまま（印なしは数えるだけ）。
2. **発火は監査の warn 一件とする。** 検査 `trace_unmarked_backlog` が、印なしが
   1件以上のとき、件数と三つの出口（範囲を張る／ファイル内の exempt 宣言／設定の
   適用除外）と一覧の導出（`trace-index --coverage`）を一件で告げる。
3. **設定側の適用除外 `trace_exempt` を足す。** `{パス: 理由}` の対応。末尾が
   `/` のパスは前置きの一致（配下すべて）。走査は該当ファイルを読む前に
   「明示管理外」へ分類し、保存則（ADR-058）の枠は変えない。理由の無い項目は
   読み飛ばす（宣言なき除外を作らない）。
4. **鼓動は一度だけモードを案内する。** 仕様側の悉皆が済み
   （`spec_coverage.undeclared` が 0）、印なしが残り、モードが未設定のとき、
   中立の案内を一度出して印（鍵 `trace_mode_hint_shown`）を残し、以後は黙る
   （ADR-066 の Level 案内と同じ形）。

## 帰結

- 「未分類」という状態に名前と残高が付き、ゼロへ向かう圧が選べるようになる。
  既定の静けさ（通常の導入先を騒がせない）は変わらない。
- opt-in の時機は数値の閾値では選ばない。**追跡を消費する物**（可視化・
  ドリルダウン・出荷条件としての被覆主張）**が現れた時**が本質的な境界であり、
  機械が示せるのはその前提条件（仕様側の悉皆の完了）までである。案内が
  この前提条件で一度だけ出るのは、そのためである。
- 既知の限界: 設定の適用除外はパスに結び付くため、ファイルの改名で外れる
  （改名は追わない — ADR-064 と同じ線）。理由の真偽は検めない（宣言の正直さは
  人に残る）。error の門は本決定に含まれない（後の決定）。
