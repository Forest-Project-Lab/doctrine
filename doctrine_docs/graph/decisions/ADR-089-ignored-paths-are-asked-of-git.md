# 無視される物は走査しない。その判定は git に訊く

## 背景

コードの走査が `.gitignore` を見ない。ビルドの投影に写った印まで範囲として返る。

実測（呼び手のリポジトリ。`tsc` の投影が `out/`、`esbuild` の投影が `dist/`）:

| 何 | 件数 |
|---|---|
| 返った範囲 | 30 |
| うち `.gitignore` 配下 | **12（40%）** |

正本と写しの対が並ぶ。

```text
src/doctrine/cli.ts   SPEC-001:1-231   ← 正本
out/doctrine/cli.js   SPEC-001:8-209   ← 投影に写ったもの
```

害は三つある。

1. **件数が狂う。** 「この文書に結ばれたコード範囲は N 件」が実際の 1.67 倍になる。
2. **指紋が二重に食い違う。** 正本を直して指紋を再記録するまでのあいだ、写しの側も食い違いと
   して立つ。**同じ一つの変更が二件に見える。**
3. **回避が設定の重複になる。** 呼び手は `trace_exempt` に `out/` と `dist/` を手で書いている。
   **同じことが既に `.gitignore` に書いてある。** 同じ事実を二箇所に持つ形であり、
   `.gitignore` だけを直した木では静かに壊れる。

## 却下した選択肢

**自前で `.gitignore` を解釈する。** 否定（`!`）・`**`・アンカー（先頭の `/`）・ディレクトリ
限定（末尾の `/`）・親から子への継承・`.git/info/exclude`・大域の設定。**再実装すれば必ず
どこかで git と違う判定を出す。** それは「見ているつもりで見ていない」新しい沈黙した欠陥で
あり、この体系が今日だけで四度直した形そのものである。**正本を再実装しない。**

**`trace_exempt` に書かせ続ける（現状維持）。** 同じ事実を二箇所に持つのがこの issue の芯で
ある。片方だけ直した木で静かに壊れる。

**`trace_exempt` を廃し、`.gitignore` だけにする。** 二つは**別の事実**である。
`.gitignore` は「リポジトリに入れない物」を言い、`trace_exempt` は「リポジトリに在るが印を
持てない／持たせない物」を言う（持ち込んだ道具・一次文書）。後者は `.gitignore` では表せない。

**走査した上で「写しである」印を付けて返す。** 呼び手が畳めるようになるが、走査の費用は払い
続ける。無視される物は**そもそも読まない**のが正しい（刈れば配下へ降りない）。

## 決定

**無視される物は走査しない。無視されるかの判定は git に訊く。**

1. 走査の入口で一度だけ git に問う —— `git ls-files -o -i --exclude-standard --directory`。
   無視されている未追跡の道を、丸ごと無視されるディレクトリは `dir/` に畳んで返す。
   **一度の子プロセスで済み、意味論は git のものである。**
2. 得た道は除外規則として刈る。`EXCLUSION_RULES` へ二つ足す —— ディレクトリ単位の
   `gitignored_dir`（配下は未到達）とファイル単位の `gitignored_file`。
   **黙って切り詰めない**（規則 id を経由して数える。ADR-058 の保存則）。
3. **追跡の免除（`trace_exempt`）は残す。** 別の事実だからである。両者の分界を仕様に書く ——
   `.gitignore` は「リポジトリに入れない物」、`trace_exempt` は「在るが印を持てない物」。
4. git が使えないとき（git が無い・リポジトリでない・問いが失敗した）は、**勘定にその状態を
   残す**。所見にはしない —— git を使わない木を毎回叱るのは害である。**黙らないが、責めない。**
5. 追跡の対象になるのは追跡下のファイルである。`.gitignore` に一致しても git が追跡している
   ファイルは走査する（git がそう扱うので、こちらもそう扱う）。

## 帰結

- 呼び手の `trace_exempt` から `out/` と `dist/` の二項が要らなくなる（あちらの判断であり、
  こちらでは変えない）。**同じ事実を二箇所に持つ形が消える。**
- 件数と指紋の食い違いが、正本の分だけになる。
- 投影のディレクトリへ降りないので、走査が速くなる（測っていないので速さは主張しない）。
- 保証限界: **判定は git の意味論そのものである。** こちらは解釈しない。git の版で挙動が
  変われば、こちらの挙動も変わる。それは意図した委譲である。
- 保証限界: git が使えない木では、いまと同じ挙動になる（`.gitignore` を見ない）。
  勘定にその状態が出るだけで、警告は出さない。
- 保証限界: 一度の問いなので、走査中に `.gitignore` が変わっても追わない。走査は一回きりの
  短命な処理であり、その間の変化は扱わない。
