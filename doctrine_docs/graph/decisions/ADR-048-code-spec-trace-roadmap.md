# コードと仕様の双方向トレースは、条件を満たす段階拡張として採る

## 背景

外部レビューで、コードと仕様の双方向トレース（コードに「この関数は指定の仕様を実装する」旨の注釈を置き、CI がトレース索引を導出し、仕様側の逆リンクを投影する）＋ Coverage Control の提案があった（#93）。上流→下流（何が壊れるか）と下流→上流（なぜ存在するか）を辿れる仕組みは、doctrine の追跡性（R3）・最小性（R8）・不在検出の思想と同型である。導入先の要求粒度の追跡（#87）を補い、上位設計書 §2 に頼らない機械可読の追跡を与えうる。

一方、doctrine の現行の統治対象は「知識と決定の層」に限る（NONGOAL 第6項ほか）。コードシンボルへの拡張は統治範囲の変更であり、黙って足すと自己規範に反する。

## 却下した選択肢

- **いま全面実装する**: コード注釈の解析・トレース索引の導出・仕様側の逆リンク投影・試験結果の接続は、複数の版に分けるべき規模である。一度に入れると、抽象の先取り（R8 違反）と、統治範囲の無断拡張を招く。
- **提案ごと退ける**: 追跡性（R3）と最小注入（R5）の思想に沿う価値があり、要求粒度の二重定義（#87）の既知の限界を埋めうる。退けるのは惜しい。

## 決定

双方向トレースを、次の条件を満たす**段階拡張**として採る（方向と制約をいま決め、実装は版を分ける）。

1. **統治範囲の拡張は別の ADR で裁く**: コードシンボルを追跡の終点に加えるのは、統治対象を「知識と決定の層」から広げる決定である。実装の前に、その範囲拡張を別の ADR で明示的に決める（黙って足さない）。
2. **試験結果の本文は取り込まない**: 実行結果・計測値は外部ツール（CI）が正本であり、NONGOAL 第6項と衝突する。取り込むのは「この試験は実装の変更後に再実行されていない」という古びの一文までとし、生の結果は参照に留める。
3. **既存の機構の拡張として設計する**: 新機構を増やさない。コードへの外部依存は EXT アンカー（`hash` で内容の指紋を追える。ADR-039）を土台にし、被覆の可視は保証マトリクス（SPEC-025、#94）の拡張として持つ。トレース索引は投影（モデルから導出。手で保守しない）とする。
4. **前提条件**: EXT の `hash` 検査（ADR-039、実装済み）と、要求タグの約束（ADR-045）を土台にする。索引を導出する前に、コード注釈の書式（実装する仕様の id を注釈で示す形と、置き場所の規約）を SPEC で定める。

## 帰結

- 双方向トレースの方向と制約が決まり、無断の範囲拡張と抽象の先取りを防げる。
- 実装は版を分ける（範囲拡張 ADR → 注釈書式 SPEC → 索引の投影 → 保証マトリクスへの接続）。各版は独立に受け入れる。
- 既知の限界: 本 ADR は方向と条件までで、コードシンボルの追跡はまだ動かない。要求粒度の確実な追跡は、当面 REQ への `depends_on`（ADR-045）で行う。
