# 統治対象に「注釈が囲むコードの範囲」を加え、言語ごとに手段を分けない

## 背景

ADR-048 は双方向トレースを段階拡張として採り、その第1項で「コードシンボルを追跡の終点に加えるのは統治対象を広げる決定であり、実装の前に別の ADR で明示的に決める（黙って足さない）」と定めた。本 ADR がその決定である。

判断の材料は RESEARCH-002 にある。要点は三つ。

- 追跡に要る五つの機能のうち四つは標準ライブラリで閉じる。外部の構文解析器が効くのは「注釈を付けた後にコードが変わった」の範囲の確定だけである。
- 最も難しい「改名・移動への追従」は、構文解析器を入れても解けない。構文解析器は単一ファイルの一時点を木にする道具で、版をまたいだ同一性の概念を持たない。
- 配布の経路が無い。プラグインの定義（`plugin/.claude-plugin/plugin.json`）に依存を宣言する場所は無く、フックは shebang が解決する解釈系でスクリプトを直に起動する。入っていなければ、PreToolUse が落ちて全編集が拒否されるか、握りつぶして予防が黙って消えるかのどちらかになる。

## 却下した選択肢

- **構文解析器でコードのシンボルを同定する**: 上の三点により釣り合わない。加えて、言語ごとに文法の品質が違い、「対応言語」として並べたものが実際には黙って落ちる（RESEARCH-002 §2.1）。
- **言語ごとに手段を変える（Python だけ標準の `ast`、他は注釈）**: 「範囲はどこか」という一つの問いに二つの実装が答えることになる。重複 id の採用規則（ADR-049）と監査要約の読み取り（ADR-053）で二度直した欠陥類型を、設計の時点で作り込むことになる。保証限界も言語ごとに割れ、利用者が言語ごとの差を覚える羽目になる。
- **注釈が指す id だけを見る（範囲も指紋も持たない）**: 実在と現行性は見られるが、コードが変わったことを検出できない。「根拠は今も信頼してよいか」に答えられず、段階拡張の目的に届かない。
- **コードを統治文書として扱う（`status` や `review_by` を持たせる）**: コードの正本は仕様ではなく実装そのものであり、二重の正本を作る。文書の生存期間とコードの生存期間は違う。

## 決定

統治対象に加えるのは、**注釈の対が囲むコードのテキストの範囲**であって、コードそのものでも、言語のシンボルでもない。

1. **追跡の終点は範囲とする**。開始と終了の注釈が囲む区間を一つの終点とし、その内容の指紋（hash）を索引が持つ。指紋の変化を古びとして扱う。
2. **言語で手段を分けない**。行注釈を書ける全ての言語で、同じ一つの規則が効く。構文解析はしない。言語ごとの対応表を持たない。
3. **コードにライフサイクルを与えない**。`status`・`review_by`・依存は持たせない。コードは統治文書にならず、正本は仕様の側に留まる。範囲は仕様から参照される終点にすぎない。
4. **標準ライブラリだけで実装する**。DECIDED-001 事実7 は維持する（置換しない）。
5. **試験の実行結果は取り込まない**（ADR-048 第2項のまま）。取り込むのは「この試験は実装の変更後に再実行されていない」という古びの一文までとする。

## 帰結

- 保証が言語に依らず一様になる。表に載っているのに落ちる言語が生まれない。
- 範囲の確定を人が印で行う。**印の対の欠落（終了の付け忘れ・消し忘れ）は機械で検出できる**ので、監査が error で挙げる欠陥類型になる。構文解析器の故障（文法と本体の版のずれ・言語ごとの黙った脱落）は同じようには検出できない。この差が方式の選択を決めた。
- 統治対象が広がったことは、常時投入の契約が運ぶ必要がある。契約に載らない範囲拡張は、次のセッションのモデルが知らないまま作業することになり、機能が黙って使われない。DECIDED-001 に一項として加える。
- NONGOAL 第6項は書き換えない。コードは「外部が正本の動的データ」ではなく、リポジトリの中にあり版管理されている。引くのは範囲の指紋だけである。
- 既知の限界: 改名・移動は追わない（git の受け持ちであり、構文解析器でも解けない）。印が意味の上で正しい場所に打たれているかは判定しない（NONGOAL 第1項と同じ形で、判断は人に残す）。印を打っていないコードは追跡の外にある（注釈が無ければ終点が無い）。
