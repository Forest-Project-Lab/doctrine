# 読み口は宣言してから読ませる — System View 構想にはスキーマ不変で応える

## 背景

issue #204 で、JAXA（宇宙航空研究開発機構）が定める JERG（JAXA の技術標準文書の番号体系）のうち宇宙機ソフトウェア開発標準 JERG-2-610C、STPA（システム理論に基づく危険分析の手法）の手引き、CAST（システム理論に基づく事故分析の手法）の手引きの三冊を骨子に、「System View」（目的・責務・入出力・保証から実装へ降りる、目的別ビューの構想）が事前分析として出された。doctrine と doctrine-lens の両エージェントが協議し、合意台帳 v2（「v」は版、「v2-n」は台帳の項番号）を固定した（2026-08-03。決定14項と、PROVISIONAL（暫定。人間の確認待ち）2件）。doctrine 側に効く合意は三つ——(1) 検証（Phase 0–1）の間、doctrine のスキーマ（型・必須キー）は変えない。(2) 表示側が読んでよいのは宣言済みの読み口（CLI が返す値）だけとし、実行時の状態（`.claude/.cache`）の直読みは契約外とする。(3) 規範文書の複製（取得したファイル・頁画像・大量の翻訳文）は再配布条件を確認するまでコミットしない。

協議の過程で、読み口の宣言に一箇所だけ穴が見つかった。追跡索引は SPEC-026 が形（`trace-index/1`・ranges の五項・終了コード）を定め、消費者（doctrine-lens の文書が名指しで参照）が既に読んでいるのに、ドメインの入口（ICD）に宣言が無い。越境の依存は相手ドメインの ICD 宛だけという規律（DECIDED-001 事実4）に照らすと、「実装と仕様は在るが入口の宣言が無い」状態であり、実装の内部形が黙った契約になっている。黙った契約は変更検出の外に居る。

## 却下した選択肢

**System View のための新型（SystemElement・Flow・Contract 等）や新しい必須キーを doctrine へ足す。** 利用実績の無い存在論の固定であり、埋める内容の無い欄（実効ゼロの欄）を増やす——この体系が三度出した欠陥類型そのものである（ADR-077・078・080）。ADR-081 の判定基準「その仕掛けが、既に実測された欠陥を塞ぐか」を満たさない。凍結の解除は、意味モデルが最低二回改訂され硬い門を通過した後、根拠 ADR の置換によってのみ行う（台帳 v2-7。DECIDED-001 事実1・事実3 と整合）。

**ハザード層（Loss・Hazard・Safety constraint）の語彙を採る。** ADR-081 が原典の実測（JERG-2-610C 本文に「ハザード」は 0 回）とともに却下済み。安全例の候補モデルは doctrine の外（doctrine-lens の実験ブランチ）に留まる（台帳 v2-5）。

**検証の置き場として第三リポジトリを作る。** 統治面（issue・決定・CI・権限）が三重化し、検証終了後も第三の正準が残りうる。隔離は doctrine-lens の実験ブランチで足りる（台帳 v2-2′）。doctrine 側の要求は「統治木に置かない」「参照は tag と SHA（コミットを一意に指す指紋）で固定する」の二点だけであり、ブランチでも満たされる。

**何もしない（trace-index を未宣言のまま読ませ続ける）。** 消費者が増えるほど、実装の内部形の変更が黙った破壊になる。規律（越境は ICD 宛だけ）と実態の食い違いを放置することになる。

## 決定

**System View 構想には、スキーマ不変で応える。doctrine が差し出すのは、ICD に宣言した読み口と、参照点（tag・SHA・EXT アンカー）までとする。その第一歩として、既に実装（`trace-index.py`）と仕様（SPEC-026）を持つ追跡索引の問い合わせを、graph の ICD（ICD-002）へ `trace-index-api` として宣言する。**

読み手の規律も対にする——消費者が読んでよいのは宣言済み CLI が返す値だけであり、実行時の状態の直読みは契約外である（台帳 v2-14）。

## 帰結

- ICD-002 に `trace-index-api` の宣言が入る（JSON の形・ranges の五項・終了コード。詳細の正本は SPEC-026 のまま動かさない。二重定義しない）。doctrine-lens 側は着地後に自側の文書参照を追随する（文書のみ）。
- 規範文書の複製 `Reference_material/` はコミットしない。`.gitignore` に一行を足し、誤コミットを防ぐ（台帳 v2-11′。外部に正本があるものは写さず出所を参照する——NONGOAL-001 第6項と同じ形）。
- スキーマは変わらない。型の一覧も必須キー8個も不変（DECIDED-001 事実1・事実3）。
- 保証限界: この宣言は読み口の形を固定するだけで、System View 構想の成立（Phase 0–1 の検証の合否）については何も言わない。検証の裁きは台帳 v2-3 の硬い門（二値・被験者数に依存しない条件のみ）が持つ。
- 保証限界: 台帳 v2 の暫定2件（画面区分の正本・実験ブランチ方式）は人間の確認待ちであり、否認されれば v3（台帳の次の版）で置換される。本決定（スキーマ不変・読み口の宣言）はその2件に依存しない。
