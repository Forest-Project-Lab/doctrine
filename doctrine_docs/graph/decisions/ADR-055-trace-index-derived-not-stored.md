# トレース索引はファイルに置かず毎回導出し、記録するのは人の確認だけとする

## 背景

ADR-048 第3項は「トレース索引は投影（モデルから導出。手で保守しない）とする」と定めた。doctrine の投影は、描き直せる派生表示をリポジトリの中のファイルとして置く形である（Overview・Context Map・ICD 一覧）。索引もその形にするのが素直に見える。

しかし索引は、既存の三つの投影と性質が違う。

- 既存の投影は文書の集合から描く。文書は一日に何件も増えない。索引はコードの注釈から描く。注釈は編集のたびに動きうる。
- 描いたファイルを版管理に置けば、注釈を触った全員がそのファイルを書き換える。**同じ行が同時に動くので、取り込み依頼が衝突する。** 近縁の道具で、生成物が利用者ごとに違って衝突する故障が実際に報告されている。
- 索引には位置（ファイルのパスと行番号）が入る。行番号は無関係な編集で動く。差分の大半が「行がずれただけ」で埋まり、意味のある変化が埋もれる。

一方で、導出するだけでは足りない問いがある。「注釈を付けた後にコードが変わったか」は、**比較する相手が残っていなければ答えられない**。毎回導出した指紋を毎回導出した指紋と比べても、常に一致する。古びの検出には、どこかに確認の時点を残す必要がある。

## 却下した選択肢

- **索引を描いたファイルとして版管理に置く**: 上の三点により、衝突と雑音を生む。走査は実測で 0.43 秒（このリポジトリ全体）であり、置いて速くする理由も無い。
- **確認の記録を索引ファイルに持つ**: 導出できるもの（位置）と、人が判断したもの（確認）が同じファイルに混ざる。片方を描き直すともう片方が消える。
- **注釈そのものに指紋を書く**: コードを変えるたびに注釈も書き換えることになり、指紋が常に一致して古びを検出できない（自分で自分を追認する）。
- **確認の記録も持たない（古びを検出しない）**: 「その根拠は今も信頼してよいか」という問いに答えられず、段階拡張の目的に届かない。

## 決定

**導出できるものは持たない。記録するのは人の確認だけとする。**

1. **索引はファイルに置かない**。問い合わせのたびに走査して導出する。版管理に生成物を置かないので、衝突も行番号の雑音も生じない。ADR-048 第3項の「手で保守しない」という意図は、ファイルを置かないことでより強く満たす（描き直し忘れが起こりえない）。
2. **確認は仕様の側に記録する**。ある仕様に対応する範囲の指紋を、その仕様の文書に書く。EXT アンカーが外部の対象に対して行っていること（`- 指紋: sha256:<64桁>`。ADR-039）と同じ形であり、新しい機構を増やさない。
3. **記録する指紋に位置を含めない**。パスも行番号も書かない。**コードを別のファイルへ移しても、内容が同じなら指紋は変わらない**ので、移動を古びと誤判定しない。位置は導出の側が毎回持つ。
4. 古びの判定（記録した指紋と導出した指紋の照合）は監査の検査として次の版で足す。本 ADR は、何を導出し何を記録するかの線引きまでを決める。

## 帰結

- 版管理に生成物が増えない。取り込み依頼の衝突と、行番号がずれただけの差分が生じない。
- 記録が位置から独立する。ファイルの移動・並べ替えでは古びと判じない。内容が変われば判じる。これは「追従しない」故障の一部を、機構の性質として避けたものである。
- ADR-048 第3項の「投影とする」を、ファイルを置く形ではなく、導出する問い合わせの形で満たす。文言との差をここに残す（黙って読み替えない）。
- 既知の限界: 走査は問い合わせのたびに走る。規模が上限（既定 5000 ファイル）を超えると、飛ばした事実を告げて縮退する。索引が無いので、コードを一つも読めない環境（走査の根が無い）では追跡そのものが成り立たない。
