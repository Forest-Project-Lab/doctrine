# ファイルは統治外の意思を自分の中に宣言できる — exempt の印と勘定の第四項

## 背景

除外は規則（パターン）単位でしか下せず、「この補助スクリプトは意図して統治の外」とファイル単位で言う手段が無かった。帰結として、使い捨ての移行スクリプトや実験コードが印なし（unmarked）の分母を永久に膨らませ、進捗計が「減らない数字」になる。停滞の検出を入れても、停滞が怠慢なのか「残りは全部意図的な管理外」なのか判別できない — 分母が濁ると検算全体が濁る。

ADR-058 はファイル単位の宣言（台帳）を「必要になったときに別の ADR で」と保留した。補助スクリプトの扱いを問われ、必要になったと判じる。仕様側には既に二択がある（指紋の記録／「コード対応なし」の宣言。ADR-061）。同じ形をコード側へ対称に写す。

## 却下した選択肢

- **台帳ファイル（管理外の一覧）を持つ**: 台帳と実体の食い違いという新しい欠陥面を作り、ファイルの移動で台帳が古びる。ADR-058 の却下理由がそのまま生きている。宣言はファイル自身の中に住まわせる — 移動しても消えず、第二の正本が生まれない。
- **除外規則（パターン）を設定で増やす**: パターンは意図を語らない。「tools/ 以下は全部外」は、そこに置かれた統治すべきコードも黙って外す。意図は一ファイルずつ書く。
- **仕様側の宣言（ADR-061）だけで足りるとする**: 仕様が存在しない使い捨てコードには宣言の置き場が無い。ファイル側の出口が要る。
- **exempt のファイルを走査から完全に消す（除外扱い）**: 消すと「不要と判断しても必要に応じて見れる」が破れる。exempt は除外ではなく勘定の第一級の項とし、一覧をいつでも導出できるままにする。

## 決定

1. **exempt の印を足す。** 行から前後の空白と非語文字を取り除いた残りが「印の語 + exempt（以降は任意の理由）」に一致する行を持つファイルは、統治外の意思を宣言したものとする。理由は書けるが機械は解釈しない。
2. **勘定に第四項 `exempt_files` を足す。** 保存則は「到達 ＝ 寄与 ＋ 印なし ＋ 明示管理外 ＋ Σ除外」になる。全枠を 0 件でも出す原則は変えない。進捗計の分母（印なし）から意図的な管理外が外れ、残りが本当の未処理だけを指す。
3. **宣言と実態の矛盾を warn で挙げる（`trace_exempt_conflict`）。** exempt を宣言したファイルに範囲の印（begin/end）もあるなら、宣言が古いか印が誤りである。実態を優先し、範囲は生かして勘定は寄与に数える（範囲を黙って落とすと、仕様側に第二の所見が連鎖して雑音が倍になる）。この検査は宣言したファイルにしか発火しない — 版を上げただけの利用者には何も起きない。
4. **綴りの揺れの疑い（ADR-059）を exempt にも広げる。** 印の語の直後に exempt の語が続くのに厳密な形に一致しない行は、疑いとして挙げる。
5. **一覧は導出で見る。** exempt のファイルの一覧は問い合わせ（trace-index）の項として導出する。保存しない（ADR-055）。

## 帰結

- 補助スクリプトの整理が一行で終わる: 結ぶ（印の対）／仕様側で対応なし宣言（ADR-061）／ファイル側で exempt — 三つの出口が揃い、キャンペーン（別 ADR）の一件処理の選択肢になる。
- 進捗計が締まる: 印なしは「まだ判断していないもの」だけを数える。停滞の検出（別 ADR）が意味を持つ前提が整う。
- 検査名が一つ増える（転記表・ICD・SPEC-011 の同時更新を列挙添字の凍結が強制する）。
- 既知の限界: exempt は意思の記録であって証明ではない。誤って exempt されたコードを機械は疑えない（矛盾＝印との同居だけを見る）。一覧の査読は人の仕事に残る（ドリルダウンがその手段）。理由の欄の真偽・妥当性は判定しない（NONGOAL 第1項と同じ形）。
