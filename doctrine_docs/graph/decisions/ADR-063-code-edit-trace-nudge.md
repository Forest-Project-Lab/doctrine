# 印の無いコードを編集したとき、セッションに一度だけ紐づけを促す

## 背景

コードだけを書いたとき、仕様と結ぶことを促す発火面がどこにも無かった。統治文書の編集には doc-review の促しが出るのに、新しいコードは無言で積もり、印なしの山（勘定が数える unmarked）は監査のときにしか目に入らない。「触った所から紐づける」ラチェット運用は、触ったその場の一言が無ければ回り始めない。

一方で、先行事例の教訓が二つ効く。通知の洪水は麻痺と放棄を生む（RESEARCH-003 類型9 — 公式対処が「通知を減らす設定」になった先行例）。そしてターンごとの全件走査はしない（NONGOAL 第5項）。促しは安く、静かで、消しやすくなければならない。

## 却下した選択肢

- **新しいフックの登録を足す**: 既に PostToolUse には促しの面（review-nudge）が配線されている。同じ出来事に別の入口を足すと、配線の変種（Level 2/3/4）ごとの整合が増える。既存の面を広げる。
- **編集のたびに毎回促す**: 同じファイルを連続で編集する通常の作業で毎回同じ行が出る。麻痺を生む通知の形そのもの。セッションに一度だけとする。
- **「追跡が使われているか」を毎回の走査で判じる**: 節を持つ文書を探すには統治木の走査が要る（NONGOAL 第5項に反する）。直近の監査の要約に勘定（`trace_coverage`）が載っているかで判じる — 読み取りは既にある共有コア一回で済む。帰結として、初回監査より前は促しが出ない（段階導入として受け入れ、ADR に明記する）。
- **warn として監査に足す**: 監査には既に印なしの勘定と欠陥Dの advisory がある（ADR-058・ADR-061）。編集の瞬間の一言は助言の層（additionalContext）の仕事で、合否や記録には関与させない。

## 決定

1. **review-nudge（PostToolUse）を広げる。** 型付き文書でないファイルの編集で、次の全条件が立つとき、紐づけの促しを一行だけ出す: 統治木がある・段階が Level 3 以上・直近の監査の要約が勘定（`trace_coverage`）を載せている（= 追跡を使っている体系）・編集されたファイルが走査の対象になりうる（dot でも `.md` でも統治木の中でもない）・そのファイルに対を成す印が一つも無い。
2. **セッションに一度だけ出す。** セッション別の印（既存の session-flags の機構）で二度目からは黙る。セッション id が無ければ、沈黙より重複が安全の側（鼓動と同じ規約）。
3. **促しの文は両方の道を示す。** 範囲を印の対で囲んで仕様に指紋を記録する道（SPEC-026）と、仕様側に「コード対応なし」を宣言する道（ADR-061）。
4. **判定に使う読み取りは、その一ファイルと要約だけ。** 統治木の走査はしない（NONGOAL 第5項の維持）。

## 帰結

- まっさらなリポジトリの導入経路の穴が閉じる: 追跡を使い始めた後は、印の無いコードを触った最初の編集で、その場に一言が出る。以後はセッションごとに一度。
- 促しが出るのは追跡を実際に使っている体系だけ。使っていない利用者・版を上げただけの利用者には何も出ない（要約に勘定が無いため）。
- 既知の限界: 初回監査より前の編集には出ない（勘定がまだ無い）。編集されないファイルには出ない（それは監査の勘定と欠陥Dの advisory の受け持ち）。セッション最初の一件にしか出ないので、網羅の道具ではない — 網羅は勘定（ADR-058）が持ち、これは着手の一押しである。
