# 印に見えるが読めない行を疑いとして挙げる（打ったつもりの無音を塞ぐ）

## 背景

印の照合は行全体の厳密な形（`doctrine:begin <TYPE>-<NNN>`）に一致した行だけを印と認める。緩めると、コードの中の文字列を印として拾うからである（IMPL-021）。その代償として、**綴りが一文字揺れた印は、存在ごと無音で消える**。実測では、小文字の id・下線の id・語の直結の崩れ・余計な語の付加・id の欠落の六変種すべてで、範囲もゼロ・所見もゼロだった。書いた本人は打ったつもりでいるので、これは入れ忘れより性質が悪い。先行事例でも、注釈が折り返しひとつで黙って失われる故障が報告されている（RESEARCH-003 類型2、strictdoc#2130）。

もう一つ、走査は上限超過を `trace_scan_truncated` の所見として正直に告げるのに、**監査の側がその所見を捨てていた**。印の対応付けの誤り五種だけを拾い、それ以外の走査所見は握られて消えていた。走査が正直でも読み手が黙れば、沈黙する検証器（[R11]）と同じである。

## 却下した選択肢

- **印の照合そのものを緩める**: コード中の文字列や散文を印として拾い、偽の範囲が生まれる。範囲の誤検出は指紋の誤照合に直結し、疑いの誤検出より害が大きい。照合は厳密なまま、疑いを別の目で見る。
- **警告を warn/error で出す**: 印の語の近くに `begin`／`end` が現れる散文は正当にありうる。誤検出の可能性がある検査を warn 以上にすると、版を上げた利用者の緑の監査が赤に変わる。advisory（助言）に留め、義務化は使用実績を見て別の ADR で裁く。
- **編集時のフックで疑いを検査する**: リンタは編集された一つの文書だけを見る決まりで、コードの走査はターンごとの費用に合わない（NONGOAL 第5項）。監査（全件・セッション終端）に置く。
- **疑いの検出を諦める（現状維持）**: 「打ったつもり」の無音は、保存則（ADR-058）でも印なしの中に紛れて見えない。名指しできる兆候を黙って捨てる理由が無い。

## 決定

1. **疑いの照合を足す。** 厳密な印に一致しない行のうち、印の語 `doctrine:` の直後（空白を許す）に `begin` または `end` の語が続く行を、`trace_marker_suspect` の所見として挙げる。厳密な照合はいっさい変えない。
2. **監査は疑いを advisory で載せる。** 検査名 `trace_marker_suspect` を検査一覧に加える。error/warn は増やさない — 版を上げた利用者の監査の合否は変わらない。
3. **監査は走査の切り詰め所見も捨てずに載せる。** 検査名 `trace_scan_truncated` を検査一覧に加える（advisory）。走査が告げた事実を読み手が握る経路を閉じる。
4. **印の書式を原文に書かない規律を、走査の実装自身へ広げる。** 試験がすでに守っている規律（IMPL-021「試験の原文に印そのものを書かないこと」）を、モジュールの説明文にも適用する。書式の例示は統治文書（`.md`。走査の対象外）だけが持つ。これを守らないと、疑いの照合が実装自身の説明文に反応する。

## 帰結

- 綴りの揺れた印が、無音ではなく名指しの疑いになる。書式の正解（`doctrine:begin <TYPE>-<NNN>`）を添えて指すので、直し方に迷わない。
- 疑いは advisory であり、監査の合否も CI の門も変えない。既存の利用者の緑は緑のまま。
- 検査一覧が二つ増える（疑い・切り詰め）。検査一覧・ICD・SPEC-011 は同じ変更で追随する。
- 既知の限界: 印の語を含まない揺れ（`doctrin:begin` など語自体の綴り誤り）は検出できない — 走査は印の語で読む対象を絞るからである。散文が偶然この形を踏めば誤検出になるが、advisory に留めることで害を絞った。疑いの網羅は約束しない（検出できる変種を SPEC-026 が列挙する）。
