# 走査の門を「節の有無」に揃え、検査の挙動を正本の列挙で添字づけた試験が凍結する

## 背景

追跡の検査は「`## 実装の指紋` の節を持つ**現行の**仕様があるときだけ」走査していた。状態（8値）×指紋の一致（2値）の全マスを実測すると、発火するのは現行×不一致の 2 マスだけで、**opt-in した仕様が廃止されると走査ごと止まり、「廃止された仕様を指す注釈」を挙げるための検査が、まさにその廃止によって死ぬ**という自己矛盾があった。さらに第三の次元（他に現行の opt-in が併存するか）を足すと 32 マス中 12 マスで答えが変わった — 上向きの検査の発火が、無関係な他者の opt-in に条件づけられていた。

試験の側にも同型の穴があった。検査名の正本 `AUDIT_CHECKS` は「TEST が凍結する」と自らの注釈で宣言しながら、**凍結する試験は実在しなかった**（名前を一つ足しても全試験が通る）。一方、登録簿の型表・状態・Hook の配線は、独立に転記した期待表との全量照合で既に凍結されている。列挙を持つ次元の試験の様式が、場所によって不揃いだった。

前セッションの反省はこの形を要求している: 実装を見て試験を書けば、実装に無い状態の試験は書けない。**期待表を先に決め、正本の列挙で添字づけ、期待の無いマスで落ちる**形にすれば、9 個目の値が足された瞬間に「期待を決めよ」と試験が言う。

## 却下した選択肢

- **走査の門を廃止し、節が無くても常に走査する**: 導入した初日に、注釈の無いリポジトリでも全ファイル走査の費用を払う。opt-in の原則（ADR-056）を壊す。門は残し、条件だけを直す。
- **状態ごとに走査の要否を細かく分ける**: 「どの状態なら走るか」という表がもう一つ増え、表と実装の食い違いという新しい欠陥面を作る。門は「節の有無」の一条件に畳む。
- **試験の期待表を生成で埋める**: 生成した瞬間、「期待を決めていないマス」と「無音を決めたマス」の区別が消える。期待表は手で書き、キー集合の両方向一致を検べる。
- **検査の重大度も実行時に表で持つ**: 重大度の一覧表をコードに足すと、所見を作る各行との二重定義になる。重大度の凍結は試験の期待表が担う（正本は所見を作る行のまま一つ）。

## 決定

1. **走査の門は「`## 実装の指紋` の節を持つ文書が一つでもあるか」とする。状態を問わない。** 節を持つ文書が無ければ走査しない（ADR-056 の静けさは保つ）。
2. **上向きの検査（注釈 → 文書）は、走査が走れば常に効く。** 実在しない id は error、現行でない id は warn。誰が opt-in しているかに依存しない。
3. **下向きの検査（記録した指紋との照合）は、現行の文書だけに掛ける。** 現行でない文書の記録は歴史であり、鮮度を問わない（その注釈は上向きの warn が掃除を促す）。
4. **状態×指紋の全マスを、正本の列挙で添字づけた試験が凍結する。** 添字は `_registry.ALL_STATUSES` を読み込んで回す（試験の中に値を書き写さない）。期待表は手書きとし、キー集合が正本と両方向で一致することを検べる。状態が増えれば、期待を書き足すまで試験は通らない。
5. **`AUDIT_CHECKS` の凍結を実在させる。** 独立に転記した名前の並びとの全量一致、および要約の `checks_run` との一致を試験が検べる。検査を足す・消すたびに、転記表を同じ変更で更新することが強制される。
6. **走査の所見コードの正本 `FINDING_CODES` を走査側に置く。** 産出側に一覧が無く消費側の集合だけがある二重符号化を解き、両者の包含を試験が検べる。

## 帰結

- 二つの欠陥（廃止が検査を殺す・発火が併存に依存する）が構造的に再発しない。全 16 マスの答えが期待表として文書化され、挙動の変更は表の差分として見える。
- 版を上げる利用者への影響: 現行でない文書だけが opt-in するリポジトリでも走査が走り、現行でない id を指す注釈が warn になる。これは検査が最初から約束していた答えであり、条件付きで死んでいた穴が閉じた結果である。節を持つ文書が無いリポジトリは従来どおり何も変わらない。
- 試験の様式（正本の列挙で添字づけ、期待の無いマスで落ちる）が、登録簿・Hook 配線・除外規則（TEST-026）・検査名・状態×指紋の五箇所で揃う。列挙の無い次元（次元そのものの発明）は試験では救えない — そこは独立導出と査読に残る（RESEARCH-003 の限界のとおり）。
- 既知の限界: 全マス試験は監査を 16 回起動するため、試験の実行時間が数秒延びる。期待表の正しさ自体は人が決める（表の誤りは試験では見えない）。
