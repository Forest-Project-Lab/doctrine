# コード注釈の書式（対の印・範囲の指紋・走査の対象）

ADR-054 が定めた追跡の終点（注釈の対が囲むコードの範囲）を、機械が読める書式として固める。言語ごとに手段を分けない。構文解析はしない `[R3][R4]`。

## 入出力

- 入力: 走査の根（統治木の親）以下のファイル。
- 返す値: 範囲の一覧・所見の一覧・勘定の三つ。各範囲は `{id, path, begin_line, end_line, fingerprint}`。`path` は根からの相対で、区切りは `/` に揃える（機械をまたいで共有できる形にする）。絶対パスも利用者名も持たない。

### 勘定（保存則。ADR-058）

走査が触れたファイルは、必ず次のどれか一つに数える。**触れたファイル数 ＝ 寄与 ＋ 印なし ＋ Σ 除外**。

- 寄与（annotated_files）: 範囲を一つ以上返したファイル。
- 印なし（unmarked_files）: 読めたが範囲を一つも返さないファイル。入れ忘れが住む場所であり、除外ではない。
- 除外（excluded）: 除外規則の正本表（`EXCLUSION_RULES`）の規則 id ごとの件数。除外はこの表を経由してだけ起こる。
- 刈り（pruned_dirs）: 降りなかったディレクトリの規則 id ごとの本数。配下は未到達と明示する（件数の対象外）。
- 打ち切り（truncated）: ファイル数上限で走査を打ち切ったか。分類せず落とした既知の分は excluded の枠に数える。

全規則の枠を 0 件でも必ず含める（空欄のセルを許さない。SPEC-025 と同じ原則）。項ごとの一覧（members）は、求められたときだけ導出して返す。既定は件数だけとする。

### 問い合わせ（`trace-index.py`）

索引はファイルに置かず、問い合わせのたびに導出する（ADR-055）。

- 引数は `[--root PATH] [--docs-root PATH] [--id ID] [--coverage] [--term TERM] [--format json|text] [--max-files N]`。
- `--id` を与えると、その仕様に対応する範囲だけを返す（仕様の側から見た逆リンク）。与えなければ全ての範囲を返す。
- `--coverage` は勘定（件数）を返す。`--term` を添えると、その項の一覧（`annotated`・`unmarked`・`excluded:<規則id>`・`pruned:<規則id>`）をその場で導出して返す。`--term` は `--coverage` と共にだけ使え、規則の表に無い項は使い方の誤りとする。
- `json` は `{"schema": "trace-index/1", "root": <相対の基準>, "ranges": [...], "findings": [...]}`。`root` は名前だけを載せ、絶対パスを載せない。
- 終了コードは、問い合わせが成立すれば所見の有無にかかわらず 0、使い方を誤れば 2、根が見つからなければ 3 とする。これは問い合わせのための CLI であって、違反を止めるゲートではない（dep-graph と同じ規約）。

### 監査への載せ方

監査は走査が走ったとき（`## 実装の指紋` の節を持つ文書が一つでもあるとき。状態を問わない。ADR-056・ADR-060）、要約に `trace_coverage`（勘定。件数だけ）を載せる。検査所見は増やさない — 版を上げただけで既存の緑の監査が変わらないための段階導入である（ADR-058）。

### 印の書式

一行に印を一つだけ置く。行から前後の空白と非語文字を取り除いた残りが、次のどちらかに一致する行を印とする。

- `doctrine:begin <id>`
- `doctrine:end <id>`

前後の非語文字を無視するので、`#`・`//`・`--`・`;`・`%`・`/*`・`*/`・`<!--`・`-->` のいずれの注釈記号でも同じ規則が効く。言語を知る必要がない。`<id>` は登録簿の書式（`<TYPE>-<NNN>`）とする。

### 疑いの検出（ADR-059）

厳密な照合はいっさい緩めない。照合に一致しない行のうち、**印の語 `doctrine:` の直後（空白を許す）に `begin` または `end` の語が続く行**を、綴りの揺れの兆候（`trace_marker_suspect`）として挙げる。検出できる変種は、コロンの後の空白・小文字の id・下線の id・行頭の語文字（文字列の中の印の形）・余計な語の付加・id の欠落である。印の語自体の綴り誤りは検出できない（走査は印の語で読む対象を絞る）。散文が偶然この形を踏む誤検出がありうるので、監査は advisory に留める。

印の書式をコードの原文にそのまま書かないこと。試験が守る規律（IMPL-021）を、走査の実装自身と、走査の対象になる全てのコードに広げる。書式の例示は統治文書（`.md`。走査の対象外）だけが持つ。

### 対応付け

- 入れ子を禁じる。開いている間に `begin` が来たら誤りとする。
- `end` は直前に開いた `begin` を閉じる。両端の `id` が食い違えば誤りとする（写し間違い・並べ替えの取り違えを捕まえる。冗長だが安い）。
- 開いていない `end` は誤りとする。
- ファイルの終端で開いたままなら誤りとする。
- 同じ `id` の範囲が複数あってよい（一つの仕様を複数の場所で実装しうる）。

### 範囲の指紋

- 対象は、印の行を**含まない**、その間の行だけとする。印の注釈記号を書き換えても指紋は変わらない。
- 正規化の順は、BOM の除去 → 改行を LF（改行一文字だけの形）へ揃える → 各行の行末の空白を除去 → 末尾の空行を除去 → `utf-8` で符号化。
- `hashlib.sha256` で計算し、`sha256:<64桁>` と記す（EXT アンカーと同じ記法。ADR-039）。

正規化する理由は、内容が同じものを古びと判じないためである。改行コードは環境が混ざれば割れる（同じリポジトリを Windows と Linux の両方で扱うと起きる）。行末の空白は整形器が黙って落とす。EXT アンカーの指紋が生のバイト列なのは、そこでは「外部のファイルが一バイトも変わっていないか」という別の問いを見ているからであり、規則が違うのは意図である。

## 制約

- 標準ライブラリだけで実装する（DECIDED-001 事実7）。構文解析器を使わない。
- 除外は、除外規則の正本表（`EXCLUSION_RULES`）の規則 id を経由してだけ起こる。表に無い除外を作らない。規則を足す・消すときは表と勘定の枠を同じ変更で更新する（TEST-026 が凍結する）。
- 統治木の中は走査しない。文書は追跡の終点にならない。根が統治木と重なる呼び方でも、包含で判じて刈る。
- `.md` は走査しない。この書式を説明する文書自身が印として読まれるのを断つ（自己言及を構造で断ち切る）。
- dot で始まるディレクトリと `node_modules` は見ない（監査の体系外 .md 走査と同じ規約。SPEC-011）。ディレクトリへのシンボリックリンクは降りない。いずれも刈りとして数える。
- 通常ファイル以外（名前付きパイプ・ソケット・デバイス）は開かない（開くと戻らないことがある）。開く前に stat で判じ、除外として数える。
- 内容の先頭に値ゼロのバイトを含むファイルは飛ばす（バイナリを読まない）。
- 一ファイルの大きさの上限と、走査するファイル数の上限を設ける。超えたときは飛ばした事実を所見一つで正直に告げ、勘定にも数える（黙って切り詰めない。SPEC-011 の語彙的酷似と同じ作法）。
- 速さのため、印の文字列を含まないファイルは復号せず印なしに数える。ただし「読まずに飛ばす」ことはしない（読んで含まれないと確かめてから数える）。

## エラー時挙動

- 読めないファイル・復号できないファイルは、規則 id で勘定に数えてから飛ばす。走査そのものは止めない（復元力を完全性より採る。§1.10。何を飛ばしたかは勘定が残す）。
- 読めないディレクトリは刈りとして数える。配下は未到達である。
- 印の対応付けの誤り（入れ子・不一致・閉じ忘れ・開いていない `end`）は、走査を止めずに所見として集める。一ファイルの誤りが他のファイルの走査を巻き込まない。
- 走査は決して例外を外へ出さない。

## 受入基準

- 注釈記号の異なる複数の言語（`#`・`//`・`--`・`;`・`%`・ブロック注釈）で、同じ印が同じように読めること。
- 印の行を含めずに指紋を取ること。印の注釈記号だけを書き換えても指紋が変わらないこと。
- CRLF と LF で同じ内容なら、指紋が一致すること。行末の空白の有無で指紋が変わらないこと。
- 入れ子・両端の `id` の不一致・閉じ忘れ・開いていない `end` を、それぞれ別の誤りとして挙げること。
- 統治木の中と `.md` を走査しないこと。バイナリを飛ばすこと。
- 上限を超えたときに、飛ばした事実を告げること。
- 返す `path` が相対で、区切りが `/` であること。絶対パスを含まないこと。
- `trace-index.py` が `--id` で仕様の側からの逆リンクを返すこと。`json` に絶対パスが混じらないこと。終了コードが 0/2/3 になること。
- 勘定の保存則が成り立つこと: 触れたファイル数 ＝ 寄与 ＋ 印なし ＋ Σ 除外。
- 勘定に全規則の枠が 0 件でも在ること。枠の集合と規則の表が両方向で一致すること。
- 名前付きパイプが根の配下にあっても走査が止まらず、除外として数えられること。
- 印なしが除外ではなく独立の項として数えられること（入れ忘れの住処を規則の陰に隠さない）。
- `--coverage` が件数を、`--coverage --term <項>` が当該の一覧を返すこと。一覧は既定で持たないこと。
- 監査の要約に、走査が走ったときだけ `trace_coverage` が載ること。opt-in が無ければ載らないこと。
- 綴りの揺れた印（コロンの後の空白・小文字/下線の id・行頭の語文字・余計な語・id の欠落）が疑いとして挙がること。厳密な照合の答え（範囲を作らない）は変わらないこと。
- 正しい印・印の語だけの散文・コロンの直後が空白でも `begin`/`end` でもない行（照合の原文など）が、疑いにならないこと。
- リポジトリ自身を走査して、疑いがゼロであること（実装・試験の原文に印の形を書かない規律の凍結）。
- 受入は TEST-026 が凍結する。
