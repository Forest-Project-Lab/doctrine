# 不変の ADR に誤りを見つけたときの正規の直し方

## 背景

不変性ガード（Guard1）は、既存の ADR の改変を拒否する（carve-out は status 遷移と `superseded_by`／`updated` の付与だけ）。この規範のため、ADR を Write で作った直後に、その ADR へ用語チェッカーの誤り（禁止同義語・カルク）や、フロントマターの構造的な誤り（循環を生む `depends_on` 等）が見つかっても、その場で Edit や Write で直せない（#100）。Wave 群の実装中に何度も遭遇し、いずれも「削除して作り直す」で回避した。

CI の一括スキーマゲート（#91）が禁止同義語を error として落とすようになったため、ADR は作成時に一発で用語を正す必要がある。誤ったまま入ると、後から直せずマージ前で止まる。

## 却下した選択肢

- **carve-out を広げ、本文以外（メタデータ・軽微な用語直し）の編集を許す**: 「本文以外」と「決定の内容」の境目は判断であり、機械では引けない。carve-out を広げると、決定の書き換えを見逃す穴になる。不変性は決定の内容を守るための規範であり、弱めない。

## 決定

不変性は現状のまま保つ。誤りを見つけたときの正規の直し方を定める。

- **未コミットの ADR（作った直後）**: 削除して作り直す。`rm` は、その ADR を現行の文書がまだ参照していないため削除安全ガードを通る。作り直しでは用語・フロントマターを最初から正す。
- **マージ済みの ADR**: 後継の ADR で置換する（`superseded_by` を付け、status を superseded へ。carve-out の範囲）。決定の訂正は、新しい決定として記録する（履歴を残す）。

作成時に誤りを入れないのが第一である。ADR を書く前に、禁止同義語（現行・履歴・投影・文書・ドメイン等の右列）とカルク（一覧）と英単語の直訳を避ける。一語訳の罠（status→位置づけ、native→標準で 等）にも注意する。

## 帰結

- 不変性の穴を作らずに、誤った ADR を直す道が明文化される。
- 作成時に用語を正す運用が、CI の一括ゲートと噛み合う（誤ったまま入れない）。
- 既知の限界: 一発で正しく書く負担は残る。これは決定の不変性の対価であり、受け入れる。
