# 巨大な台帳 PR の門の受入

SPEC-030 の受入である。テストコードは `plugin/tests/test_ledger_diff_summary.py`
（CI が毎回走らせる単体テスト群の一つ）。`git` を呼ぶので、実リポジトリではなく
使い捨ての git 木を組んで測る（決定的にするため。実リポジトリには触れない）。

## 受入基準への対応

- 閾値: 一件の処遇に相当する小さい差分では門が鳴らないこと、二万行規模で鳴ることを凍結する。
- 二つの出口: 作成者以外の承認で通ること、digest の一行が本文に在れば通ること、
  どちらも無ければ終了コード 1 で止まることを凍結する。
- **digest の改竄**: 手で書き換えた digest では通らないことを凍結する。数を打ち直せる形に
  すると要約は測定ではなく主張になる。
- **過少報告**: 網羅台帳の実物の形（`dispositions` 5 件と `entries` 338 件を両方持ち、
  名の鍵は `key`）で、動いた 21 件を 21 件として数えることを凍結する。**実際に落とした** ——
  最初に見つけた一覧だけを数える作りで、再判定 21 件が「動いた件 0」と要約された。
  要約が黙って過少に出るのは、要約が無いより悪い（読み手は「見た」と思う）。
- **名前空間**: 別の列に同じ名が在っても衝突しないことを凍結する。
- 破損: 前後どちらの台帳が読めなくても「破損の疑い」として挙がり、**新規ファイルにも空にも
  見えない**ことを凍結する。
- 範囲: `assurance/ledger/` 以下の `.json` 以外は数えないことを凍結する。
- 入口: `--diff-base` の欠落・未知の引数・引けない基準が終了コード 2 になることを凍結する。
- **配線**: CI（`.github/workflows/checks.yml`）が本スクリプトを呼んでいることを凍結する。
  走らせ手を足して読む段を足さない形（INC-012・INC-015・ADR-148 で三度起きた）を作らない。

## 合否基準

`python3 plugin/tests/test_ledger_diff_summary.py` が全件通ることを合格とする（CI では
`plugin/run_tests.py` が同じものを走らせる）。一件でも落ちれば不合格であり、赤を避けるために
閾値や照合を緩めない。**過少報告の錨**（動いた 21 件を 21 件と数える）と**配線の錨**
（CI が呼んでいる）は、他が通ってもこの二つが落ちれば不合格である —— 門が在るのに数が
出ない状態と、門が在るのに走らない状態は、どちらも門が無いのと同じだからである。

## 退行観点

- 「一覧の鍵を一つ選ぶ」形へ戻さない。列に見えるものを全部数える。
- 破損を「空」や「新規ファイル」へ写像しない（INC-027 で直した形をここで作り直さない）。
- 一覧の打ち切りを無音にしない（「ほか N 件」を必ず告げる）。
- 実時計を読まない。閾値は行数であって時間ではない（WATCH-001 第8項・第11項）。
