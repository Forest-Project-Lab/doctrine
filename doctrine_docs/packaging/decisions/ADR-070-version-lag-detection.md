# 導入済みの複製の遅れを鼓動が検める — 正本の版との照合

## 背景

版 0.5.0 の公開後も、フックは二日前に導入した 0.4.0 の複製で動き続けた。
監査要約に `trace_coverage` が載らず、紐づけキャンペーン・契約注入の進捗計・
編集時の促しの三機構がすべて沈黙した。原因は故障ではなく「更新の一手が
打たれていない」ことだが、それを指す照合が無かった。

ADR-066 の版の切替の検出は、セッション冒頭の版と今の版を比べる。導入済みの
複製が古い**まま**のとき、二つの版は一致し続けるため、この検出は決して鳴らない。
生存期待 [R11] は「注入があるか」を見るが、注入する側の版が体系の正本より
古いことは誰も見ていなかった — 注入は生きているのに中身が一世代前、という
死角である。マーケットプレイスをディレクトリで指す自己適用のリポジトリでは、
公開のたびにこの遅れが構造的に再発する。

## 却下した選択肢

- **監査の検査にする**: 監査は SessionEnd に走る。「更新して新しいセッションを
  開始する」はセッションの中で言わなければ実行可能でない。ADR-066 が版の切替を
  鼓動に置いたのと同じ判断。
- **導入の台帳（`~/.claude/plugins/` 配下）を読む**: 統治はリポジトリの中で
  閉じる（ADR-066 決定4・NONGOAL の越境の線）。実行中のコード自身の版が
  「いま動いている版」の証しであり、リポジトリの外の台帳は要らない。
- **版の大小を比べて「遅れ」だけ鳴らす**: 版の文字列に順序を仮定できる保証が
  ない。不一致だけを判じ、向きは言わない（`version_drift` と同じ規則）。
- **食い違いを検出したら自動で更新する**: 導入済みの複製は利用者の環境であり、
  統治が書き換えない。助言だけを返す（リンタと同じ線 — 拒否も実行もしない）。

## 決定

1. **判定は共有コアに一度だけ置く。** `_auditcache.version_lag` が、実行中の
   包みの版（`plugin.json` の version）と、プロジェクトの
   `.claude-plugin/marketplace.json` が同名のプラグインに宣言する版を比べる。
   正本の版は、項目の `source` が指す先の `plugin.json` を優先し、読めなければ
   項目の `version` に退避する。どれかが読めなければ判じない（前方寛容）。
2. **鼓動が毎回検め、助言の一行を足す。** 食い違えば「導入済みの複製が正本と
   食い違う。更新して新しいセッションを開始する」を、更新の言い方
   （`claude plugin update <プラグイン>@<マーケットプレイス>`）まで含めて告げる。
3. **マニフェストを持たない導入先では黙る。** 照合が成立するのは、統治対象の
   リポジトリ自身がマーケットプレイスの正本である（自己適用の）ときだけ。
   通常の利用者を騒がせない（ADR-063 の静けさと同じ線）。

## 帰結

- 「公開したら導入済みも更新する」という、覚えるしかなかった運用知識が、
  覚えなくてよい促しになる（ADR-066 帰結と同じ形の閉じ方）。
- ADR-066（セッション途中の切替）と本決定（遅れたまま動き続ける）で、版の
  食い違いの二つの形が両方とも照合される。
- 既知の限界: 同じ版番号のまま中身だけ差し替えた複製は見分けられない
  （ADR-066 と同じ）。マニフェストがこのプラグインを名前で載せていなければ
  黙る。マーケットプレイスが実際に設定へ組み込まれているかまでは検めない。
