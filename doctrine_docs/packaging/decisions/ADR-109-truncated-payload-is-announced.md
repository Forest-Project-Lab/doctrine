# 封筒を切り詰めたら黙らない。標準エラーへ一行で告げる

## 背景

ADR-108 で、Hook の封筒の読み取りを共有コアへ一本化し、上限（8 MB）が全部の Hook に
掛かるようにした。**そのとき保証限界に一つ残した** —— 切り詰められたことは呼び手に
伝わらない。正本は空の写像を返すだけで、**「封筒が無い」と「大きすぎた」を区別しない。**

測った。上限を超える封筒を三本に渡し、標準エラーを見た。

```text
review-nudge   stdout=0字   stderr=''
gov-heartbeat  stdout=718字 stderr=''
capture-nudge  stdout=0字   stderr=''
```

**完全に黙っている。** 使う人から見れば、Hook が理由もなく助言を出さなくなる。

この体系は**黙って切り詰めない**規律を三度立てている —— 走査の切り詰めは所見一つで
正直に告げ（ADR-059）、語彙的酷似の省略も助言一つで告げ（SPEC-011）、
`.gitignore` による刈りは規則 id を経由して数える（ADR-089）。**封筒だけが黙っていた。**

## 却下した選択肢

**不具合のジャーナルへ記録する。** あの記録は「**doctrine の部品が実行時に倒れた**」の
ためのものであり（ADR-074）、鼓動はそれを「不具合の疑い」として報告を促す。
**切り詰めは倒れではない。** そこへ書くと、**名が事実を語らなくなる** —— この体系が
繰り返し直してきた欠陥そのものである。

**返す値を変えて呼び手に伝える（写像と真偽値の対を返す）。** 呼び手は三本とも
「封筒が無い」と同じ道へ退く設計であり、**受け取っても使い道が無い。**
公開の形を変える対価に見合わない。

**上限を上げる／外す。** 上限は memory を守るための正本の判断である（ADR-108）。
**黙りを直すために守りを外さない。**

**何もしない（保証限界のままにする）。** 三度立てた規律の四件目の例外を残すことになる。
しかも**使う人には理由が見えない。**

## 決定

**上限に達して切り詰めたら、標準エラーへ一行で告げる。返す値は変えない。**

1. **切り詰めを検める。** 上限まで読んだあと一文字だけ余分に読み、まだ残っていれば
   切り詰めと判ずる。
2. **標準エラーへ一行。** 部品の名・上限・「封筒が上限を超えたので空として扱う」を書く。
   Hook が返す JSON の経路は汚さない。**この口は既に使われている**（注入と監査が
   警告と内部誤りを標準エラーへ書く）。
3. **不具合のジャーナルへは記録しない。** 倒れではないからである（上記）。
4. **返す値は変えない。** 空の写像のまま —— 呼び手は封筒が無いときと同じ道を通る。

## 帰結

- 三度立てた「黙って切り詰めない」の規律が、封筒にも掛かる。
- 使う人が、Hook が黙った理由を知る道ができる。
- 保証限界: **標準エラーが使う人に見えるかは、実行環境が決める。** この体系は
  それを保証しない —— 保証するのは「**書くこと**」までである。
- 保証限界: 一文字余分に読むので、**上限ちょうどの封筒でも一度余分に読む**（無害）。
- 保証限界: **上限そのものの妥当性は測っていない**（ADR-108 と同じ。8 MB は見立て）。
- 保証限界: 切り詰めの回数は数えない。**起きたことを一度告げるだけ**である。
