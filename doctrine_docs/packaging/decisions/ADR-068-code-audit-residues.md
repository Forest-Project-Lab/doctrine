# 開発方法論の機械化残差 — コード層の検算三点と開発規範の正本化

## 背景

ADR-047 は方法論（テスト駆動・ドメイン駆動・オブジェクト指向）の採用範囲を決めたが、担保の機械は文書層で止まっていた。仕様に対するテスト文書の不在は逆孤児検査が拾うのに、**コードの import 境界は無検査**で、リンタが監査を取り込んでも誰も止めない。規則の二重定義の禁止（DECIDED-001 事実1・WATCH）も**コードのリテラルには効いておらず**、棚卸しの実測で九件の二重定義（要約 schema の三重・状態行文法の二重・段階次元の四重ほか）が素通りしていた。方針は寄稿の案内（CONTRIBUTING.md）にあり、それは統治木の外 — 監査の視界の外で、着地検査（adr_not_landed）が警告する「文書上の宣言に留まる」欠陥類型が、方法論そのものに起きていた。

方法論の遵守そのものは意味の判断であり、機械では閉じない（NONGOAL 第1項と同じ形）。しかし各方法論には**機械で検算できる残差**がある。新しい検査器の発明ではなく、既にある機構（境界の検査・列挙添字の凍結・正本は一つ）をコード層へ対称に写す。

## 却下した選択肢

- **外部の点検器（flake8。pip で配る Python 点検器）の導入**: pip 依存になる（DECIDED-001 事実7 違反）。要る検査は三種だけで、標準ライブラリの `ast` で足りる。
- **per-turn のフックで検査する**: ターンごとの全走査はしない（NONGOAL 第5項）。実行面は CI とし、リンタの一括検査（#91）と同じ隔離に従う。
- **docs-audit へ検査群として足す**: docs-audit は既に約 1,600 行・30 検査で、肥大が固着しつつある（分割は別 ADR で裁く）。対象も返す形も別物（コード対 文書）なので、別体 `code-audit.py` とする。
- **import の許可行列をモジュール別に固定する**: 現状を丸ごと凍らせると、正当な整理まで表の更新を要して雑音になる。規則は三条（下記）の関係だけに絞り、行列は必要が出てから。
- **test-first の順序や抽象の先取りも検査する**: 履歴を持たない体系で順序は原理的に検証不能、先取りは意味の判断。保証限界として正本に書く。

## 決定

1. **`code-audit.py` を新設し、三種の検算を置く。** 対象は `plugin/scripts/*.py` と `scripts/*.py`（試験は対象外 — 試験は全てを取り込んでよい）。
   - **import 境界（error）**: 三条 — 入口スクリプト（`_` で始まらない）は他の入口を取り込まない／共有コア（`_*`）は入口を取り込まない／`_registry` は体系内の何も取り込まない（最下層）。ドメイン駆動の「共有コアは境界づけられた文脈、入口は利用者」（ADR-047）の機械化。
   - **二重定義リテラル（advisory）**: 二つ以上のファイルに現れる同一のタプル・集合・長い文字列定数の代入を挙げる。「規則を二重定義しない」の機械化。
   - **肥大（advisory）**: 上限（関数 120 行・ファイル 1,300 行。正本は `LIMITS`）を超える関数・ファイルを挙げる。分割の判断は人に残し、兆候だけを名指しする。
2. **検査名と上限は列挙で正本化し、転記表の試験が凍結する**（ADR-060 の規範に従う）。構文解析に失敗した対象ファイルは error で告げる（黙って飛ばさない — 検査名は解析不能を含めて五つ）。返す値は `code-audit/1` の JSON と平文。終了コードは `--fail-on error` のとき error があれば 1。
3. **CI に配線する。** 継続的結合の検査段に code-audit を足す（error で門を閉じ、advisory は報告のみ）。フックには配線しない（実行面の隔離。将来足すなら別の決定）。
4. **開発規範を PROC-001 として統治木に正本化する。** ADR-047 の採用範囲・三検算の位置づけ・保証限界（順序と先取りは人の査読）を手順書に置き、CONTRIBUTING.md は正本を指す案内に痩せる（二重定義しない）。
5. **テスト文書も指紋を記録してよいことを規範に明記する。** 追跡の機構は文書型を選ばない。TEST 文書がテストコードの範囲の指紋を記録すれば、仕様⇔実装⇔試験の三角が閉じる（先導例は自己適用のキャンペーンで入れる）。

## 帰結

- 方法論が「決めた」から「検算される」へ動く。棚卸しで実測した九件の二重定義と 148 行関数が、導入した日から名指しされる（advisory — 合否は変えず、分割・統合の判断は人に残す）。
- 自分の監査（docs-audit）へは何も足さない。統治木の緑は変わらない。
- 既知の限界: 検算できるのは残差だけである。test-first の順序・抽象の先取り・良い設計そのものは検証しない（PROC-001 が保証限界として持つ）。二重定義の検出は字面の一致に限る（意味的に同じで綴りが違う重複は見えない — NONGOAL 第1項と同じ線）。
