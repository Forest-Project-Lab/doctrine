# 事故分析の推奨は処遇を持ち、terminal に至るまで次の行動に挙がり続ける

## 背景

ADR-124 は、台帳の成果物の種別ごとに「読む関数の名」か「読まない理由」かを必ず
持たせた。その検査は**ファイルの種別までしか見ない**。事故分析の記録
`ledger/cast/<事象 id>.json` は「読まれている」と宣言できたが、読み手が見るのは
生成日時だけで、統制欠陥・先行指標・新規仮説・推奨は正本へ一度も入力されていなかった。

数えると、17 件の事象から出た推奨は **146 件**あり、うち 43 件は所有者判断を要すると
分析自身が印していた。どれも次の行動にも報告の規定形式にも現れていない。分析は
一件あたりおよそ一ドルで毎反復買われながら、その成果は台帳に滞留していた。

同型の未接続の四度目である（INC-012・INC-015・ADR-124・INC-016）。前三度と違うのは
粒度で、ファイルは読まれており、読まれていないのは中身である。

## 却下した選択肢

- **推奨を読んだら全件を次の行動に並べる**: 146 件が一度に並ぶと、先頭から着手する
  規律が働かない。信号が薄まり、短い行動列を「済んだ」と読ませない工夫も無意味になる。
- **処遇を事故分析の記録そのものへ書き戻す**: 実装者が評価者の判定を書き換える形に
  なる。評価の記録は評価者だけが書く（ADR-115 の独立性）。
- **所有者判断の要る推奨もレーンの未着手として並べる**: 勝手に進めてよい物と判断を
  仰ぐ物が同じ列に混ざる。境界は列の形で保つ。
- **報告のたびに人が台帳を読み返して思い出す**: 四度思い出さなかった。記録の存在は、
  記録が次の判断に届くことを保証しない。

## 決定

1. 事故分析が出した推奨は、`(事象 id, 番号)` で一意に指し、**処遇**を持つ。語彙は
   `pending`（未着手）・`landed`（機構化済み）・`rejected`（却下）・`owner`
   （所有者判断待ち）の四つとし、terminal は後ろの三つとする。
2. 処遇は台帳の別の記録（`ledger/recommendation-status.json`）に置く。事故分析の
   記録には書き戻さない。
3. 未着手の推奨が残る間、正本は `APPLY_FINDINGS` を次の行動として挙げる。挙げるのは
   先頭の一件だけとし、未着手・所有者判断待ち・処遇済みの件数を必ず添える。
4. `rejected` は理由を、`landed` は証拠のポインタを必ず持つ。持たない処遇は
   正本の自己検査を赤にする（根拠なき合格判定を書かないのと同じ扱い）。
5. 処遇の書かれていない推奨の既定は、分析が所有者判断を印していれば `owner`、
   それ以外は `pending` とする。既定も明示であって、黙認ではない。

## 帰結

- 状態機械に `APPLY_FINDINGS`（推奨の処遇決め）を足し、名指しできる側へ置く。
  遷移は `CAST_DONE` の行き先を `APPLY_FINDINGS` へ移し、未着手が尽きたときに
  `FINDINGS_TRIAGED` で創出へ戻る。ADR-120 の二分は保つ。
- 処遇の台帳は新しい成果物の種別なので、ADR-124 の不変条件が読取経路の宣言を要求する。
  本決定はその不変条件が働いた最初の例である。
- 所有者判断を要する 43 件は、報告のたびに思い出す物ではなくなる。正本の `status` が
  数えて一覧に載せ、人はそれを読む。
- **この決定は推奨を片づけない。**146 件のうち処遇が済んだのは 0 件であり、当面の
  反復は処遇決めが先頭に来る。滞留していた事実が見えるようになっただけで、
  見えるようになったことを片づいたことと読まない。
- 先行指標のうち「未適用の推奨の滞留反復数」は測れるようになったが、「新規仮説の
  消費率」と「次の行動に占める分析由来の割合」は、まだ測る口が無い。緑の意味は
  推奨の粒度までであり、統制欠陥と先行指標そのものはなお正本へ入力されていない。
