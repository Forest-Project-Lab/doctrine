# 次の行動の優先順は表に持ち、測る対象（本丸の欠落）を測る道具（基盤の推奨）より前に置く

## 背景

正本は「次にやることを手で選ばない・先頭の一件から着手する・飛ばさない」を定める
（ADR-115）。**この規律の下では、並びそのものが規範である** —— 並びが誤っていると、
規律を守る者ほど誤った方へ進む。

ところが並びは、どこにも書かれていなかった。`next_actions` が `actions.append` を
呼ぶ順序が、事実上の優先順だった。表に無いので読めず、試験も無いので凍っておらず、
段を足すたびに黙って変わる。

ADR-130 が本丸の欠落を初めて次の行動に出したとき、その形が実害になった。
`APPLY_FINDINGS`（検証基盤の改善の推奨 177 件）が `MAP_COVERAGE`（体系そのものの
欠落 299 件）より前に立った。推奨は一件ずつしか処遇できないので、規律どおり先頭から
着手する限り、**推奨 177 件を消化しきるまで本丸へ一度も着かない。**

数の非対称が効く。道具の改善の推奨は反復のたびに増える（事故分析が推奨を出すのが
その仕事である）。本丸の欠落は減るだけである。増え続ける側が前に立つと、減る側は
永久に順番が来ない。

ADR-130 は同じ構図を「正本が読む段が無い」の側から直した。これはその続きで、
読む段は在るのに**順番が来ない**という形である。

## 却下した選択肢

- **先頭を飛ばして本丸へ着手する**: 運転手順 §1 が明示的に禁じている。飛ばしたく
  なったのは正本の優先順が誤っている兆候であり、飛ばす側ではなく正本の側を直す。
  実際 INC-006・INC-012・INC-015 はその形で見つかった。
- **`append` の順序を入れ替えるだけにする**: いま在る誤りは消えるが、原因は消えない。
  次に段を足す者がどこへ挿すかは、やはりどこにも書かれていない。同じ欠陥が黙って戻る。
- **件数や緊急度から優先順を計算する**: 数の多い側が勝つ規則にすると、今回の実害が
  そのまま規則になる。緊急度は評価であって決定論ではなく、`next_actions` に judgement
  を持ち込む（ADR-115 に反する）。
- **推奨を一括で処遇できるようにして山を崩す**: 山の高さは症状であって原因ではない。
  高さが変わっても、増える側が前に立つ構図は残る。

## 決定

1. 名指しできる状態の優先順を、コードの表（`ACTION_PRIORITY`）に一度だけ持つ。
   `next_actions` は `(優先順, 発生順)` で安定に並べ替えて返し、`append` の位置が
   並びを決めることを止める。同じ状態の中の順序（三冊の jerg→stpa→cast など）は
   発生順のまま保つ。
2. 順序は次に凍結する（所有者判断。試験が凍らせる）:

   | 順 | 状態 | 位置の理由 |
   |---|---|---|
   | 1 | `INGEST_NORMS` | カタログが無ければ網羅台帳が立たない（他のすべての前提） |
   | 2 | `CAST_ANALYSIS` | 「なぜ見逃したか」を残す装置。動かさない |
   | 3 | `REVIEW_ASSUMPTION` | 想定が破れれば、そこに寄りかかる下流の適合が根拠を失う |
   | 4 | `MAP_COVERAGE` | 本丸（体系そのもの）の欠落。**測る対象** |
   | 5 | `APPLY_FINDINGS` | 検証基盤の改善の推奨。**測る道具**の完成度 |
   | 6 | `ATTACK_EVALUATOR` | 評価器自身への攻撃 |
   | 7-8 | `FORMALIZE` / `DISCOVER` | 上のどれも鳴らないときの既定の入口（INC-006） |

3. 位置の根拠は「検証基盤は本丸を測るための道具であって、道具の完成度が目的では
   ない」とする。数の多い道具の推奨が、数の少ない本丸の欠落を押しのける形を禁ずる。
4. 名指しできる状態（`NAMEABLE_STATES`）は、すべて優先順の表に載っていること。
   載らない状態は並びの中で自分の位置を主張できず、黙って末尾へ落ちる —— これは
   `ATTACK_EVALUATOR` が5反復飛ばされたのと同じ形である（INC-012）。差集合が
   空でなければレーンの試験を赤にする。

## 帰結

- 実測で、先頭が `APPLY_FINDINGS`（推奨 177 件）から `MAP_COVERAGE: jerg の 80 件`
  へ移った。本丸の欠落 299 件に、規律を守ったまま着手できる。
- 優先順が読める場所に在る。次に段を足す者は、表のどこへ入れるかを決めて書く。
  決めずに足すと試験が赤になる。
- **これは「推奨を軽んじる」決定ではない。**推奨は消えず、処遇に至るまで挙がり続ける
  （ADR-125 のまま）。本丸の欠落が尽きたときに順番が来る。
- 優先順は保証の範囲そのものではないが、何を先に保証するかを決めるので、変更には
  所有者判断を要する。表の書き換えはこの ADR の置換を経ること。
