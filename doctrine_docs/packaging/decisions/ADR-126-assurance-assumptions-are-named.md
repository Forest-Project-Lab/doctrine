# 保証が寄りかかる想定は、決定でも非目標でもなく想定として名指しし、失効の先行指標を併記する

## 背景

INC-001（SessionEnd 監査の不実行）の事故分析は、推奨として「『SessionEnd は必ず発火する』
『last-audit.json は監査以外が書かない』という二つの安全上の想定を明示的に文書へ記録し、
それぞれの想定が失効したことを示す先行指標を併記する」を挙げた。

この二つを置く場所が体系に無かった。確定方針（DECIDED）は**決めた**事実であり、
想定は決めた物ではない。やらないこと（NONGOAL）は**引き受けない**範囲であり、
想定は引き受けているのに検めていない物である。退行監視（WATCH）は**戻してはならない**
事項であり、想定は戻る戻らないの話ではない。三つのどれに書いても意味がずれる。

ずれたまま散らばると何が起きるかは、実測で出た。ADR-119 は帰結に「依然として区別
できないのは『SessionEnd がそもそも発火しない』場合である。これは残す限界として台帳に
持つ」と書いたが、それは限界の記述であって、いつ限界が現実になったかを告げる指標では
なかった。結果、想定が破れていることに二日気づかなかった。

## 却下した選択肢

- **想定のための型を登録簿へ足す**: 型は配布物の構造規則であり、`_registry.py`・
  リンタ・ガード・監査・雛形の全部に及ぶ。想定の置き場が要るという理由だけで
  配布境界を動かすのは対価が釣り合わない。
- **NONGOAL へ第19項として足す**: 「想定が破れたことは検出しない」と書けば形は通るが、
  非目標は永久に閉じてよい項であり、想定は閉じてはならない項である。同じ表に置くと、
  検めるべき物が「引き受けないと決めた物」の顔で並ぶ。
- **DECIDED へ足す**: 検証していない前提を確定事実の表へ書くのは、根拠なき
  PASS（適合の証拠あり）と同じ形である。DECIDED の値打ちは「そこに在るものは
  決まっている」ことにある。
- **散文の ADR に書いて終わりにする**: 推奨が求めたのは記録と**先行指標**である。
  散文は指標を観測できる形にしない。同型の「文書上の宣言に留まる」欠陥は三度出ている
  （WATCH-001 第6項）。

## 決定

保証が寄りかかる想定は、保証台帳の登記簿 `assurance/ledger/assumptions.json` に
一件ずつ載せる。各項は次を持つ。

1. `verified_by` の欄を必ず持つ。検証者が居なければ `null` と**明記する**
   （欄の不在は理由にならない）。
2. 先行指標を一つ以上持ち、各指標は「どこで観測するか」と「何を異常と見るか」の
   両方を持つ（ADR-117 と同じ二条件）。
3. 観測を書くときは日付と状態語彙を添える。語彙は保証レーンの六語
   （PASS（適合の証拠あり）／FAIL（走ったが不適合）／UNKNOWN（観測できず判定不能）／
   UNASSESSED（前提欠如で未評価）／DEGRADED（縮退運転）／NOT-APPLICABLE（非該当））
   をそのまま使い、ここで語を増やさない。
4. 指標として成り立たないと判った案は捨てず、`rejected_indicators` に理由つきで残す。
5. PASS でない観測を持つ想定は、対応する事象 id を持たないかぎり、正本が
   `REVIEW_ASSUMPTION` として次の行動に挙げ続ける。

## 帰結

- 正本（`orchestrator.py`）が `load_assumptions` と `assumption_backlog` で読み、
  `REVIEW_ASSUMPTION` を状態機械の**名指しできる**側へ置く（ADR-120 の二分を保つ）。
  台帳種別の宣言（ADR-124）も同じ差分で足す —— 足し忘れは実際に赤で止まった。
- 挙げる位置は推奨の山より**前**とする。想定は保証の前提であって成果物ではなく、
  前提が破れれば下流の PASS は根拠を失う。後ろに置くと 100 件超の推奨の陰に隠れ、
  ATTACK_EVALUATOR が5反復飛ばされたのと同じ形になる（INC-012）。
- 事象 id を持つ想定はここで鳴らさない。是正は事象の側（CAST_ANALYSIS と推奨の処遇）が
  持っており、二重に鳴らすとどちらを踏んでも消えない行動になる。
- 次の行動に挙がらない想定も、`status` が必ず数えて出す。挙がらないことと登記簿が
  読まれていないことが区別できなければ、種別の宣言だけが在って中身が読まれていない
  形（INC-016）を繰り返す。
- **登記簿は保証を強くしない。**想定を名指しすることは、想定が真になることではない。
  実際、最初の三件のうち二件は初回の観測で PASS ではなかった。
