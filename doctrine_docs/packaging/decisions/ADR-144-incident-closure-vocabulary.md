# 事象のクローズの語彙 — 受容は裁定者を持ち、出荷は三条件で立て、想定の観測は機械が追記する

## 背景

事象の台帳は「閉じた」を言い表す印を三つ持ち始めていた。INC-017 と INC-026 は
所有者裁定（2026-08-07）で費用として受理され、`cost_accepted` の印が付いた。
INC-019 は「修正が利用者の複製に届いたか」を問う —— 版番号は複製の同一性を
判定しない（同事象の実測。15 コミット離れた複製が同じ版番号を持った）ので、
「出荷済み」を版の文字で言うことはできない。想定の登記簿（ADR-126）は観測を
持つが、観測を書く手は人であり、機械の観測と独立の検証が分かれていなかった。

語彙が正本に無いまま印だけが増えると、三つの形が沈黙する: 裁定者の無い受容
（誰も引き受けていない費用）、根拠の無い出荷（届いた証拠の無い `shipped:
true`）、直った事象への受容（矛盾した二重のクローズ）。加えて、受容済みの
事象が DISCOVER（失敗仮説の創出）の種に流れ続け、裁定済みの選択肢を毎反復
問い直していた。

## 却下した選択肢

- **closed の一語で全部を言う**: 「直った」「費用として受け入れた」「届いた」は
  別の主張であり、要る証拠も別である —— PASS（適合の証拠あり）の
  verify 記録・裁定者・tag の照合。
  一語に畳むと、どの証拠が欠けているかが判らなくなる —— 一語に二つの意味を
  持たせる取り違えは INC-006・INC-010 で二度起きた。
- **shipped を版番号で判ずる**: 版番号は複製の同一性を判定しない（INC-019 の
  実測）。判定の根拠にできるのは commit の系譜だけである。
- **想定の観測も検証も機械に書かせる**: 観測器自身の誤りは観測器では検められ
  ない。機械が書けるのは観測までで、検証者の欄は独立の実施だけが埋められる
  （実装者の申告を信じない。ADR-127 と同じ向き）。

## 決定

事象のクローズの語彙を次のとおり定め、正本の自己検査（validate）が形を機械で
検める。

1. **受容**: `cost_accepted: true` の行は `cost_accepted_by`（裁定者の名指し）を
   必ず持つ。`fixed: true` とは両立しない —— 直ったなら受容は要らない。
   受容済みの事象は DISCOVER の種にしない —— 裁定済みの選択肢を毎反復問い直す
   「消えない行動」を作らない。
2. **出荷**: `shipped: true` は次の三条件がすべて立ったときだけ書く。
   (1) リリース tag が存在する。(2) `git merge-base --is-ancestor
   <修正 commit> <tag>` が真である（修正が tag の祖先に居る）。(3) 照合の
   記録を `ship_ref` に残す。機械が検めるのは記録の形（`shipped: true` には
   `ship_ref`）までとし、三条件の実施は書き手の手順に置く。
3. **想定の観測**: 機械の観測器（`observe_assumptions.py`）が登記簿の
   `observation_history` へ**追記だけ**を行う（日付は `--today` で受け、
   実時計を読まない）。`verified_by` は独立の評価セッションの実施だけが
   埋める。機械の観測は観測であって検証ではない。

## 帰結

- validate に `_validate_closure_vocabulary` が入り、裁定者の無い受容・参照の
  無い出荷・`fixed` と受容の両立を赤にする。実台帳（INC-017/026 の受容）は
  この門を通ることを実測で確かめた。
- `seed_facts` が `cost_accepted` の事象を種から外す。
- 登記簿の検査（ADR-126 の実装）は `observation_history` と `verified_by` の形
  （null か文字列）を受け入れ、履歴の各項に日付・状態語彙・観測者を要す。
- **語彙は保証を強くしない。** 出荷の三条件は「届いた」ことを言うのであって
  「効いている」ことを言わない —— 複製の稼働は体系から観測できない
  （NONGOAL-001 第14項）。
