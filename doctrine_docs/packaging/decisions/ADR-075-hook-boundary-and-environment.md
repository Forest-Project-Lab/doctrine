# フック境界は沈黙して開かない — 読み手・書き出し・経路解決・配布の四点を実行環境に対して堅くする

## 背景

全件監査・code-audit・リンタ・投影ドリフト・リリース整合のすべてが緑で、1028 件の
試験が通る状態で、外部の多面レビューが実行環境との境界に欠陥を見つけた。共通するのは
「主経路の外」であり、いずれも門が緑のまま素通りしていた。実測で確かめたものだけを挙げる。

**読み手**: 共有の `_frontmatter.parse_file` は種別を検めずに `open` する。統治木に
`.md` という名の名前付きパイプが一つあるだけで、PreToolUse のガードと全件監査が
書き手を待って永久に戻らなかった（実測 rc=124）。種別の検査は走査層 `_tracescan` に
だけ在り、共有の読み手に無かった。

**書き出し**: 拒否の JSON は `ensure_ascii=False` で裸で書いていた。`PYTHONIOENCODING` が
非 UTF-8 の環境では `UnicodeEncodeError` で exit 1 になり、拒否が丸ごと消える。公式の
約束は「判定が読まれるのは exit 0 のときだけ、それ以外の非ゼロは非ブロッキングの誤り」
なので、これはそのまま fail-open である。入力側も同じで、日本語を含む payload の
読み取りが失敗すると payload が空 dict に化け、ガードが判定を持たないまま allow へ倒れた。

**per-turn の走査**: リンタの ICD 依存検査が、`depends_on` を持つ文書を編集するたび
依存グラフを丸ごと組んでいた。木 8000 文書でリンタ 0.53 秒（`depends_on` 無しなら
0.14 秒で平坦）の O(N)。NONGOAL 第5項と仕様 §4.2 の「per-turn は編集された一文書
だけを点検する」に正面から反する。これを検出するはずの受入門（ADR-047）は、合成文書に
`depends_on` を持たせておらず、守るべき経路を一度も通っていなかった。加えて、その門が
測っていた対象ファイルは実在しなかった（3 桁で生成し 4 桁で指していた）。

**経路解決**: `CLAUDE_PROJECT_DIR` が無く、かつセッションの作業ディレクトリが部分
ディレクトリのとき、統治木が見つからず契約の注入が 627 文字から 99 文字へ縮み、
DECIDED の中身を失ったまま黙って続いた。`walkup_docs_root` は既に在ったのに、
cwd 起点の解決だけが親をたどらない `locate_docs_root` のままだった。公式には
`CLAUDE_PLUGIN_ROOT` が SessionStart・UserPromptSubmit・Stop で注入されない不具合が
複数報告されており、環境変数の欠落を前提に置く必要がある。

**配布**: marketplace の `source` がディレクトリのとき、配布は git archive ではなく
作業木の複製である。`plugin/.gitignore` は複製を止めない。実際に導入実体
（`~/.claude/plugins/cache/forest-project-lab/doctrine/0.7.0`）へ、別ワークスペース
時代の監査要約（`root` が `/workspaces/llm-docs-governance` を指す）と開発機の
セッション印、`__pycache__` が複製されていた。さらに同梱の試験がリポジトリ直下の
`scripts/` と `doctrine_docs/` を素で読むため、導入先で `run_tests.py` が
1 failure / 4 error で落ちた。公式文書は「導入したプラグインは自分のディレクトリの
外を参照できない」と明記している。

**縮小構成**: `hooks.level2.json` が UserPromptSubmit・Stop・PreCompact を落として
いた。ADR-030 決定(2)は生存性(R11)と捕捉(R12)を段差に依らず動かすと定め、SPEC-019 が
定める縮小差分は SessionEnd と PostToolUse の二本だけである。ADR-028 で三イベントを
足したときの取り残しで、既存の試験が「落とすもの」しか検めていなかったため鳴らなかった。

## 却下した選択肢

- **入力を信用し、環境を前提にする**: 名前付きパイプも非 UTF-8 の locale も
  「起きない前提」で置く。予防の層が沈黙で開くことを許すのは、体系が唯一持つ
  予防の価値を捨てることに等しい。R11「沈黙する故障を禁じる」に反する。
- **per-turn のドメイン解決をやめ、ICD 依存の検査をリンタから外す**: 事後検出が
  一段薄くなる。ドメインは置き場所そのものが持つ（§3.7）ので、読まずに解ける。
  検査を捨てる必要はない。
- **配布物の衛生を `.gitignore` に委ねる**: ディレクトリ配布では効かないことが
  実測で分かっている。宣言と実体が食い違ったまま残る。
- **実行時状態を `${CLAUDE_PLUGIN_DATA}` へ移す**: 版をまたいで残る正しい置き場だが、
  プロジェクトをまたいで共有されるため、別プロジェクトのセッション印が混ざる。
  ADR-037 が監査要約について選んだプロジェクトスコープと揃える方が一貫する。

## 決定

五つを定める。

1. **共有の読み手は種別の門を通す**。`_frontmatter.ensure_regular` / `read_text` を
   置き、通常ファイルでなければ開かずに `OSError` を送出する。統治対象を読む経路は
   すべてここを通す（リンタの `--batch`・体系外 .md・辞書・コード層・分類の記録・
   段の目印）。呼び手はすべて `OSError` を捕捉済みで、非通常ファイルは黙って飛ばされる。

2. **フック境界の入出力を共有コア `_hookio` に一本化する**。三つの標準ストリームを
   UTF-8(文字符号化の方式)へ張り替え、書けなければ ASCII(英数字だけの符号化)へ退避する。それでも書けず、かつ阻止できる
   事象（PreToolUse）なら exit 2（stderr が拒否理由になる）へ倒す。書けない拒否を
   exit 0 で返さない。

3. **per-turn は兄弟文書を読まない**。依存先のドメインは置き場所の名前だけから解く
   （`<docs_root>/<domain>/` と、id がファイル名の接頭辞であること）。解けなければ
   従来どおり「未検証」の助言へ落とす。受入門は「開いた統治文書の件数が編集された一件
   だけ」を数えて凍結する。時間の門は機械の速さに隠されるため、構造で凍結する。

4. **統治木の解決は親をたどる**。cwd 起点の解決を `walkup_docs_root` に揃え、
   環境変数が欠けても部分ディレクトリから統治木へ届くようにする。

5. **実行時の状態は配布物の中に置かない**。セッション印の書き先を
   `${CLAUDE_PROJECT_DIR}/.claude/.cache` に限り、`${CLAUDE_PLUGIN_ROOT}/.cache` は
   後方互換の読み口としてだけ残す（ADR-037 が監査要約に対して下した判断を、印にも
   広げる）。同梱の試験は配布物の外を素で読まず、`_util.require_repo_root` を通して
   導入先では skip する。配布物の衛生はリリースの門が検める。

縮小構成のイベント集合は「全構成 −{SessionEnd}」と定め、試験で凍結する。

## 帰結

- 予防の層が、名前付きパイプ・非 UTF-8 の locale・シンボリックリンク・`cd` を挟んだ
  削除・整形の揺れに対して沈黙で開かなくなる。
- per-turn の費用が木の規模に依らなくなる（実測 8000 文書で 0.53 秒 → 0.11 秒）。
- 導入先で `run_tests.py` が通る。配布物に他所のデータが混ざらなくなる。
- 手で配線した Level 2 の導入先で R11/R12 が動く。
- 受入の門が、守るべき経路を実際に通る。旧実装に対して落ちることを確かめてある。

## 保証限界

- 予防: 上に挙げた経路を実行前に拒否する。exit 2 が阻止として尊重されるかは
  実行環境の仕様であり、ここでは測れない。
- 検出: 配布物の衛生はリリースの門が、追跡の残高は監査が挙げる。
- 委ねる: `CLAUDE_PLUGIN_ROOT` が注入されない不具合そのものは上流の実装に属する。
  体系は「無くても統治木へ届く」ところまでを担い、変数の存在は前提にしない。
