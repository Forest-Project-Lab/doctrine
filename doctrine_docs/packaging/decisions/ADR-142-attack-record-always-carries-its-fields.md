# 故障注入の記録は generated_at・findings・residual_risks・故障族を常に持つ

## 背景

故障注入の記録（`mutations-*.json`）の欄は、組み立てのたびに手で選ばれていた。
2026-08-06 の記録は findings 4 件と residual_risks 4 件を持つ。翌 2026-08-07 の
記録は injections だけで、どちらの欄も無い。

これは書式の揺れでは済まない。失敗仮説の創出の種（`discover.seed_facts`）は
`mutations-*.json` の residual_risks を読んで次の攻めどころの出発点にする。欄の無い
記録は「残余リスクが無かった」と同じ読まれ方をする —— **直近の攻撃の残余リスクが、
次の失敗仮説の種から黙って消えた**（実測）。残余リスクは攻撃のたびに消えるもの
ではない。「評価器も攻撃者も同系 model である」といったリスクは、書かれなかった
回にも立ちつづけている。

同族の欠けは前にも測られている。generated_at を持たない記録は自分の鮮度を
言えず、読む側だけ精密にしても比べられない（INC-023）。また INC-003 の事故分析は
「台帳の項に故障族ラベルを必須で持たせる」ことを推奨（#1）していたが、記録は
評価の実行基盤の失敗を note の自由文でしか持たず、故障の族を後から集計
できなかった。

## 却下した選択肢

- **既に書かれた記録を遡って直す**: 証拠の遡及編集は所有者判断のまま
  （INC-023 が残した扱いと同じ）。前方だけを機構で塞ぐ。
- **運転手順に「残余リスクを書き忘れない」と足す**: 手順は書き忘れを防がない。
  実測の欠落がその証拠である。欄はコードが持つ。
- **読む側（discover）が、欄の無い記録を直前の記録から補う**: 補完は「どの記録が
  何を主張したか」を壊す。書く側が常に完全な記録を書く。
- **全注入で安全側が成立したとき findings の欄を省く**: 空欄は「無かった」と
  読まれる。空配列が正直な記録である。

## 決定

1. 記録の組み立ては純関数 `build_document` に一本化する（評価の実行基盤を
   呼ばない・実時計を読まない・決定論試験の対象）。
2. 記録は**常に** generated_at・findings・residual_risks を持つ。findings は
   機械導出とする —— 安全側が成立しなかった注入一件が一件になり
   （id・summary・severity）、安全側の破れだけを high とする。全注入で安全側が
   成立したときも空**配列**として書く。
3. residual_risks は土台（`RESIDUAL_RISKS`。2026-08-06 の記録の 4 件を転記した
   定数）を必ず含み、安全側の成立を測れなかった注入（観測不能・前提欠如）の
   分を足す。土台を消すには、この定数を消す決定が要る。
4. 評価の実行基盤・分類の失敗が在った注入には**故障族ラベル**（fault_family）が
   付く（INC-003 推奨#1）。`sdk_lane.classify_error` と同じ手掛かりを族の名へ
   写す。状態は「どれだけ観測できたか」を言い、族は「何が壊れたか」を言う ——
   別の軸である。どの手掛かりにも当たらないものは "unclassified" として残す
   （分類不能を無ラベルと混ぜない）。
5. **前方のみ。**既存の mutations-2026-08-04／-06／-07 は遡って直さない。

## 帰結

- 以後の記録から残余リスクが黙って消える形は機構で塞がれた。ただし 2026-08-07 の
  記録は欄を持たないままなので、次の攻撃が走るまで失敗仮説の種には 2026-08-06 の
  残余リスクだけが載る。
- findings の severity は状態からの機械写像であって、重大度の意味判断ではない。
  観測不能・前提欠如の注入は「破れていない」ではないので、落とさず medium で
  残る。
- 故障族の軸は記録に載っただけである。族ごとの集計・閾値の経路（INC-003 推奨#3）
  はまだ無い。
