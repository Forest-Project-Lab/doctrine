# フック境界と実行環境の堅牢化 — 影響の列挙

ADR-075 を受けて更新する文書・実装・試験を、依存からたどって列挙する。

## 仕様（SPEC）

| 文書 | 何が変わるか |
|---|---|
| SPEC-002 | 解析器の契約に「通常ファイルでなければ開かない」と「誤りの消費者」を足す |
| SPEC-003 | 三ガードに、生の全文への適用・realpath・`cd` 追跡・構文修復の carve-out・削除の対称を足す |
| SPEC-007 | リンタに `FRONTMATTER_SYNTAX`・走査から外す範囲・読まないドメイン解決を足す |
| SPEC-011 | 監査の id 走査の境界と設定の型検査を足す |
| SPEC-013 | パックの上限の数え方と、現行でない依存を同梱しないことを足す |
| SPEC-019 | 縮小構成のイベント集合と、フック境界の共有コアを足す |
| SPEC-020 | 配布物の衛生（実行時の状態を含めない）を足す |
| SPEC-027 | リリースの門に配布物の衛生の検査を足す |

## 実装（IMPL）

- IMPL-002（解析器）: 種別の門と共有の読み手。
- IMPL-003（ガード）: 生の全文への適用、経路の解決、Bash の走査。
- IMPL-007（リンタ）: 新しい検査と走査から外す範囲。
- IMPL-011（監査）: id の境界、設定の型。
- IMPL-013（パック）: 上限の数え方。
- IMPL-019（配線）: 縮小構成のイベント集合。

## 試験（TEST）

- TEST-002・TEST-003・TEST-007・TEST-011・TEST-013・TEST-019・TEST-020・TEST-027 の
  受入に、上の各項を足す。
- 性能の受入（ADR-047）は、測る対象を実在させ、`depends_on` を持たせ、
  「開いた統治文書の件数」で凍結する形へ置き換える。

## 横断の正本

- DECIDED-001: フック境界の事実を一件足す。
- WATCH-001: 「per-turn で兄弟文書を読む経路を戻さない」「実行時の状態を配布物へ
  置かない」を足す。
- 用語辞書: 新しい承認語は足さない（既存の語で書ける）。

## 体系外

- `spec/doctrine.ja.md`（DOCTRINE-001）: §4.3 のスクリプト表に共有コアを足し、
  `updated` を実際の更新に合わせる。EXT-003 の検査を `exists` から `hash` へ上げる。
- 公開ビュー3件（README・plugin/README・CONTRIBUTING）: 刻印の `as-of` を打ち直す。
- CHANGELOG: 版付き節を積む。

## 影響しないもの

- 文書型登録簿・status 統制語彙・必須キー・依存規則・置き場所は変えない。
- 技能は 7 個のまま。Hook のイベントは全構成 7 種のまま。
- 注入とパックの二つの上限のキーは変えない。
