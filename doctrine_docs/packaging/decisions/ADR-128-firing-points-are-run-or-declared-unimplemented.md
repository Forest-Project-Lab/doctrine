# 宣言された評価の発火点は、走らせ手を持つか、未実装と明記されるかのどちらかとする

## 背景

ADR-120 は状態機械の各状態を「名指しできる」か「名指しできないと明記される」かの
どちらかに属させた。ADR-124 は台帳に置く成果物の種別に同じ二分を課した。

どちらの検出も**「在る物」を入力に走る**。走らせ手を持たない段は成果物を生まないので、
台帳に未宣言のファイルも欠落の記録も現れず、種別が無いので不在を表す語彙すら無い。
状態の側では遷移が宣言どおり定義されているため矛盾も出ない。二つの検出器の対象範囲の
外に、**宣言された発火点と実行器の対応**という三面目が残っていた。

実測すると、jerg レーンが宣言する三つの発火点のうち走らせ手が在るのは
`MAP_COVERAGE` だけだった。`FORMALIZE` と `VERIFY` は `schemas.py` にスキーマの殻が
残るだけで、`prompts` の組み立て関数も実行器も台帳の種別も無い。状態機械は
`FIX_APPLIED → VERIFY → ATTACK_EVALUATOR` の遷移を持つのに踏む先の実体が無く、
**修正の正しさを別セッションが確かめる段を一度も経ないまま**、成果が台帳へ記録され
所有者へ渡っていた（事象 INC-021）。

逆向きの穴もあった。`INGEST_NORMS` は実行器が実 opus セッションを走らせるのに、
どのレーンの `fires_on` にも現れていなかった。宣言と実装は**両方向**に離れうる。

## 却下した選択肢

- **未実装の段を `fires_on` から黙って外す**: 乖離は消えるが、独立した検証を経ていない
  という事実も一緒に消える。宣言を実装へ合わせるのは、実装が正しいと決めたときだけ
  してよい。ここではまだ決めていない。
- **未実装の発火点を `next_actions` に挙げる**: 是正は事象 INC-021 が持っており、
  その推奨が `APPLY_FINDINGS` に載る。二重に鳴らすと、どちらを踏んでも消えない行動に
  なる（ADR-126 で想定について同じ判断をした）。
- **走らせ手の有無だけを見る**: 実行器が在っても、組み立て関数か台帳の種別が欠けて
  いれば成果は正本へ届かない。三点そろって初めて「走る」と言える。
- **一段ごとの受入試験を足す**: ADR-124 が同じ理由で却下した。次に発火点が増えた
  ときには守られない。

## 決定

1. 発火点ごとに、**走らせ手の三点**（実行器・prompt 組み立て関数・台帳の成果物種別）
   を持つか、**未実装である旨と理由**を持つかの、ちょうど一方に属させる。正本は
   `orchestrator.py` の `FIRING_POINTS`。
2. 宣言した名は実在へ解決できなければならない —— 実行器は `harness/` のファイル、
   組み立て関数は `prompts` の呼べる属性、成果物種別は `LEDGER_KINDS` の鍵。
3. 表の鍵集合は、すべてのレーンの `fires_on` の合併と一致する。**両方向の差集合が
   空**であること —— 宣言だけの段も、宣言の無い実行器も許さない。
4. 未実装の発火点は `next_actions` に挙げないが、`status` が必ず数えて出し、
   どの事象が是正を持つかを添える。

## 帰結

- 判定は `validate()` に入り、レーンの決定論試験が凍結する。発火点を足して走らせ手を
  足し忘れた差分は merge 前に赤で止まる。三度目の同じ二分である（状態・台帳の成果物・
  発火点）。
- 現状は `FORMALIZE` と `VERIFY` の二つが**未実装と明記された**状態で緑になる。
  緑は「実装されている」ではなく「**実装されていないことが宣言されている**」の意味で
  あり、`status` の `firing_points.unimplemented` に理由つきで出続ける。
- `INGEST_NORMS` を三つの冊子レーンの `fires_on` へ加えた。実装が在るのに宣言が
  無かった側の是正である。
- **走らせ手を作っても独立した検証にはならない。**得られるのはセッションの独立
  （一回限り・設定の読み込みなし・構造化された成果物だけ）までである。独立した組織に
  よる検証は NONGOAL-001 第17項が採らないと決めており、評価役はすべて同系 model で
  あるため、共通原因故障は残余リスクとして残る。
