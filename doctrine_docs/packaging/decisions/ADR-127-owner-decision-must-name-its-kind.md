# 所有者判断は六類型のどれかを名指してはじめて成立し、評価者の申告は既定にしない

## 背景

ADR-125 は事故分析の推奨に処遇を持たせ、所有者判断を要すると分析が印した推奨を
レーンの未着手に混ぜないと決めた。印は分析が返す `owner_decision_required` である。
運用してみると 45 件がその棚に積まれ、誰も読まないまま反復をまたいだ。

棚の中身を読むと、45 件のうち 21 件は分析自身の分類（`kind`）が「所有者判断」ですら
なかった（機構の変更 17・文書化 3・調査の継続 1）。台帳の中で申告と分類が食い違って
いた。

原因は分析の側にはない。**分析の入力に統治木が入っていない。**
`prompts.build_cast_analysis_prompt` が渡すのは事象の記録・統制構造・検証原則カタログの
三つだけで、確定方針も、やらないことも、退行監視も、決定の一件も渡らない。何も決まって
いない場所から見れば、すべてが未決に見える。評価者が書く「所有者が決めよ」は、所有者の
権限についての判定ではなく、**評価者の視野の申告**である。

正本はその申告を権限の判定として読み替えていた。検証できない申告を信じる形であり、
この体系が ADR-050 と NONGOAL-001 第9・14・16項で三度「やらない」と決めた形の四度目
である（三度目は INC-013 の捏造事象）。

実地の確かめとして、棚から三件を統治木に当てた。三件とも消えた —— 一件は
NONGOAL-001 第14項・DECIDED-001 事実7・ADR-122 が既に決めており、一件は ADR-122 が
可否を決めており、一件は「台帳が版管理下にあるか」を実際に調べれば前件が成り立たな
かった。判断待ちではなく、材料が届いていない未処理の山だった。

## 却下した選択肢

- **棚を人が定期的に読む**: 45 件を六反復にわたって誰も読まなかった。記録は在り、
  伝達が無かった（ADR-124 と同じ診断）。
- **`owner_decision_required` を分析に返させない**: 申告そのものは有用な信号である。
  評価者がどこで視野の外に出たかを示す。消すと、視野の狭さが観測できなくなる。
- **レーンが類型を機械で判定して自動的に振り分ける**: 判定には統治木の全体像が要り、
  それを機械の照合で行うのは意味の判断になる（NONGOAL-001 第1項と同じ理由）。
  レーンが決めるのは「類型が名指されているか」までとする。
- **六類型をレーンが増やす**: 自分の自律の境界を自分で広げることになる。写すだけとする。

## 決定

1. 所有者判断の類型は六つとする —— 互換性を壊す変更・配布境界や保証範囲の変更・
   復旧不能な削除・外部費用や credential・評価 model 最低線の引き下げ・配布物の
   版番号の変更とリリース。正本は `orchestrator.py` の `OWNER_DECISION_KINDS` で、
   運転手順が持つ表をそのまま写す。レーンはこの表を増やさない。
2. 処遇が `owner` になるのは、処遇の行が明示的にそう書き、かつ**類型のどれかを
   名指した**ときだけとする。名指せない申告は所有者判断ではない。
3. 書かれた処遇が無い推奨の既定は、分析が何を印していようと `pending`（未着手）と
   する。評価者の申告を既定にしない。
4. 申告の件数と、類型の照合を通って成立した件数は、`status` が別々に出す。
   一語に二つの意味を持たせない。

## 帰結

- 棚に既定で落ちていた 45 件が未着手の山へ戻る（`pending` 108 → 153）。件数は増える
  が、それが正直な数である。減ったように見えていたのは、見ていない山を裁いた山と
  同じ顔で数えていたからである。
- 所有者へ渡すときは類型を名指す義務が生まれる。名指せないなら、それはレーンが
  統治木を当てて自分で裁く仕事である。
- **本決定は申告の読み替えを止めるだけで、評価者の視野そのものは狭いままである。**
  既決を評価者へ渡す設計は別の決定になる。独立性の規律（ADR-115）は「実装者の会話・
  弁明を渡さない」であって「木の既決を渡さない」ではないが、渡せば「既決に寄りかかり
  すぎて既決自体の誤りを指摘できなくなる」共通原因故障が新たに立つ。事象 INC-020 の
  分析を待つ。
