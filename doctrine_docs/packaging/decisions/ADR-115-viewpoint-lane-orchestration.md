# 規範3冊の評価は観点別レーンに分け、発火は決定論の状態機械が制御する

## 背景

保証キャンペーンの規範は三冊——JERG（宇宙機関のソフトウェア開発標準群。対象は
2-610C）・STPA（システム理論に基づく危険要因分析）・CAST（システム理論に基づく
事故分析）——で、合計およそ 28 万字ある。一つの評価セッションに三冊を同時に
読ませることはできず、読ませたとしても観点が混ざって薄まる。冊子ごとに役割が
違う（検証計画と証拠／事故候補の創出／失敗後の体系更新）ので、発火すべき時機も
違う。評価をいつ・何に対して走らせるかを LLM 自身の判断に委ねると、発火の欠落と
都合のよい停止が記録に残らない。

## 却下した選択肢

- 三冊を一つの評価セッションへ同時に渡す: 文脈量の点で不可能であり、観点も混ざる。
- 冊子ごとの評価を主セッションの判断で随時起動する: 発火の欠落を検出できない。
- 観点レーンを配布 Skill として実装する: 技能7個の固定（DECIDED-001 事実8）に反する。

## 決定

規範評価は冊子と一対一の観点レーン（stpa=創出・jerg=検証計画と証拠・cast=失敗後
更新）に分け、どの状態で・どのレーンが・何を読むかの正本と遷移を
`assurance/harness/orchestrator.py` の決定論コードに置く。

## 帰結

- 状態は INGEST_NORMS（規範取り込み）→ MAP_COVERAGE（網羅の対応付け）→
  DISCOVER（創出）→ CHALLENGE（独立批判）→ FORMALIZE（定式化）→
  REPRODUCE_RED（修正前再現）→ FIX（最小修正）→ VERIFY（独立検証）→
  ATTACK_EVALUATOR（評価機構への故障注入）→ RECORD（記録）→ CURATE（整理）を
  巡り、FAIL（不適合）と事象はどの状態からでも CAST_ANALYSIS（事故分析）へ入る。
  再現不能は実装へ進まず記録へ落ちる。
- 冊子の取り込み（検証原則カタログの抽出）は jerg → stpa → cast の順を既定とする。
  引用はチャンク本文との機械照合で検め、実在しない引用の原則は却下する。
- カタログの各原則は網羅台帳で五値（実装・試験・証拠あり／対応計画あり／非該当で
  理由あり／UNKNOWN（判定不能）／UNASSESSED（前提欠如で未評価））のどれかに
  割り当てる。「観点を思いつかない」を網羅の証拠にしない。
- 正本の自己整合（レーンが指す冊子・状態・model 役割）は決定論試験が凍結する。
- 事象は `assurance/ledger/incidents.json` に積み、修正済みでも「なぜ既存の保証が
  見逃したか」の cast 分析が済むまで閉じない。
