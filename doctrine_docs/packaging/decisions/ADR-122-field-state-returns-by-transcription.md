# 運用中の版と生存状態は供給側へ戻すが、通信ではなく承認を経た転記で戻す

## 背景

導入された複製が正本より古いまま動き続けても、供給側からは見えない。実際に三世代の
遅れが二セッション気づかれずに続き、その間のフックはすべて旧世代のコードで走っていた。
配る側は「配った」ことしか知らず、現地で何が動いているかを知る手立てを持たない。

規範はこの一方通行を欠陥として扱う。CAST（システム理論に基づく事故分析）は「製造者は
当初の安全分析の基礎とした運用環境の想定を顧客に伝達し、**運用側は運用中の性能を
製造者へフィードバックする**」と定め、供給側が安全性に影響する変更を利用者へ明確に
警告すべきことも求める。STPA（システム理論に基づく危険要因分析）は、運用中の先行指標を
「当初の設計前提がいつ崩れるのかを損失の前に特定する」ために置けと言う。

一方で本体系は、通信しないこと（DECIDED-001 事実7）と、リポジトリを越えた統治を
しないこと（NONGOAL-001）を確定させている。規範が求める経路と、体系が引き受けない
範囲が正面から当たる。

## 却下した選択肢

- **遠隔測定（実行時に供給側へ送る）**: 規範の求める経路を最短で満たすが、通信しない
  という確定事実を破り、利用者の環境の情報を本人の関与なく持ち出す。
- **経路を作らない**: 規範が名指しする欠陥をそのまま残す。版の遅れは現に起きており、
  「見えないままでよい」とは言えない。
- **供給側から現地を推定する**: マニフェストと配布物からは、現地で何が動いているかを
  決められない。推定を事実として扱うと、INC-005 と同じ「知っているつもり」を作る。

## 決定

運用中の版と生存状態は供給側へ戻す。ただし**通信を伴わず、利用者の承認を経た転記
としてだけ**戻す。フックは現地の状態を利用者のプロジェクトの中（`.claude/.cache`）に
残し、利用者が求めたときに貼り付けられる形で示す。送信は体系が行わない。

## 帰結

- 現地の状態として残すのは、実行中の版・正本として宣言された版・監査の走った印と
  書けたかの印・鼓動が出した警告の種別に限る。統治対象の内容（文書の本文・場所）は
  入れない（ADR-074 のエラージャーナルと同じ線引き）。
- 転記は許可制とする。下書きを利用者へ全文見せ、承認を得てから利用者自身の手元で
  投稿する（ADR-074 で確立した手順をそのまま使う）。**体系は送らない。**
- したがって供給側が得るのは、利用者が渡すと決めた分だけである。網羅は保証しない。
  これは規範の求める経路を、確定事実の内側で満たせる範囲まで縮めた結果であり、
  縮めたことを非目標として明記する。
- 先行指標のうち、導入複製の側でしか観測できないものは版に依存する。版が遅れれば
  指標も遅れる（古びの検出器が古びる。事象 INC-005）。この残余リスクは消えない。
