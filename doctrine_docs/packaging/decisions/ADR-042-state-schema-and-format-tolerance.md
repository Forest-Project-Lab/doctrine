# 監査要約のスキーマは全読者が照合する・状態ファイルの書式は前方寛容とする

## 背景

状態ファイル（監査要約 `last-audit.json`、`.md-intake`、`.governance-state`、`.docs-level`）に版の識別が無く、更新時の移行の道筋も定めていなかった（#77）。具体の食い違いとして、監査要約の読者が二人で判定を違えていた。注入（`inject-contract`）は `schema` が `docs-audit/1` でなければ要約を捨てるのに、生存性（`gov-heartbeat`）は `schema` を見ずに `today` を読んでいた。将来スキーマを上げた場合や別ツールが書いた要約で、片方は捨て、もう片方は誤って読む。

## 却下した選択肢

- **全状態ファイルに `version` 行をいま足し、移行コードを書く**: まだ壊す変更をしていないのに先回りで版を刻むのは、要求に紐づかない記述（NONGOAL 第1項の精神、R8）。版は壊す変更をするときに足す。
- **スキーマ照合をしない（現状の生存性）**: 形が違えば `today` の解釈も誤りうる。読者間で判定がずれるのは、同じ入力を二つの道具が別々に裁く欠陥類型。

## 決定

1. **スキーマ照合を全読者で揃える**: `gov-heartbeat` も監査要約の `schema` が `docs-audit/1` でなければ読まない（注入と同じ）。読まない＝「前回監査なし」へ安全側に倒す。未知のスキーマ（将来の `docs-audit/2` や別ツールが書いたもの）は、誤って読むより無視する。
2. **状態ファイルの書式は前方寛容とする**: `.md-intake`・`.governance-state`・`.docs-level` は `キー: 値`／一行一項目の平文で、読者は知らないキー・行を無視する（不明は読み捨て、壊滅しない）。版の識別行は、書式を壊す変更を実際にするときに足す（それまでは足さない）。移行が要る変更をする ADR が、そのとき版と移行を定める。
3. **辞書シードの退行警告は仕様どおり**: 同梱テンプレートの用語が増えたとき、運用正本がそれを取り込むまで `glossary_seed_drift` が warn を出し続けるのは意図どおり（drift＝運用正本がシードに追いついていない）。新しい語を運用正本へ併合すれば消える。これは更新の作業を促す設計であり、欠陥ではない。

## 帰結

- 監査要約の読者が同じ判定をする（読むか捨てるかが一致）。未知スキーマは全員が捨てる。
- 状態ファイルは、いまは版を持たず、壊す変更のときに版と移行を導入する。先回りの版付けをしない（最小性）。
- 手で配線するときのパス書き換えの手順は、`docs-system-init` の `references/fallback.md` に明記する（#75。`${CLAUDE_PLUGIN_ROOT}` を実際の場所に書き換えないと予防が黙って無効になる fail-open を防ぐ）。
