# サブエージェントへ注入しない理由を「届かない」から「呼び出し側が組む」へ置き換える

## 背景

`NONGOAL-001` 第11項は「サブエージェントへの契約注入はしない（**届かない**）」と書き、
その理由として次を挙げていた。

> ハーネスの子エージェントは SessionStart を通らず、注入の差し込み口が無い。無いものを
> 在ると書けば誤った安心を与える。**差し込み口が生まれた時点で再検討する。**

**その差し込み口は在る。** 現行の公式仕様には `SubagentStart` があり、`additionalContext`
を運ぶ事象の一つとして定義されている（`SessionStart` / `Setup` / `SubagentStart` は
「会話の冒頭、最初のプロンプトの前」に文脈を運ぶ群である。2026-08-02 確認）。

つまり非目標が自ら書いた再検討の条件が満たされている。理由が偽になった非目標を、
そのまま置くことはできない。非目標は「あえて引き受けない範囲」の正本であり、
「できないこと」を書く場所ではない。

## 却下した選択肢

**第11項をそのまま残す。** 理由が偽である。読んだ者は「実行環境の制約でできない」と
受け取るが、実際には選べる。誤った制約の共有は、誤った安心と同じだけ害がある。

**第11項を撤回し、直ちに `SubagentStart` を配線する。** 配線それ自体は筋が通るが、
本 ADR で決めるべきは「非目標の理由をどうするか」である。何を配線するかは、注入する
文脈の中身・上限・サニタイズを含む別の設計判断であり、一つの ADR に混ぜない。

**「届かない」を「届くが使わない」に書き換えるだけで済ませる。** 理由が空になる。
なぜ使わないのかを書かなければ、次に誰かが同じ問いを立て直す。

## 決定

**第11項の理由を差し替える。範囲としての非目標は保つが、根拠を実行環境の制約から
設計の選択へ移す。**

1. 「（届かない）」を外す。`SubagentStart` は在り、文脈を運ぶ。
2. 理由を書き直す —— **子へ渡す文脈は呼び出し側が組む**（技能 `llm-context-pack` が
   課題ごとの最少の文脈を組む）。親の契約をそのまま子へ流すと、子は自分の課題に要らない
   文脈を大量に受け取り、最少の文脈という方針と正面から当たる。子に要るのは課題ごとの
   縮約であって、親の復唱ではない。
3. `SubagentStart` の配線は本 ADR では決めない。決めるなら別の ADR で、注入する中身・
   上限・サニタイズ（注入境界の規範）まで含めて裁く。
4. 「ガードは子のツール呼び出しにも効くが、それは拒否の面であって理解の面ではない」は
   そのまま残す。これは事実として正しい。

## 帰結

- 非目標が、実行環境の仕様に照らして真になる。読んだ者が誤った制約を受け取らない。
- 再検討の条件（差し込み口の有無）が、実際には満たされていたことが記録に残る。
  `EXT-001` の `review_by` を待たず、外部レビューが先に反証を持ってきた形である。
- 保証限界: 子エージェントが契約を持たずにツールを呼ぶ状態は変わらない。変わったのは
  その理由だけである。子の統治は依然としてガードの拒否の面に頼る。
- 次に問うべきこと: `SubagentStart` へ何を注入すべきか、注入しないままでよいか。
  本 ADR は問いを開いたままにする（課題ごとの縮約と重なるため、設計を詰めてから決める）。
