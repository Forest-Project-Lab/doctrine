# フック境界と実行環境の堅牢化 — 何を変えたか

ADR-075 の決定を実装へ落とした変更の記録である。なぜ決めたかは ADR-075 が持つ。

## 変更内容

部品ごとに次を変える（詳細は各節）。

### 共有コア

- `_frontmatter.ensure_regular` / `read_text` を新設。通常ファイルでなければ開かずに
  `OSError`。`parse_file` はこれを通る。統治対象を読む六つの経路（リンタの `--batch`・
  体系外 .md・辞書・コード層・分類の記録・段の目印）を同じ門へ寄せた。
- `_hookio` を新設。標準の入出力を UTF-8 へ張り替え、書き出しの失敗を ASCII へ退避し、
  PreToolUse で書けなければ exit 2 へ倒す。フックの入口 7 本がこれを通る。
- `_registry.is_outside_governance` を新設。根の案内と dot ディレクトリ配下という
  「統治の走査から外す範囲」を、監査とリンタで共有する。
- `_registry.is_archived_path` を新設。倉庫の判定を監査が独自に持っていたのをやめた。

### ガード

- 編集は生の全文へ当てる（再構成は最後の手段）。整形の揺れで判定が外れなくなった。
- 既存 ADR の carve-out に「フロントマターの構文修復」を足した。本文不変と
  「誤りが消えること」で機械的に見分ける。
- 包含の判定を `realpath` へ揃えた（リンク経由の倉庫改変を塞ぐ）。
- Bash 経路で `cd` を追い、`git` の大域オプション（`-C` ほか）を読み飛ばす。
  削除の動詞を含まない経路には何も言わない。
- 削除は対象の `status` を問わない（削除は状態に依らず死リンクを作る）。

### リンタ

- `FRONTMATTER_SYNTAX`（ERROR）を新設。解析器の誤りを表に出す。
- 依存先のドメインを置き場所の名前だけから解く。兄弟文書を読まない。
- 統治の走査から外す範囲を監査と共有する。
- 助言の描画を `sanitize_inline` に通す。
- SPEC の必須節を「同レベル以下の次の見出し」まで見る。
- 発火の印は PostToolUse のときだけ残す。

### 監査・パック・リリース

- 本文中の id の境界を `\b` から否定先読みへ。仮名・漢字が隣接する参照を拾う。
- 設定の値の型を検め、不正値は既定へ落とす。
- パックの上限は落とすたびに一意被覆を数え直し、勘定は実際に描画される形で行う。
  上限で覆えなくなった要求は uncovered へ戻す。
- 依存の閉包は現行でない文書の本文を同梱しない（たどるのは可）。
- `trace-index` が `trace_exempt` を読む（監査と同じ答えを返す）。
- リリースの門に配布物の衛生の検査を足した。

### 配線・配布・試験

- `hooks.level2.json` に UserPromptSubmit・Stop・PreCompact を戻した。
- 実行時の状態の書き先をプロジェクトスコープに限った。
- 作業木にバイトコードを残さない。
- 同梱の試験は配布物の外を素で読まない（`require_repo_root` を通す）。
- 受入の門を実効にした（`depends_on` を持たせ、実在する対象を測り、読んだ件数で凍結）。
- `run_tests.py` は 0 件を成功と読まない。

## 理由（要求元）

外部の多面レビュー（2026-07-28/29）。全件監査・code-audit・リンタ・投影ドリフト・
リリース整合のすべてが緑で 1028 件の試験が通る状態で、実行環境との境界に欠陥が見つかった。
共通するのは「主経路の外」であり、いずれも門が緑のまま素通りしていた（ADR-075 の背景）。

## 影響の初期見積

一巡。塞ぐ手立て自体は小さいが、実測での再現（名前付きパイプ・非 UTF-8 の符号化・
8000 文書での性能・部分ディレクトリからの解決・配布物の複製）に時間の大半が掛かる。
影響の列挙は IMPACT-006 が持つ。
