# 事象を閉じてよいのは、照合を通った統制欠陥と先行指標を持つ事故分析が揃ったときだけとする

## 背景

ADR-115 は「事象は CAST（システム理論に基づく事故分析）が済むまで閉じない」と
決めたが、「済んだ」が何を指すかを決めていなかった。定義が無ければ、体裁だけを
整えた分析でも閉じられる。実際に台帳へ積んだ5件のうち3件はすでに修正済みで、
修正を理由に閉じたくなる力が働く。加えて CAST は、統制構造——誰が・何を・どの
手掛かりを見て制御していたか——を先に置いてから欠陥を導く手順だが、その構造を
分析のたびに文章で組み直すと、要素の欠落が記録に残らないまま結論だけが変わる。
規範の出典も、文字列として書かせるだけでは実在を確かめられない。

## 却下した選択肢

- 「済んだ」を人の読みで判ずる: 判定が記録に残らず、急ぐときに緩む。
- 応答が構造の定義へ適合したことだけを条件にする: 形は満たすが中身が空でも通る。
  存在しない統制要素や憶測の出典を指した欠陥も通ってしまう。
- 統制構造を分析のたびにプロンプトへ手書きする: 要素の欠落と版ごとの揺れが
  記録に残らない。分析どうしを突き合わせることもできなくなる。

## 決定

事象の分析状態を done にしてよいのは、次の三つをすべて満たす分析が保存された
ときだけとし、判定は `assurance/harness/cast_analysis.py` の決定論コードが行う。

1. 応答がレーン側の再検証でも `CAST_ANALYSIS_SCHEMA` へ適合する。
2. 参照照合を通った統制欠陥が一つ以上残る（統制構造に実在する要素の識別子を指し、
   規範の出典がカタログに実在する鍵であること）。
3. 先行指標が一つ以上あり、どれも「どこで観測するか」と「何を異常とするか」を
   埋めている（CAST_DONE の前提条件）。

## 帰結

- 統制構造の正本は `assurance/harness/control_structure.py` に一度だけ置き、
  各要素は実在するファイルを指す。指す先が消えたら決定論試験が落ち、分析は
  UNASSESSED（前提欠如で未評価）へ倒れる。構造の古びを、分析の質ではなく
  ファイルの実在で検出する。
- 分析の入力は事象の構造化記録・統制構造・カタログ全件だけとする。実装者の
  会話・弁明・期待する結論を渡す口を作らない（ADR-115 の独立性）。規範は
  選り好みで絞らず全件を渡す（都合のよい出典だけを見た分析にしない）。
- 条件を満たさない分析は FAIL（走ったが不適合）として保存し、事象は未分析の
  ままとする。次の実行が同じ事象をもう一度引く。修正済みであることは閉じる
  理由にならない。
- 先行指標が導入複製の版に依存するかどうかを指標ごとに書く。版が遅れると
  検出器も遅れる故障（古びの検出器が古びる。事象 INC-005）を隠さない。
