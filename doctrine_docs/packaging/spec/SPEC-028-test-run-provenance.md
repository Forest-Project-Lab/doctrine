# 試験走行の証跡

試験走行が最後に刷る「判定の依り所」の書式を定める。**書式の正本はここ一箇所である**
（ADR-085）。

刷る目的は一つ —— 「試験が通った」という主張が、**どの環境の話なのかを読めるようにする**。
2026-08-02 に、同じ試験・同じ commit が手元で 1036 件すべて緑、CI で落ちた
（`core.fileMode=false` により git の索引の mode が 644）。そのとき主張は環境を持って
いなかった。JERG-2-610C の定義でいう「客観的証拠の提示」を伴っていなければ、それは検証では
なく検証戦略である。

## 入出力

### 入力

| 何 | 出所 |
|---|---|
| Python の版と実装 | `platform.python_version()`・`platform.python_implementation()` |
| 実行環境の種別 | `platform.system()`・`platform.release()` |
| プラグインの版 | `plugin/.claude-plugin/plugin.json` の `version` |
| 判定を変える設定 | `git config --get core.fileMode`（実測で判定を変えた） |
| 対象の commit | `git rev-parse HEAD` |
| 走行の結果 | 走者が数えた件数と PASS/FAIL |

### 投影

走行の末尾に、要約の直後へ次の順で刷る。一行一項目。

```text
PROVENANCE:
  python: <実装> <版>
  platform: <名> <版>
  plugin: <版>
  core.fileMode: <値>
  commit: <40桁 or （取れなかった）>
```

## 制約

1. **保存しない。** 走行のたびに作り、走行のログへ刷るだけとする（ADR-055。導出値を保存しない）。
2. **統治対象の内容を入れない。** 環境と版だけを刷り、パス・文書の内容・リポジトリの名前・
   作業ディレクトリは刷らない（ADR-074 の許可制と同じ形）。
3. 刷る項目は「いま判定を変えると分かっているもの」に限る。**網羅を主張しない。**
   次に驚かされる性質は、驚いてから足す。
4. 取得に失敗した項目は、走行を落とさない。`（取れなかった）` と刷って続ける。
   証跡の取得は試験の本務ではない。
5. 走行の合否は証跡に依らない。証跡が全て取れなくても、判定は変わらない。

## エラー時挙動

| 何が起きたか | どうするか |
|---|---|
| `git` が無い・リポジトリでない | `commit` と `core.fileMode` に `（取れなかった）` を刷る |
| `plugin.json` が読めない | `plugin` に `（取れなかった）` を刷る |
| 想定外の例外 | 証跡の節を飛ばし、要約と終了符号は保つ |

## 受入基準

1. 走行の末尾に `PROVENANCE:` の節が在り、**五つの項目**（`python`・`platform`・`plugin`・`core.fileMode`・`commit`）が上の順で並ぶ。走行の結果は既存の `SUMMARY`／`RESULT` の行が持つ。
2. `python`・`platform`・`plugin` が実際の値を持つ（`（取れなかった）` でない）。
3. `git` の無い場所で走らせても、走行が落ちず、該当項目が `（取れなかった）` になる。
4. 統治対象の内容（パス・作業ディレクトリ・リポジトリ名）が刷られない。
5. 証跡の取得が失敗しても、走行の合否と終了符号が変わらない。

## 覆わないもの

- **証跡の無い判定を機械が咎めること。** 監査はセッション終端に走り、試験の走行を見ていない。
  見ていないものを見ていると書かない（ADR-085 の保証限界）。
- **証跡が在れば内容が真であること。** 証跡は「この環境でこの版でこの判定が出た」以上を
  言わない。試験そのものが弱ければ、強い証跡が弱い主張を飾る。
- lens 側の証跡。あちらは自分の `SPEC-007` が持つ（二重定義しない）。

## 実装の指紋

- コード対応なし: 試験の入口（`plugin/run_tests.py`）は統治の追跡から外してある
  （`doctrine:exempt`。方法論の正本は ADR-047 と PROC-001。ADR-067）。本仕様の受入は
  `TEST-028` が走者の投影を直に検める。
