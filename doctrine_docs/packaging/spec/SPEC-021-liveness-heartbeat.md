# 統治ハートビート（監査の鮮度・定例の期限・外部アンカーの存在）

`gov-heartbeat.py`(UserPromptSubmit)と、注入(ICD-006)・監査(ICD-005)に足した生存性の検査の仕様である。ADR-028 が配線を、ADR-030 が段差非依存を定める `[R11]`。

## 入出力

- 入力: UserPromptSubmit のエンベロープ(session_id)。読むのは三つの小ファイルだけ — 前回監査の要約(ICD-005 の `docs-audit/1`。読み取りは共有コア `_auditcache.py` に一本化し、候補順・`schema` 照合・root 照合・世代の照合を注入と同じ規則で行う。ADR-053。条件を満たさない候補はそこで止まらず次の候補へ進む。前の世代の木の要約は世代の照合で捨て、「前回監査なし」へ倒す。ADR-042、#77)、`_system/.governance-state`(`キー: 値` の平文。`last_cadence_review` と `initialized` を読む。知らないキーは無視する)、`_system/.context-config.json`(`audit_stale_days` 既定 7、`cadence_review_days` 既定 30)。全木の走査はしない(毎会話走るため)。
- 返す値: 最も重い一件だけの助言(additionalContext)。重い順に、(1) 前回監査の要約なし(状態の記録がある体系のみ。使い始めの前は黙る)、(2) 監査の鮮度超過、(3) 定例の実施記録なし(要約か状態の記録がある体系のみ)・周期超過、(4) 移行キャンペーンの1件(未分類の体系外 .md の先頭1件を、統治率と三分類の選び方つきの自己完結文で促す。台帳は `.md-intake` の導出で持ち、二重の台帳を作らない。ADR-034)、(5) 紐づけキャンペーンの1件(ADR-065。移行キャンペーンが出す物を持たないときだけ順番が回る — 位相は文書の整理→紐づけの整理。要約の `spec_coverage.next_undeclared` が運ぶ未宣言の仕様一件を、三つの出口〔指紋の記録／コード対応なしの宣言／exempt〕つきの自己完結文で促す。id は登録簿の書式に一致するときだけ文面に載せる。停滞〔`stagnation_streak`≧3〕はその旨を添える)、(6) Level 昇格の一度きりの案内(ADR-066。Level 2 のまま全件監査の実績〔読める要約〕が確認できたときだけ、`.docs-level` への書き方を含む中立の案内を一度出し、案内済みの印〔鍵 `level_hint_shown`〕を残して以後は黙る。昇格するかは人の判断のまま)。同じセッションでは一度だけ出す(セッション別の印)。何も無ければ何も出さない。
- あわせて、注入(SPEC-012)は「前回監査なし」と鮮度超過を警告文で出し、監査(SPEC-011)は EXT アンカーの対象の存在を検査する(ADR-026)。
- 発火の印(ADR-062): 注入(SessionStart)・ガード(PreToolUse のときだけ)・リンタ(PostToolUse)は、起動のたびに `.claude/.cache/hook-stamps`(git の追跡外)へ「鍵: 時刻」を最善努力で残す。鼓動は毎回、印の対の食い違い — リンタの印があるのにガードの印が無い/60 秒超古い — を判じ、「拒否経路の疑い」を助言に足す。監査も同じ判定(`_auditcache.liveness_gap`。読み手をまたいで一つ)を `guard_liveness_gap`(advisory)として挙げる。印が無ければどちらも黙る(古い版からの更新直後は印が育つまで沈黙する — 前方寛容)。
- 版の印と切替の検出(ADR-066): 注入はセッション冒頭に、実行中の包みの版(`plugin.json` の version)を印(鍵 `hook_inject_version`)として刻む。鼓動は毎回、今の自分の版と冒頭の版を比べ(判定は `_auditcache.version_drift` に一度だけ)、食い違えば「版の切替 — 新しいセッションを開始する」を助言に足す。どちらかが読めなければ黙る。同じ版番号のままの差し替えは見分けない(既知の限界)。
- 版の遅れの検出(ADR-070): 鼓動は毎回、実行中の包みの版と、プロジェクト自身の `.claude-plugin/marketplace.json` が同名のプラグインに宣言する版を比べる(判定は `_auditcache.version_lag` に一度だけ。正本の版は、項目の `source` が指す先の `plugin.json` を優先し、読めなければ項目の `version` に退避する)。食い違えば「導入済みの複製が正本と食い違う — 更新して新しいセッションを開始する」を、更新の言い方まで含めて助言に足す。マニフェストが無い・読めない・同名の項目が無いときは黙る(この照合は、統治対象のリポジトリ自身がマーケットプレイスの正本である自己適用のときだけ成立する)。
- 導入直後の中立案内(ADR-041、#74): 監査要約が無くても、`.governance-state` に `initialized` の印が在れば、生存性・注入とも「導入直後。初回監査は SessionEnd に走る」という中立の案内にする(警告ではない)。`initialized` が無く要約も無い場合(停止の疑い)は従来どおり警告を出す。同様に、`initialized` と `last_cadence_review` を種蒔きするため、導入初日に定例催促を出さない(以後は周期でだけ促す)。

## 制約
- Level 2 の全件検査は CI が担い、初回監査前は警告でなく中立の案内を出す（ADR-046、#73）。

- 決定論: `--today` で基準日を固定できる。与えないときだけ壁時計に退避する(監査と同じ規約)。
- 段差の扱い(ADR-030 の精密化): 督促の機構そのものは全 Level で動くが、監査の死活(要約なし・鮮度超過)の検査は Level 3 以上でだけ立てる。Level 2 に SessionEnd の監査は無い(ADR-019)ため、そこでの「監査が動いていない」は誤報になる。定例と移行の督促は全 Level で出す。
- 統治木の無いプロジェクトでは黙る。決して例外を外へ出さず、終了コードは常に 0。
- 助言のみ。decision・permissionDecision を出さない。

## エラー時挙動

- 要約・状態・設定のどれかが読めない/壊れているときは、読めた範囲で判定する(読めない要約は「無い」と同じ)。
- セッションの印を書けないときは、重複覚悟で出す側に倒す(沈黙より重複が安全)。
- 想定外の例外は握りつぶして静かに終わる(会話を止めない)。

## 受入基準

- 新鮮な監査と期限内の定例では何も出ない。
- 監査の要約が古い/無い(状態の記録がある)とき、R11 の警告を一度だけ出す。
- リンタの印だけが進みガードの印が無い/古いとき、鼓動が「拒否経路の疑い」を告げ、監査が advisory で挙げる。印が無ければどちらも黙る。新鮮な対では黙る。
- マニフェストが正本として宣言する版と実行中の版が食い違うとき、鼓動が更新の言い方まで含めて告げる。マニフェストを持たない導入先と、版が一致するときは黙る。
- 定例の記録が無い/超過のとき、実行の言い方と記録先(`last_cadence_review`)まで含めて促す。
- 使い始めの前(要約も状態も無い)と統治木の外では黙る。
- 受入は TEST-021 が凍結する。
