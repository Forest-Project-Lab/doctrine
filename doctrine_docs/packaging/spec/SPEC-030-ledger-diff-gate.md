# 巨大な台帳 PR の門（ledger-diff-summary — 独立レビューか機械生成の差分要約）

`scripts/ledger-diff-summary.py` の仕様である。リポジトリ内の自己適用であり、配布する
プラグインの一部ではない（`release-check.py`（SPEC-027）・`consistency-check.py`
（SPEC-023）と同じ位置づけ）。標準ライブラリだけで動く。

## 背景

保証レーンの台帳（`assurance/ledger/**.json`）は一件が数百 KB になる。網羅の再判定を
一度回すと二万行が動く。2026-08-07〜10 の一括是正キャンペーンは、その規模の PR を
運転手順 §7.1 の常設許可で自律 merge しており、**誰も中身を見ていない merge** が
積み上がった。所有者の要求（2026-08-09）で門を置く。

## 入出力

```
ledger-diff-summary.py --diff-base <sha>                     要約を出す
ledger-diff-summary.py --diff-base <sha> --check \
    --pr-body-file <path> [--approved]                       義務を検める
```

終了コードは 0（適合）・1（違反）・2（使い方の誤り、または差分を取れない）。

## 判定

- 対象は `assurance/ledger/` 以下の `.json` **だけ**とする。他のファイルの差分は数えない。
- 台帳の差分（追加＋削除）が **200 行**を超えるものを「巨大」とする。一件の推奨を処遇する
  差分（数十行）は素通りし、再判定や一括トリアージだけが掛かる位置に置く。
- 巨大な差分を持つ PR は、次のどちらかを要する。
  1. **作成者以外の承認**（独立レビュー）
  2. **機械生成の差分要約**が PR 本文に貼られていること
- 2 の成立は、本スクリプトが計算する **digest の一行**が本文にそのまま在るかで判ずる。
  散文は書き手が自由に書いてよいが、**数は機械が出す** —— 書き手が数を打ち直せる形に
  すると、要約は測定ではなく主張になる。

## 要約の中身

変わった台帳の一覧・差分行数・新しい件・消えた件・状態が動いた件を出す。

- 件の名は `id` → `incident_id` → `scenario_id` → `key` → `token` → `name` の順に当たり、
  `index` があれば添える。どれも無ければ位置を名の代わりにする。
- 件の状態は `state` → `status` → `disposition` → `verdict` → `phase` の順に当たる。
- **一覧の鍵は選ばない。列に見えるものを全部数える。** 最初に見つけた一つを採る形は、
  網羅台帳（`dispositions` 5 件と `entries` 338 件を両方持つ）で 338 件の側を丸ごと
  落とした —— 再判定で 21 件が動いた PR が「動いた件 0」と要約された。名は列の鍵で
  名前空間を分け、別の列の同名が衝突しないようにする。
- 一覧が 20 件を超えたら打ち切って「ほか N 件」と告げる。**黙って切らない。**

## 制約

- 標準ライブラリだけで動く。pip も通信も使わない（`git` の呼び出しだけが外部依存）。
- 配布物ではない。`plugin/` の下へは置かず、`plugin/` から import もしない（ADR-114）。
- 台帳の中身の**正しさ**は判じない。数と名と状態の差だけを出す。何が良い変更かは人が決める。
- 閾値（200 行）は運用の既定であり、根拠は「一件の処遇が数十行、再判定が数千行」という
  実測の隔たりだけである。精密な値ではない。

## エラー時挙動

- 差分そのものを取れない場合（`git` の失敗・存在しない基準）: 終了コード 2 で止める。
  判定を書けないときは沈黙して開かない（DECIDED-001 第12項）。
- 台帳が JSON として読めない場合: 「読めなかった台帳（破損の疑い）」として**別に挙げ**、
  空として扱わない。破損を「空」や「新規ファイル」へ写像しない（INC-027 で直した形を
  ここで作り直さない）。
- PR 本文を読めない場合: 終了コード 2。免除には倒さない。

## 受入基準

- 小さい差分は素通りする。巨大な差分は、承認か digest のどちらかで通り、どちらも無ければ
  終了コード 1 で止まる。手で書き換えた digest は通らない。
- 網羅台帳の実物の形（短い列と長い列・名の鍵は `key`・別の列の同名）で、動いた件を
  過少に報告しない。
- CI が本スクリプトを呼んでいることを試験が検める（走らせ手を足して読む段を足さない形を
  作らない。INC-012・INC-015・ADR-148 で三度起きた）。
