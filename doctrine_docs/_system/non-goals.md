# 横断のやらないこと（16項）

本文書は、体系があえて引き受けない範囲の正本である。どこまでを保証しないかを明示する（[R8]・[R9]）。各項は、対象を具体に書き、理由を添える。

## やらないこと

1. 意味的に重複する文書を、最終的に同じかどうか判断することはしない。リンタ（文書を機械点検するスクリプト）と監査は、語彙の近い重複に印を付けるだけにとどめる。統合してよいかは人が決める。
2. カルク（英語の比喩・構文・一語訳をなぞった日本語）をすべて見つけ出すことはしない。用語チェッカーが照合するのは、一覧に載った表現だけである。
3. 違反を100%防ぐことはしない。ガード（違反を機械的に拒否するHook）は防ぐための最初の関門であり、ここを逃れた違反は監査が後から拾う。
4. ガードを通さずに書かれた文書までは防げない。Hookが起動しない経路で書かれた文書は止められず、全件監査が後から補う。
5. ターン（一回のやり取り）ごとに全件を走査することはしない。リンタは編集された一つの文書だけを点検し、全件の点検は監査に委ねる。
6. 業務トランザクション（請求・受発注・仕訳）、外部ツールが正本の動的データ（チケット・台帳・計測値）、署名済みの法的文書は、統治の対象にしない。許すのは要点の転記（DECIDED・ADRへ）と出所の参照（EXT アンカー）だけとする（ADR-015・ADR-026）。
7. 会話の中の決定を、機械が取りこぼしなく検出することはしない。捕捉（R12）が保証するのは、セッションの終端と圧縮**後**の合図と、退避したメモの選別の義務までである。**圧縮の前に促すことはしない**（実行環境が圧縮の直前に文脈を運ばないため、原理的にできない。ADR-077）。圧縮で失われた詳細は戻らず、告げられるのは「失われたかもしれない」ことだけである。記録されなかった決定が「無かった」ことの検証は、構造ではできない。
8. 敵対的な文書内容・ファイル名に対する完全な防御はしない。注入境界のサニタイズ（ADR-040）が防ぐのは構造的な注入（改行による偽セクションの捏造・ファイル名による指示の注入・巨大値による上限回避）までであり、引用データがモデルを説得しようとすること自体は止められない。provenance の明示で縮め、最終判断は人とモデルに委ねる。
9. ガードが実際に違反を拒否できることは検出しない。発火の印の対（ガード PreToolUse とリンタ PostToolUse。ADR-062）で「配線されているのに発火していない」欠落は疑いとして挙がるようになったが、それは起動の証跡であって、拒否の往復（違反を投じて拒まれること）の証跡ではない（ADR-050）。編集が一度も走らないセッションでは、欠落があっても信号は生まれない。
10. リポジトリを越えた統治はしない。組織を横断する識別子も、リポジトリ間の依存も持たない。越境の参照が要るときは EXT アンカーで引き、相手の統治木を直接の依存先にはしない（ADR-057）。
11. サブエージェントへの契約注入はしない。SessionStart の注入と要点の復唱は主セッションだけのものであり、分岐した子エージェントは契約を持たずにツールを呼ぶ。ガードは子のツール呼び出しにも効くが、それは拒否の面であって理解の面ではない。**理由は「届かない」ではない**（`SubagentStart` は在り、文脈を運ぶ。ADR-079）。子へ渡す文脈は呼び出し側が組む、という選択である（llm-context-pack。ADR-064）。親の契約をそのまま流すと、子は自分の課題に要らない文脈を大量に受け取り、最少の文脈という方針と当たる。
12. id の改名・改番は追わない。体系は履歴を持たず、内容の指紋はファイルの移動を生き延びるが、id そのものの改名は「別の文書の出現と元の文書の消失」にしか見えない。変更の正規の道は後継の作成と置換であり、旧 id を指し続ける参照は監査が事後に指す（ADR-064）。
13. ブランチ並行の採番の衝突は防がない。同じ番号が二重に生まれたら、事後に採用規則（先勝ち。ADR-049）で一意に裁き、影は error で名指しする。防止に要る採番の中央装置は、分散の版管理と根本で衝突する（ADR-064）。
14. 継続的結合（CI）の敷設・稼働は検出しない。統治はリポジトリの中で閉じ、外部の実行環境を感知する手段を持たない。感知できるのは CI が残した成果物（監査の要約）までであり、それは敷設の証跡ではない（ADR-066）。
15. 不具合報告の自動送信はしない。スクリプトは通信せず（DECIDED 事実7）、エラージャーナルへの記録（ローカル・許可制）までを機械が受け持つ。issue への投稿は、LLM の起草→下書きの全文を利用者に見せる→承認、を経て利用者の手元の gh でだけ行う。承認なしの外部送信の経路は作らない（ADR-074）。
16. セッションの途中で設定が差し替わったことは検知しない。settings 由来の hooks はセッション中に live reload されるため、モデルが冒頭で読んだ契約と、実際に発火するガードが食い違う窓が開きうる（ADR-080）。`ConfigChange` は配線しておらず、この食い違いを機械は見ない。本プラグインの配線は plugin 層なのでセッション中は保持されるが、同じ木に置かれた settings 由来の hooks までは面倒を見ない。

## 理由

1. 意味が同じかどうかは文脈に依存する。機械に白黒を付けさせると、擬陽性も取りこぼしも生む。判断を人に残すほうが安全である。
2. 言い回しは限りなくあり、すべてを網羅することはできない。確実なものだけを一覧で弾き、残りは doc-review の逆翻訳テルに委ねる。
3. すべての書き込み経路を塞ぐと、運用が止まる。予防・検出・委ねるの三層に分けるほうが壊れにくい。
4. Hookは登録された経路でしか起動しない。これは仕組み上どうしても残る穴であり、監査の全件走査で埋める設計とした。
5. ターンごとに全件を走査すると、応答が遅くなる。編集された一文書の点検と、定例での全件監査に役割を分ける。
6. 外部に正本があるデータを写すと、正本が二つになり、どちらが真かを機械で判別できなくなる。鮮度の速いデータは文書の版管理では追えず、常時集合も肥える。境界の外に置き、要点だけを引くほうが壊れにくい。
7. 会話は構造化されていない。決定かどうかの判定は意味の判断であり、機械の照合では閉じない（§7）。促しと選別の義務という形で、判断の機会を作ることまでが構造の受け持ちである。
8. 文書内容は、他者の変更取り込み依頼・外部から取り込んだ依存・展開物としてリポジトリに入りうるため、チーム作成という信頼前提は置けない。構造（改行・制御文字・長さ）は機械で無害化できるが、文面の説得力は意味の判断であり、機械では閉じない。予防（サニタイズ）と境界の明示（provenance）までを構造が受け持ち、残りを委ねる。
9. 発火の印は「起動した」ことしか語らない。起動しても正しく拒否するかは別の問いで、そこを確かめるには意図的な違反を投じて往復を見る仕掛け（機能カナリア）が要り、それは版を分けるだけの規模がある（ADR-050・ADR-062）。見ていないものを見ていると書けば、限界の明示より害の大きい誤った安心を与える。カナリアが入るまで、拒否の保証はやらないことの側に置く。
10. この体系はリポジトリ一つで動いており、二つ目の痛みがまだ出ていない。衝突の解決規則も名前空間の切り方も、必要になる前に決めれば誤りうるうえ、誤ったことに痛みが出るまで気づけない。越境は既にある EXT アンカーで足りる。痛みが出たときに決め直す（ADR-057 を置換する）。
11. 差し込み口（`SubagentStart`）は在る。かつて「無い」と書いていた再検討の条件は満たされた（ADR-079）。それでも注入しないのは、子に要るのが課題ごとの縮約であって親の復唱ではないからである。何を注入するかは別途裁く。
12. 改名の追跡には履歴か別名表が要る。履歴は持たず（事実7の帰結）、別名表は第二の正本になって表と実体の食い違いという新しい欠陥面を作る。置換の道が既にあるので、逸脱だけを監査が指せば足りる。
13. 採番の予約は中央装置を要し、乱数の id は「型と番号で引ける」可読性を壊す。先行事例の解決案が採番サーバへ後退した教訓のとおり、防止の対価が痛みに釣り合わない。事後の一意な裁定で足りる。
14. 敷設の自己申告（設定キー）は、申告と実態の食い違いを検める手段が無く、検証できない申告は誤った安心の素になる（ADR-050 と同じ判断）。見ていないものを見ていると書かない。
15. 統治対象のリポジトリには機密がありうる。例外の自由文にはパスや内容が混入するため、記録の時点で自由文を捨てる許可制と、送信前の人の承認だけが構造的に安全である。送る内容の最終判断は機械では閉じない。
16. 検知するには、注入した契約と実際の配線の同一性を継続して照合する仕掛けが要る。何を attest し、食い違ったときどこまで拒むかは、それ自体が設計判断であり未決である（ADR-080 が問いを開いたまま残した）。見ていないものを見ていると書かない。
