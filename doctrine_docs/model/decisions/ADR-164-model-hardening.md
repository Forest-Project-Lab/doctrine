# MODEL の描画先・引退の扱い・塊の中の散文の門を定める（ADR-163 の追補）

## 背景

ADR-163 の実施（三波）の後、独立の検証を五つの視点で回し、各指摘を別の検証者が反証に
かけた。生き残った指摘のうち、**決定を要するもの**が四つ在った。

1. **描画先の置き場所に決定の正本が無い。** 実装・SPEC-014・ICD-006 は「正本の .md と同じ
   場所・同じ名の `.json`」を「ADR-163 決定4」に帰していたが、決定4 は描く向きと並びしか
   決めておらず、置き場所はどの決定にも書かれていなかった。**空所へ向けた引用が三箇所に
   写されていた。**
2. **確定の同値が、引退の道を塞いだ。** `check_confirmation` は `current` 以外を一括で咎める
   ため、確定を経た模型を廃止・置換・退避へ移した瞬間に所見が立ち、二度と消えなかった。
   逃げ道は「引退を取り消す」か「確定の記録を偽る」の二つしかなく、どちらも壊れている。
3. **用語の門が MODEL にだけ効かない。** 用語チェッカーは囲みの中を丸ごと覆う。MODEL は値の
   ほとんどが囲みの中に在るので、禁止同義語・カルク・未定義語の門がこの型にだけ素通しに
   なっていた（同じ一文を囲みの外に書けば咎められるので、書き手からは効いて見える）。
4. **助言が機械へ「確定せよ」と促していた。** 「全ての値が confirmed である。確定の一押し
   （`status` を `current` へ）を行うか…」という文面が、`Self-correct` の見出しの下に
   ERROR（重大度の最も重い段）で出ていた。ADR-163 決定6 が人だけの仕事と定めたものを、機械への指示にしていた。

あわせて、例外を漏らす経路（`realized_by` が配列でない）・必須欄が `null` でも通る隙間・
id の型を検めない・塊を持たない見出しが黙って消える、という**形の穴**も出た。これらは
決定を要しない欠陥であり、同じ波で直す。

## 却下した選択肢

- **ADR-163 を編集する。** 受理済みの ADR は不変であり、正規の道は追補か置換である
  （ADR-044）。本 ADR は決定4 を置き換えず、書かれていなかったことを足す。
- **黙って実装だけ直す。** 置き場所の決定の正本が空のまま、引用だけが三箇所に残る。次に
  置き場所を変えたい者が根拠を辿れない。
- **MODEL を用語の門の外だと宣言する。** 「この型にだけ門が効かない」状態を正当化する。
  値の大半が散文である型で門を外すのは、規範の側の敗北である。
- **確定の同値を捨てる。** 同値は「確定の一押しだけ人」の実体であり（ADR-163 決定6）、捨て
  ない。引退した位置づけを対象から外すだけで足りる。

## 決定

1. **描画先は、正本の .md と同じ場所・同じ名の `.json` とする。** 置き場所の正本は本 ADR で
   あり、SPEC-014 と ICD-006 はこれを引く。
2. **引退した位置づけ（`deprecated`・`superseded`・`archived`）では、確定の同値を検めない。**
   引退した模型の値は `confirmed` のまま凍らせてよい。確定を経た模型を引退させる道を塞がない。
3. **用語の門は、塊の中の散文の欄に掛ける。** 対象は `_model.PROSE_FIELDS`（`purpose`・
   `boundary`・`guarantee`・`response_measure`・`label`・`payload_or_action`・`condition`・
   `name`・`responsibilities`・`assumptions`・`na_reason`・`self_loop_reason`）に限り、
   id・種別・パス・日付のような機械の値には掛けない。
4. **「全ての値が confirmed なのに current でない」は WARN とし、助言は機械に `status` を
   動かさせない**（WARN は重大度・警告の段である）。機械が取れる行いは値を戻すことだけで
   あり、確定の一押しは人が行う。
   逆向き（`current` なのに未確定の値が在る）は ERROR のままとする——そちらは「current と
   名乗っているのに中身が未確定」であり、名乗りの側が誤っている。
5. **形の穴を塞ぐ。** 必須欄は「値が `null` も欠落と数える」。id は空でない文字列とする
   （`MODEL_BAD_ID`）。`realized_by` は配列とし、配列でなければ所見にする
   （`MODEL_BAD_REALIZED_BY`。例外を漏らさない）。塊を持たない `###` の見出しは所見にする
   （`MODEL_HEADING_WITHOUT_BLOCK`）。
6. **節名は登録簿から機械的に導き、写さない。** WATCH-001 第2項が同じ形の手写しを戻り禁止に
   している（DECIDED-001 事実1）。
7. **正本を持たない投影（取り残しの `.json`）を描き手が見張る。** 一括の描画と `--check` の
   ときに、`MODEL-` で始まる `.json` のうち隣に MODEL の .md が無いものを告げる。

## 帰結

- SPEC-031（所見の名・必須欄の扱い・節名の導出・散文の門）と TEST-031・`test_model.py` を
  追随させる。SPEC-014 と ICD-006 の「ADR-163 決定4」の引用を本 ADR へ向け直す。
- 所見の名が三つ増える（`MODEL_BAD_ID`・`MODEL_BAD_REALIZED_BY`・
  `MODEL_HEADING_WITHOUT_BLOCK`）。`MODEL_CONFIRMED_NOT_CURRENT` の段は ERROR から WARN へ
  下がる。
- 保証限界: 用語の門を塊の中へ届かせたのは**散文の欄だけ**である。鍵の名・id・出所の
  `source` と `locator` は対象外であり、そこに書いた散文は門の外に残る。
- 保証限界: 取り残しの `.json` の見張りは、名が `MODEL-` で始まる物に限る。別の名で置いた
  投影は見張られない。
- **この決定は、機械が捕まえた欠陥から起きた。** 検証は五つの視点で 31 件を挙げ、別の検証者
  による反証を経て残った。うち二件は実際に例外を出しており、一件は不具合の記録
  （`.claude/.cache/doctrine-errors.jsonl`）に残っていた。
