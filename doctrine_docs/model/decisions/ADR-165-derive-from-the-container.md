# 器の形を写さず、固定した一枚から導く（写しをやめる）

## 背景

doctrine-lens が、こちらが描いた投影 `MODEL-001-doctrine.json` を自分の門へ無修正で掛け、
**二つの門で落ちた**と報せた（#294、2026-08-14）。こちらで再現し、報告が正確であることを
確かめた。

- **M-18（形）**: 投影は `system-map/gold-model/0.1` を名乗るのに、器の Scenario の必須欄
  九つのうち四つ（`goal`・`trigger`・`preconditions`・`outcome`）を欠き、段の必須欄
  （`action`・`expected`）も欠いていた。**名乗った器に適合していなかった。**
- **M-14（到達）**: 要素が `realized_by` も `realization` も持たず、到達可能な要素が 0 件
  だった。これは JSON Schema では書けない不変条件である。

原因は `_model.py` 自身が註釈で書いていたとおりである——語彙は器の写し、必須欄は散文の
手引き（`references/model-shape.md`）から採っていた。**出所が二つに割れていた。** 実測で
Scenario の必須欄は器が九つ、こちらが五つだった。

固定点（EXT-006 の tag）の validator では通ると出る。ただし**同じ固定点の `schema.json` も
既に九つを要求している**——固定点の門が形を検めていなかっただけであり、適合していなかった
という事実は変わらない。

## 却下した選択肢

- **写しを手で直す。** 今回と同じ割れが次の版でまた起きる。実際、今回がその実例である。
- **上流に必須欄を緩めてもらう。** 欠けている六欄はシナリオ画面の実体を支えており（見出し・
  きっかけ・前提・結果・行い・期待）、緩めると「記録が無い」と「問題が無い」が同じ表示に
  なる。上流が Phase 2 で潰してきた欠陥類型そのものである。
- **通信して毎回取りに行く。** スクリプトは通信しない（DECIDED-001 事実7）。
- **器が書けない不変条件（要素の到達など）まで doctrine 側へ写す。** 写しをやめるという本
  ADR の趣旨に反する。上流が機械可読の口を出すまでは、第四門で見る。

## 決定

1. **器の形の正本は doctrine-lens の `gold-model/schema.json`**（`$id` は
   `system-map/gold-model/0.1`）とする（#294 の B7（語彙の正本をどちらが持つかの項目）の
   確認）。
2. **doctrine は固定した一枚を配布物へ同梱し、そこから導く。** 置き場は
   `plugin/schemas/system-map-gold-model-0.1.json`、固定点は EXT-006 と同じ tag
   `system-map/phase-1-continue`。導くのは、実体ごとの必須欄・段の必須欄・出所の必須欄・
   語彙（器が `enum` を書いた欄を機械的に集める）・最上位の欄・器の版である。
   **手で並べた表を持たない。**
3. **同梱の一枚が黙って動かないことは、EXT-007 の指紋が見張る。**
4. **版の進め方**（#294 の合意）: 欄の追加（既存の投影が通り続ける物）は版を上げない。
   必須欄の追加・削除、語彙の縮小は名を上げる（`0.1` から `0.2` へ）。上げるときは
   doctrine-lens が #294 へ告知し、doctrine が追随する。逆はしない（正本は一つ）。
5. **系の塊は、器の `system` の必須欄に加えて `target` を持つ。** 器では最上位の欄であり、
   描き手が塊から持ち上げる。
6. **器が書けない不変条件は写さない。** M 層の不変条件（要素の到達など）は doctrine 側の
   検査に持たず、第四門（doctrine-lens の validator）が見る。上流が機械可読の口を出したら、
   そのときに参照へ切り替える。
7. **同梱の一枚を読めないときは、黙って通さない**（`MODEL_SCHEMA_UNREADABLE`）。器を持たない
   まま緑を出さない。

## 帰結

- `locator` は必須でなくなる（器の `Source` が要するのは `source`・`checked_at`・`verdict`
  である）。錨の無い出所は、出所の門が「機械検証不能」として数える——**咎めないが、
  数えないわけではない。**
- SPEC-031・TEST-031・雛形・起草の手引き・実例 MODEL-001 を追随させた。実例は、直す前は
  上流の門で八件の指摘が立ち、直した後は**指摘ゼロ**（合格 11・空虚 6・不合格 0）で、
  到達の門も合格（到達可能な要素 4 件）である（こちらで無修正の複製を回して実測）。
- 実例を直す途中で、こちらの出所の門が**私が伸ばした偽のコミットの指紋を四件とも落とした**
  （`D4_ANCHOR_UNMATCHED`）。門は設計どおり働いている。
- 保証限界: 同梱の一枚と上流の一枚が同じであることは、指紋では確かめられない（通信しない
  ため）。`review_by` の見張りと #294 の告知に委ねる。
- 保証限界: 器が書けない不変条件は、doctrine 側の門では捕まらない。起草者は第四門まで回す
  こと（技能の `references/acceptance-gates.md`）。
