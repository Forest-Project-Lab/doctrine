# 意味モデルの正本を統治木の中の型付き .md とし、JSON は一方通行の投影とする（方向づけ。実施は凍結の解除後）

## 背景

issue #294 の洗い出し B2（同 issue が「解除の日に決める必要がある」として並べた項目の
二つ目）は、模型の置き場の規約を挙げた。いまの起草の技能（`system-map-draft`。配布を
決めたのは ADR-136）の既定の置き場は、技能本体 `plugin/skills/system-map-draft/SKILL.md`
のとおり、対象リポジトリの `.claude/system-map/` である。そこは統治木の外であり、鮮度の
見張りも、逆依存ゼロを条件とする削除・降格の安全も届かない。

体系の目的は「古びた仕様をコードにしない」ことであり、その手段が「正本を統治の下に置く」
である。人が確定まで押した意味モデルが統治の外に残ると、確定した意味だけが古びを見張られ
ない。issue #210 の条件1（最小性）の論点の一つ「意味モデル正本の置き場」が未確定のままで
あるのも、同じ問題である（同 issue の草案は、所有者の停止の指示により暫定の記録として
保たれている）。

所有者は 2026-08-14 の会話で、二つを述べた。(1) 置き場は統治木の中を本命とする。(2) 形は、
JSON の側で表さねばならないことを .md の側で機械的に担保し、そのまま JSON へ投影できる
ようにする。

体系は、この形の部品を既に持っている——型ごとの必須キーと必須節（構造の担保）、
`render-projection.py`（投影の機械描画）、監査の `projection_drift`（投影の古びの検出）、
宣言済みの読み口が名乗る `source_revision`（測った木の版。ADR-155）、`map-draft-check.py`
（出所の門。SPEC-029）である。

## 却下した選択肢

- **JSON を正本にして統治木へ置く。** 統治の規則はフロントマターを持つ .md を前提にして
  おり（必須キーは八つ。ADR-033）、JSON を正本にすると型の規則を二つの形で持つことになる。
  人が確定を押す対象としても読みにくい。
- **統治木の外に置き続ける。** 器の保護がどれも届かない。消費者は置き場を総当たりするしか
  ない——#294 の B3（この木は意味モデルを持つかを問う口の不在）が挙げた事態である。
- **双方向にする**（JSON を直して .md へ書き戻す）。正本が二つになり、食い違ったときに
  どちらが勝つかを決められない。体系が最初から拒んでいる形である。
- **凍結が解けた日に考える。** 会話の決定は残らない。方向づけを木へ写さなければ、同じ検討を
  後からやり直すことになる。

## 決定

本 ADR は方向づけであり、いま型を増やさない。凍結（ADR-112 決定5）は効いたままであり、
実施はその解除の日に、根拠 ADR の置換とともに行う。

1. **層B（要素・流れ・契約・シナリオからなる系の模型）の意味モデルの正本は、統治木の中に
   置く。**
2. **正本の形は型付きの .md とする。** JSON は投影であり、手で保守しない。
3. **描画の向きは .md から JSON への一方通行とする。** JSON を編集して正本へ戻す道は作らない。
4. **JSON の側が要する構造は、.md の型の規則で機械的に担保する。** 担保の口は必須キー・
   必須節・リンタの点検であり、描いた投影の古びは監査の `projection_drift` が見る。
5. **人が読んで確定を押す対象は .md とする。** 機械が担うのは下書きの起草・構造の点検・
   投影の描画・古びの申告であり、確定の一押しだけを人に残す。
6. **読者ごとに文言を変えるときも、正本を増やさない。** 同じ .md から粒度の違う投影を描き、
   投影の同期切れは既存の描画と古びの検出に見張らせる。

## 帰結

- issue #294 の B1（器の正本と版の進め方）・B5（確定の記録の形と権威）・B7（語彙の正本）は、
  本 ADR の形の下でなお決める必要が残る。あわせて**出所の門（SPEC-029）の掛け先**——門を
  .md の側へ移すか、描いた JSON に掛け続けるか——も、実施の日の決め事として残る。
  B3（この木は意味モデルを持つかを問う口）は、正本が統治木の中に在れば宣言済みの読み口
  （`dep-graph.py` の nodes）で答えられる見込みだが、本 ADR は測っていない。
- issue #210 の条件1（最小性）の論点の一つ「意味モデル正本の置き場」に、doctrine 側の
  方向づけを与える。ただし同 issue が求めているのは**移管の時点**（凍結の解除より前）の
  置き場と形式であり、本 ADR が決めるのは解除の後の正本の置き場と形である。条件1 の定義と
  充足の判定は doctrine-lens 側と所有者の領分であり、**本 ADR の受理では条件1 は埋まらない。**
- 実施の日に doctrine 側で直す先は、起草の技能（`SKILL.md` の既定の置き場）・その根拠の
  ADR-136・門の仕様 SPEC-029・authoring の ICD-007 の外部条項・EXT-006 の期待である。
  **受理だけを先に済ませると、現行の文書が一つも本 ADR を参照しないまま残り、監査の
  `adr_not_landed` が上がる**（WATCH-001 第6項）。したがって受理は、実施の波と同じ日に行う。
- 受理の条件は二つである——H 層の床を通ること（ADR-160）、および ADR-112 決定5 を後継の
  ADR で置換すること。本 ADR は ADR-112 を置換しない。
- 保証限界: 実施の費用を測っていない。構造を .md の側で担保するリンタの規則は、JSON の器を
  検める仕組みより作り込みが要る。正本の分量も増える。
- 保証限界: 本 ADR は型の名前・必須キー・必須節の中身を決めていない。それらは実施の日の
  設計であり、根拠 ADR を要する。
