# 器 0.2 へ追随し、M 層の不変条件は requirements 口を参照する

## 背景

doctrine-lens が #294 で二件を告知した（第3信 2026-08-14・第4信 2026-08-15）。

1. **器が 0.2 へ上がった。** 同じ名 `system-map/gold-model/0.1` を名乗る器が二つ在り、
   受け入れる集合が違っていた——tag 時点の一枚（doctrine が同梱した物）に対し、上流の
   現行は `realization`/`realized_by` の排他と `minLength: 1` を足していた。上流は
   「名が嘘をつく」状態を断つために版名を上げ、規約も「受け入れる集合が狭まる変更
   （制約の追加を含む）は名を上げる」へ改めた。貼り直すまで、doctrine の投影は上流の
   門 M-18（形）で落ちる（落ちるのは `schema` の値だけで、中身は 0.2 に適合している。
   第3信 §4 の実測）。
2. **requirements 口ができた。** 器（JSON Schema）が書けない M 層の不変条件（要素の
   到達など）を機械可読で出す口 `validate.mjs --requirements --json`
   （`system-map/requirements/1`）である。ADR-165 決定6 は「上流が機械可読の口を
   出したら、そのときに参照へ切り替える」と定めていた。その条件が成立した。

取得した 0.2 の一枚を 0.1 と機械で突き合わせ、差が制約の追加と版名だけであること
（必須欄と語彙は不動）を実測した。所有者は 2026-08-16 の会話で取り込みを裁定した。

## 却下した選択肢

- **0.1 のまま留まる。** 上流の門で落ち続け、追随の窓が開いたままになる。版が上がったら
  追随するのは ADR-165 決定4 の合意である。
- **requirements の一覧を doctrine 側へ写す。** 写しは割れる（ADR-165 の趣旨）。第4信も
  「写していたら二重になっていた」と実測を添えている。
- **排他と `minLength` を doctrine 側の導出に足す。** 導出する面（必須欄・語彙・段・出所・
  最上位・版）を任意の JSON Schema の検証へ広げることになり、第四門の再実装に向かう。
  形の全検証は第四門が持ち、doctrine の門は導出の面だけを検める（ADR-165 決定2 のまま）。
- **0.1 の写しも並置して残す。** 同梱が二枚になると、どちらから導いているかが読み手に
  見えなくなる。同梱は一枚だけとする（正本は一つ、の同型）。

## 決定

1. **器 0.2 へ追随する。** 同梱は `plugin/schemas/system-map-gold-model-0.2.json` の一枚
   だけとし、0.1 の写しは取り除く。固定点は tag `system-map/gold-model-0.2`
   （commit `991b8a6e3e6870d9651279956a8f7a60292e47af`）、指紋は sha256（内容の指紋を
   採る算法）で `92fa79c38b4db5e53ed1c02c73bdab948ccb41d6f7188531ee32972b5cb5a30c`。
   見張りは EXT-007 が続ける（対象と指紋を付け替える）。
2. **版の進め方の規約の正本は、器の一枚の `$comment` が持つ**（上流の定め）。規約の要点は
   「受け入れる集合が狭まる変更（必須欄の追加・語彙の縮小・制約の追加）は版の名を上げ、
   #294 へ告知し、doctrine が追随する。逆はしない」。doctrine 側は規約の本文を写さない。
   ADR-165 決定4 の記述は当時の合意の記録として残る（本 ADR は置換しない。写しをやめ、
   一枚から導くという決定そのものは変わっていない）。
3. **M 層の不変条件の機械可読の参照は requirements 口とする**（ADR-165 決定6 の切り替えの
   実施）。写さないのは変わらない——起草の手引き（第四門）がこの口を指し、依存は EXT-008
   に登録する。口が返す `container.sha256` と同梱の一枚の指紋を突き合わせれば、貼り直しの
   済みと参照先の器のずれを機械で確かめられる。
4. **第四門の固定点を 0.2 の tag へ動かす。** 検収で回す validator（検証器）の複製は
   `system-map/gold-model-0.2` から採る。

## 帰結

- MODEL-001 の投影を描き直すと `schema` の値が `system-map/gold-model/0.2` になり、
  上流の門 M-18 の窓が閉じる。
- 排他と `minLength` は doctrine の門では捕まらない（導出の面の外）。両方の欄を持つ要素や
  空文字列の証跡は、第四門が落とす。起草者は第四門まで回すこと（従来どおり）。
- requirements 口の一覧のうち、負例で裏づけの無い 13 件は「述べているが確かめていない」
  と上流が明示している（`proven: false`）。参照する側もこの区別を保ち、裏づけを合格の
  証拠と読み違えない。
- 保証限界: 同梱の一枚と上流の一枚の同一性、および requirements 口の存続は、通信しない
  ため機械では確かめられない。EXT-007・EXT-008 の `review_by` と #294 の告知に委ねる。
