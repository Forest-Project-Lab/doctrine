# スカラへの正規化を共有コアに一度だけ置く。入れ物は空にする

## 背景

フロントマターの値をスカラの文字列へ正規化する `_coerce_str` が、**四箇所に別々に在った。**

2026-08-03 に、この関数が入れ物（一覧・写像）に対して Python の内部表記を返す欠陥を
直した（ADR-092）。**そのとき直したのは一箇所だけだった。** 残る三つは直っていない。

四つに同じ入力を与えて突き合わせた。

| 入力 | `_depgraph`（直した） | `inject-contract` | `policy-guard` | `render-projection` |
|---|---|---|---|---|
| `'x'` | `'x'` | `'x'` | `'x'` | `'x'` |
| `None`・真偽値 | `''` | `''` | `''` | `''` |
| **`['a']`** | `''` | **`"['a']"`** | **`"['a']"`** | **`"['a']"`** |
| **`{'k': 'v'}`** | `''` | **`"{'k': 'v'}"`** | **`"{'k': 'v'}"`** | **`"{'k': 'v'}"`** |

**同じ名前の関数が、同じ入力に四通りのうち二通りの答えを返す。** ADR-099 で日付の解釈に
ついて同じ形を直した直後に、隣で同じ形が残っていた。

害は在処ごとに違う。

- `inject-contract`: 常時投入の契約の文へ `"['t']"` が載る。**モデルが読む文が壊れる。**
- `render-projection`: 投影に載る。
- `policy-guard`: **ガードの判定に使っている。** これは別の決定で扱う（ADR-102）。

**一箇所だけ直す形が、この欠陥を生んだ。** 正本が無ければ、直しは写しの数だけ要る。

## 却下した選択肢

**残る三箇所を同じように直す。** 四つ揃うが、**五つ目が生まれたときに同じことが起きる。**
実際、これは「一箇所だけ直した」ことの帰結である。**正本を置かずに揃えても、揃った
ことを誰も保てない。**

**入れ物を `str()` で文字列にする（緩い側へ揃える）。** 宣言（「スカラ値を str に
正規化する」）と食い違う。そして内部表記は誰にとっても意味を持たない。

**呼び手ごとに違ってよいことにする。** 同じ名前で違う答えを返す関数が四つ在る状態を
認めることになる。**名前が同じなら答えも同じであるべきである。**

## 決定

**スカラへの正規化を共有コアに一度だけ置く。写しは全て正本を呼ぶ。**

1. **`_frontmatter.coerce_str(value)` を正本とする。** 文字列はそのまま、`None` と真偽値は
   空文字、**入れ物（一覧・写像・組）は空文字**、その他のスカラは `str()` とする。
   決して例外を投げない。
2. **四つの写しを消し、呼び手は正本を直に呼ぶ。** 薄い前面も置かない（ADR-099 と同じ
   理由 —— 前面は後からそこで挙動を変えられる場所になる）。
3. **機械が二重定義を咎める。** `_coerce_str` を正本の外に定義したら、メタの受入が落ちる。
4. **入れ物を空にするのは、宣言どおりにするためである。** 「スカラ値を」と書いてある関数に
   入れ物を渡すのは呼び手の誤りであり、**内部表記を下流へ流すより空にするほうが安全**で
   ある（下流は空を「取れなかった」として扱える）。

## 帰結

- 同じ名前の関数が、どこから呼んでも同じ答えを返す。
- 常時投入の契約の文と投影から、内部表記が出なくなる。
- 保証限界: **空文字は「無い」と「読めない」を区別しない。** 呼び手はどちらかを知りたい
  ときに別の手段を要する（節点の項が空文字なのは、未指定か入れ物かのどちらかである）。
  **区別が要る場面が出たら、そのとき決め直す。**
- 保証限界: 機械が咎めるのは名前（`_coerce_str`）の形である。別の名前で同じことをすれば
  掴めない（機械で判じられる形に限るという取引）。
- 保証限界: ガードの判定が入れ物で狂う問題は、これだけでは直らない。**空文字にしても
  「ADR でない」と読まれる**ので、別に決める（ADR-102）。
