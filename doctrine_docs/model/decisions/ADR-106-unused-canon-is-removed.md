# 使われない正本を落とす。二重に持っていた規則は正本へ寄せる

## 背景

構造規則の正本（登録簿）に、**どこからも使われない公開名が五つ在った。** 走査した ——
公開名 44 のうち、スクリプトからも登録簿自身の取得関数からも参照されないものである。

| 名 | 状態 |
|---|---|
| `SYSTEM_TIER_TYPES` | 消費者ゼロ。文書にも出てこない |
| `ALWAYS_CONTRACT_TYPES` | 消費者ゼロ。文書にも出てこない |
| `LEVEL3_KEYS` | 消費者ゼロ。文書にも出てこない |
| `LEVEL4_KEYS` | 消費者ゼロ（ADR-092 が「凍結されているのに消費者が無い」と記録済み） |
| `required_keys` | **ICD で公開しているのに、生産の呼び手ゼロ** |

**そして二つは、生きた規則と食い違っていた。**

| 死んだ表 | 生きた規則 | 欠けていたもの |
|---|---|---|
| `ALWAYS_CONTRACT_TYPES`（4型） | 既定が `always` の型（5型） | **`OVERVIEW`** |
| `SYSTEM_TIER_TYPES`（6型） | `_system/` に置ける型（7型） | **`REQ`** |

後者は **ADR-091 の帰結である。** `_system/` に `REQ` を置けるようにしたとき、
**誰も読まない表は誰も直さなかった。** 読む者が居ないので、古びても誰にも見えない。
**これが「使われない正本」の害である** —— 消費者が無いことは無害ではなく、
**静かに嘘になる。**

`required_keys` はもう一段悪い。**規則の写しが在る。** リンタは必須キーの検査で
`REQUIRED_KEYS_L2` を回し、`REQUIRED_REVIEW_BY_TYPES` の分岐を自前で書いている ——
つまり「DECIDED と WATCH は `review_by` も必須」という規則が二箇所に在り、
**正本の側が死んでいる。** しかも公開している署名は `required_keys(level, type)` で、
その `level` は受け取って検証したあと**無視される**（説明文自身が「level は結果を
変えない」と書いている）。**段が許可を決めると読める名前と説明で、何も決めていない。**

段の梯子（`LEVEL3_KEYS`・`LEVEL4_KEYS`）は、そもそも**禁止を持たない。** 段2の木で
`depends_on` を書くのは違反ではなく、**まだ意味を持たない**だけである。禁じるものが
無いので、検査する対象が無い。

## 却下した選択肢

**段の梯子に強制を与える（段2で `depends_on` を咎める）。** 禁止ではないものを咎める
ことになる。しかも**段を上げようとしている木を叱る** —— 段3へ移る準備で依存を書き始めた
木に警告が出る。ADR-090 が戒めた「門が邪魔者になる」形である。

**死んだ表を生きた規則に合わせて直す（`OVERVIEW` と `REQ` を足す）。** 揃うが、
**次に規則が動いたときにまた古びる。** 読む者が居ないからである。
**同じ事実を二箇所に持つのをやめるのが筋である。**

**`required_keys` を消す。** 規則そのもの（必須キーは八つ、DECIDED と WATCH は
`review_by` も）は生きている。消すと、リンタの中の写しだけが残る ——
**正本を消して写しを残すことになる。** 逆である。

**そのままにして「未使用」と註記する。** 註記は古びを止めない。実際、ADR-092 で
「消費者が無い」と記録した後も、そのまま残っていた。

## 決定

**使われない正本を落とす。二重に持っていた規則は正本へ寄せる。機械が再発を咎める。**

1. **`SYSTEM_TIER_TYPES`・`ALWAYS_CONTRACT_TYPES`・`LEVEL3_KEYS`・`LEVEL4_KEYS` を
   落とす。** 消費者が無く、生きた規則と食い違っていた。段の梯子の説明は仕様の散文に
   残す（**何がいつ意味を持つかは書く価値がある。強制はしない**）。
2. **`required_keys` は残し、リンタがそれを呼ぶ。** 必須キーの規則の写しを消す
   （確定事実1 —— 構造規則は登録簿に一度だけ）。
3. **`required_keys` から `level` を落とす。** 生産の呼び手はゼロで、受け取って無視して
   いた。**何も決めない口を公開しない。** ICD と仕様の記述も同じ変更で直す。
4. **機械が再発を咎める。** メタの受入に、登録簿の公開名が消費者を持つことを検める
   歯止めを置く —— **今回の欠陥を見つけた走査そのものを、門にする。**
5. 例外の一覧は持たない。使われないものは落とすか、使う。

## 帰結

- 正本が「読まれるもの」だけになる。**古びても誰にも見えない表**が消える。
- 必須キーの規則が一箇所になる。リンタが正本を呼ぶ。
- 保証限界: **走査は名前の参照で判ずる。** 動的な参照（文字列から引くなど）は掴めない。
  **機械で判じられる形に限る**という取引である。
- 保証限界: **「使われている」ことは「正しい」ことではない。** 参照が在っても、
  その値が妥当かは見ない。
- 保証限界: **ICD の公開を狭める。** 木の外の呼び手が `required_keys(level, …)` を
  呼んでいたら壊れる。測った範囲では呼び手ゼロだが、**リポジトリを越えた統治はしない**
  ので（非目標 第10項）、外は測れない。
- 保証限界: 段の梯子の説明を散文へ移すので、**機械はそれを検めない。** もともと検めて
  いなかった（禁止を持たないので検める対象が無い）。
