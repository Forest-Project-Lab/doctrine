# 日付の解釈を共有コアに一度だけ置く。写しの食い違いを消す

## 背景

日付の値（`updated`・`review_by`・`created`、要約の `today`・`generated_at`、分類の記録の
刻印）を解す実装が、**四箇所に別々に在った。** 日付の正規表現は五箇所に在った。

| 在処 | 何のために |
|---|---|
| `docs-audit.py` の `_parse_date` | 鮮度・期限の判定 |
| `gov-heartbeat.py` の `_parse_date` | 鼓動の鮮度 |
| `inject-contract.py` の `_parse_date` | 注入の鮮度 |
| `_auditcache.py` の `_parse_date` | 要約の日付・初期化の刻印 |
| `_intake.py` の `_STAMP_DATE_RE` | 分類の記録の刻印 |

**そして写しの一つが違う答えを返していた。** 四つに同じ入力を与えて突き合わせた。

| 入力 | docs-audit | gov-heartbeat | inject-contract | **_auditcache** |
|---|---|---|---|---|
| `2026-01-01` | 解せる | 解せる | 解せる | 解せる |
| **`2026-01-01xyz`** | None | None | None | **解せる（`2026-01-01`）** |
| `2026-13-45` | None | None | None | None |
| `2026-02-30` | None | None | None | None |

`_auditcache` の正規表現に終端の錨（`$`）が無い。**要約の鮮度を読む側だけが緩い。**

これは ADR-053 が防ごうとした形そのものである —— あちらは「要約の読み取りを共有コアに
一度だけ正本化する。注入と鼓動は自前の候補順・照合を持たない」と決めた。**読み取りの
規則は一本化したのに、その中で使う日付の解釈は四本のままだった。**

WATCH-001 第3項も同じ規律を別の対象で立てている（「承認辞書をモジュールの中で二重定義
してはならない」）。**同じ事実を二箇所に持たないという規律の、五箇所目の破れである。**

## 却下した選択肢

**`docs-audit` の実装を正本と呼び、他が import する。** 入口のスクリプトを他の入口が
import する形になる。共有の判定は `_` で始まるコアに置くのが既存の作法である
（`_registry`・`_frontmatter`・`_auditcache`・`_intake`・`_termcheck`）。

**新しいコア（`_dates.py`）を作る。** 関数一つのためにモジュールを増やす。
`_frontmatter` は既に横断の値の補助を持っている（`sanitize_inline` は注入境界の
サニタイザであり、フロントマター専用ではない）。**置き場所は既に在る。**

**緩い写しに合わせる（`$` を外す）。** `2026-01-01xyz` を日付と認めることになる。
**緩い側へ揃えない。**

**そのままにして、食い違いを文書に書く。** 書いても消えない。実際、ADR-053 が一本化を
決めた後に、その中で四本が残り続けた。**同じ事実を二箇所に持たない**のは規律であって
注意書きではない。

## 決定

**日付の解釈を共有コアに一度だけ置く。写しは全て正本を呼ぶ。**

1. **`_frontmatter.parse_date(value)` を正本とする。** `YYYY-MM-DD` に厳密に一致し
   （前後の空白は削る、終端の錨を持つ）、実在する日付なら `date` を返す。それ以外は
   `None` を返す。**決して例外を投げない。**
2. **四つの写しを消し、すべて正本を呼ぶ。** `docs-audit`・`gov-heartbeat`・
   `inject-contract`・`_auditcache` の `_parse_date` は正本の薄い前面に留めるか、
   直接呼ぶ形にする。
3. **厳しい側へ揃える。** `_auditcache` が受けていた `2026-01-01xyz` は、これ以降
   `None` になる（緩い側へ揃えない）。
4. **機械が二重定義を咎める。** 日付の解釈を自前で持つスクリプトが現れたら、メタの受入が
   落ちる（型の表の二重定義を咎める既存の検査と同じ形）。**書いても消えないから、
   機械に見せる。**
5. `_intake` の刻印の照合は対象に含める（同じ日付の形を見ている）。

## 帰結

- 日付についての答えが、読み手によって割れなくなる。ADR-053 の一本化が、その中身まで
  届く。
- 保証限界: **揃えるのは「解せるかどうか」だけである。** 解せた日付をどう扱うか
  （古び扱いにするか、咎めるか）は各検査の受け持ちであり、ここでは決めない
  （それは ADR-100 が決める）。
- 保証限界: **時差と時刻は扱わない。** 日付だけである。要約の `generated_at` は
  `YYYY-MM-DDTHH:MM:SSZ` の形だが、日付の部分だけを見る（いまと同じ）。
- 保証限界: 機械が咎めるのは「自前の日付の解釈を持つこと」の**形**である。別の名前で
  同じことをすれば掴めない（機械で判じられる形に限るという取引）。
