# 統治木の外への依存を EXT 型のアンカーとして統治する

## 背景

体系を止めた事故(自己適用のパス消失・上位設計書の置き去り・実行環境の前提の破れ)は、すべて統治木の外で起きた。体系はドメイン間には ICD という境界宣言を持つのに、体系と外界の境界には何の宣言も持たず、外への依存は本文の散文にしか現れなかった。ADR-015 は外部の中身を統治しないと決めたが、外部への依存を追跡しないとは決めていない。

## 却下した選択肢

- 外部の中身を統治木へ写す: 正本が二重になる(ADR-015 と NONGOAL 第6項に反する)。
- フロントマターに専用欄(external_deps)を足す: グラフ・ガード・監査の全てに並行の機構が要る。既存の `depends_on` 資産を使えない。
- 何もしない: 外界の変化・消失が、次の事故まで見えないままになる。

## 決定

型登録簿に `EXT` を一つ足す(置き場所 `<domain>/external/`、既定 `status: current`・`llm_context: task`)。EXT は外部依存 1 件につき 1 文書のアンカーであり、対象の場所・検査の方法(exists／hash／`review_by` のみ)・期待・壊れ方だけを記す。中身は写さない。他の文書は普通の `depends_on: [EXT-n]` でアンカーへ依存し、既存の逆参照・鮮度伝播・変更影響の機構がそのまま外へ届く。監査はアンカーの対象の存在を検査する。

## 帰結

- 「畿外の中身は統治しない、畿外への依存は統治する」が体系の境界規則になる。
- 指紋(hash)照合と未登録の外部参照の走査は後続で足す(v1 は存在検査まで。SPEC-021)。
- 機械で追えない外部(実行環境の仕様など)は `review_by` だけのアンカーとして定期再検証する。
