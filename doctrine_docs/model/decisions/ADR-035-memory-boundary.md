# ハーネスのメモリは環境と個人の事実に限り、影の正本化を見張る

## 背景

Claude Code は持続するメモリ(設定ディレクトリ配下の `projects/<プロジェクト>/memory/`)へ事実を書き溜める。ここに体系の決定・仕様・用語が書かれると、統治木の正本と並ぶ第二の真実になり、正本が更新されてもメモリの古い記述が次のセッションの判断を汚す(影の正本化)。この経路は統治木の外かつプロジェクトの外で、監査の体系外 .md 走査からも見えていなかった。ADR-015 は外部の中身を統治しないと決めたが、影の正本化を見張らないとは決めていない。

## 却下した選択肢

- メモリを統治木へ取り込む: メモリは端末・利用者ごとの揮発する状態であり、正本にできない(ADR-015)。
- メモリへの書き込みを禁じる: ハーネスの機能であり、環境・個人の事実(端末の癖、利用者の好み)には正当な用途がある。
- 何もしない: 実際に本リポジトリのメモリへ統治文書への言及が蓄積していた。矛盾は誰にも見えない。

## 決定

三つを定める。(1) 規範: メモリに書いてよいのは環境と個人の事実だけとする。体系の決定・仕様・用語は書かず、統治木の正本(DECIDED・ADR・GLOSSARY)へ書く。メモリと正本が食い違ったら、常に正本が勝つ。この規範は決定事実(DECIDED-001 事実9)として常時注入で毎セッション届ける。(2) 見張り: 監査の `memory_shadow` 検査が、メモリの .md が統治文書の id に言及していたら advisory で挙げ、正本との矛盾の点検と、残すべき事実の正本への移動を促す。中身の真偽・矛盾の判定はしない(§7。言及の検出まで)。(3) 場所の解決: メモリの置き場は `CLAUDE_CONFIG_DIR`(無ければ `~/.claude`)`/projects/<プロジェクト根の絶対パスの / を - に置換した名前>/memory/` から決定論で引く。無ければ検査しない(CI では通常無い)。

## 帰結

- 「メモリ配下に書き溜められて履歴と正本がずれる」事故類型が、規範(注入)と見張り(監査)の二層で塞がる。
- メモリの中身は引き続き統治しない(強制も写しもしない)。advisory は点検の促しであり、拒否ではない。
- ハーネスがメモリの置き場を変えたら、EXT-001(実行環境の仕様への依存)の再検証で拾い、本 ADR を置換する。
