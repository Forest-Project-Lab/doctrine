# 複数の木にまたがる模型は、跨ぐ接頭を正本に宣言し、経路は実行時に束ねる

## 背景

doctrine-lens が #294 第5信で判断を求めた（欠けの2番）。一つの系が二つのリポジトリに
またがる実データが既に在る（lens の対象1 は doctrine と doctrine-lens の両方の木を
描き、v0.12.0 の門で出所 34 件のうち 10 件が接頭の不一致で機械検証不能だった）。
検証の道具は既に複数の木を受ける（`map-draft-check --repo 接頭=経路` の反復。
ADR-158）。欠けているのは宣言である —— 模型自身が「どの接頭のリポジトリを描くか」を
言わないので、走らせ手が接頭と根の対応表を自前で持ち、消費者は接頭が何のリポジトリを
指すかを知る術が無い。

第5信は二択を挙げた。(a) 模型が対応表を宣言し道具が複数を受ける。(b) 「一つの MODEL は
一つの木を描く」と宣言し複数木の系を射程外とする。

## 却下した選択肢

- **(b) 一つの MODEL は一つの木に限る。** 実データ（二リポジトリの系）が既に在り、
  ADR-158 は複数の木の検証を既に受け入れた。ここで射程外へ戻すのは退行である。
- **接頭 → ローカル経路の対応表を正本に書く。** 複製の置き場所は機械ごとに違う。
  正本に書けば、その模型は特定の機械でしか検証できない嘘の宣言になる。
- **接頭の集合を出所から機械が推す（宣言を置かない）。** 推した集合は「書き手が跨ぐと
  意図した集合」と区別できない。接頭の書き誤り（typo）が「新しいリポジトリ」に見え、
  検証不能の山に静かに埋まる。宣言が在れば書き誤りは所見になる。
- **相手リポジトリの統治木を depends_on で指す。** リポジトリを越えた統治はしない
  （NONGOAL-001 第10項）。越境の参照は EXT アンカーで引く（ADR-057）。

## 決定

1. **一つの MODEL が複数のリポジトリの系を描くことは射程内とする。** これは系の記述で
   あって、リポジトリを越えた統治（越境の識別子・依存）ではない（NONGOAL-001 第10項は
   動かさない）。
2. **跨ぐ接頭は正本 .md のフロントマターの任意キー `repos` に宣言する。** 形は文字列の
   一覧で、各項は `接頭=指し先`。指し先は `self`（この正本が住む木）か、相手リポジトリの
   識別と固定点を持つ EXT 文書の id とする。同じ接頭の二度宣言は形の誤り。宣言に使った
   EXT は当該文書の `sources` にも載せる（監査の ext_anchor_broken が見張れるように）。
3. **ローカル経路は宣言しない。** 検証時の束縛は従来どおり呼び手の
   `--repo 接頭=経路`（ADR-158）が担う。宣言（何を跨ぐか）と束縛（どこに在るか）を
   分ける。
4. **宣言が在るとき、本文が使う接頭は宣言の集合に含まれなければならない。** provenance の
   `source` とアンカーの `target` の接頭が対象。リンタが文書の中だけで検める
   （`MODEL_UNDECLARED_REPO`。形の崩れは `MODEL_BAD_REPOS`）。宣言が無い模型は従来
   どおり検査しない（後方互換）。
5. **宣言は `model-index/1`（ADR-169）が写して返す。** 消費者はこの口から、模型が
   跨ぐ接頭と相手の識別を知る。投影の JSON には載せない —— 器（lens 側 `schema.json`）の
   語彙に doctrine が欄を足すことはしない（ADR-165 の分界のまま）。

## 帰結

- SPEC-031 に `repos` の形と二つの所見の名が載り、`_model.py` が接頭の解析の正本を持つ
  （出所の門が持っていた解析と二重にしない）。TEST-031 が受入を持つ。
- MODEL-001 に `repos: ["doctrine=self"]` を実例として宣言する。
- `map-draft-check` の挙動は変えない。束ねられなかった接頭の出所が機械検証不能に載る
  のは従来どおりで、その量は出所ごとの判定（ADR-171）で読める。
- 保証限界: 宣言した EXT の実在と鮮度は文書の中では閉じない（監査と `review_by` に
  委ねる）。接頭が指すリポジトリの取得（複製）は道具の仕事ではない。
