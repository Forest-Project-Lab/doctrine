# 境界の語彙は、意味の規範を機械可読の正本へ、表示の語を view の領分へ分ける

## 背景

doctrine-lens が #294 第5信で判断を求めた（欠けの6番と小2点）。器（lens 側
`schema.json`）は列挙の語を定めるが、各語の**人が読む名**と「どの語を実測と数えるか」
は定めておらず、lens は 8 つの表示の表を自分の `registry.json` に手書きしている。
「両方が持つと必ず割れる —— 器 0.1 が二つ在った件と同じ形」であり、どちらが持つかを
決めてほしい、という問いである。小2点は、実測対象アンカーの述語（lens は「権威が
doctrine かつ種別が code_range」で絞る）と、鮮度の判定規則（記録時の版といまの版の
同一・相違・不明の三値）の正本の在り処である。

## 却下した選択肢

- **表示語彙の正本を doctrine が持つ。** 読者層は対象ごとに宣言され（ADR-160 決定4）、
  同じ正本から粒度の違う投影を描く（ADR-161 決定6）。読者ごとに変わる文言を上流が
  一枚の表で持てば、view ごとの読者層に合わせられず、結局 view 側に第二の表が生まれて
  割れる —— 問いが避けたい形そのものになる。
- **表示語彙を器（schema.json）へ書く。** 器は受け入れる集合の宣言であり、表示は器の
  関心ではない。表示の語を足すたびに器が動き、版の規約（受け入れる集合が狭まる変更は
  版上げ）と無関係な改版が増える。
- **実測の述語を doctrine 側にも写す。** 写しは割れる（ADR-165 決定2・決定6 と同じ
  判断）。doctrine の門の検査 D4（アンカーと追跡範囲の照合。SPEC-029）が持つ絞り
  （doctrine 権威の code_range）は「この門が機械で検証できる範囲」の宣言であって、
  「表示で実測と数える」の正本ではない —— 二つの問いを一つの表に畳まない。
- **鮮度の規則を暗黙のまま残す。** lens は「不明を肯定として描いていた欠陥を直した
  ばかり」と報じており、規則が二箇所に在れば再発する。規則は版の鍵を宣言した場所
  （ICD-002）に一度だけ書く。

## 決定

1. **表示語彙（列挙の値の人が読む名・画面の割り付けの表）は view の領分とする。**
   doctrine は正本を持たず、検査もしない。view は自分の読者層（ADR-160）に合わせて
   表示の語を選ぶ。
2. **「どの語を実測と数えるか」（実測対象アンカーの述語）の機械可読の正本は、lens 側
   requirements 口（`system-map/requirements/1`）の `policy` とする。** doctrine は
   写しを持たない（依存は EXT-008 の登録のまま）。doctrine の門の検査 D4 の絞りは
   「この門が検証できる範囲」の宣言に留まり、表示の述語の正本を名乗らない。
3. **鮮度の判定規則は ICD-002「測った木の版と作り手」の宣言に一度だけ定める。**
   記録時といまの `source_revision` が共に完全 SHA（コミットを一意に指す指紋）で等しく、
   かつ、いまの `source_dirty` が false なら「同一」。共に完全 SHA で異なれば「相違」。
   どちらかが null、または、いまの `source_dirty` が true か null なら「不明」。三値で
   あり、**不明を肯定（同一）に丸めない**。
4. **判断の分け方の原則を記録する** —— 意味（何が実測か・何が新しいか）は機械可読の
   正本を一つ持つ側に置き、表示（どう読ませるか）は読者層を知る view に置く。以後の
   同型の問いはこの線で分ける。

## 帰結

- ICD-002 に鮮度の三値の規則が載る（版の鍵の宣言の一部。model → graph の影響は ICD を
  通る）。
- NONGOAL-001 に「表示語彙の正本を持たない」を一項として足す（19項になる）。
- lens 側の 8 つの表示の表は lens の正本のままでよい。doctrine 側に対応する表は
  作らない。
- 保証限界: view が表示の語を誤って選ぶことは doctrine には検められない（表示は検査の
  対象外）。requirements 口の `policy` の存続と意味は lens 側の宣言に依る（EXT-008 の
  `review_by` と #294 の告知に委ねる）。
