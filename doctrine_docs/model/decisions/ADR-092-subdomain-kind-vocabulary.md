# ドメインの種類は語彙だけを正本に持つ。投資の判断は決定と非目標が持ち続ける

## 背景

`domain` は在るが、その区画が中核（core）か補完（supporting）か一般（generic）かを表す項が無い。
種類ごとに投資の仕方を変えろというのが出所の本 1.2 の定めであり（中核は内製、一般は買う、
補完は外注してよい）、その判断が木の中に置けない。報告はそう指した。

**測った。まず「その判断がいまどこに書かれているか」から。**
呼び手（編集器の拡張）の木を、報告が挙げた三行に当てて突き合わせた。
越境の id は裸で書かない（NONGOAL-001 第11項）ので、役で示す。

| 種類 | 呼び手の木でいまどこに在るか | 型 |
|---|---|---|
| 中核 | 最上位の要求（起点から直す順を辿ること）と、それを実現する一本の仕様 | REQ・SPEC |
| 補完 | 上流の命令への橋渡し・追跡索引への橋渡し・コード側の面（作ったが差別化ではない三本） | SPEC |
| **一般** | **非目標の文書の「統治の規則を持たない」「図を描かない（作図ライブラリも持たない）」と、上流へ委ねる二本の決定** | **NONGOAL・ADR** |

**三種類はすでに書かれている。散らばっているだけである。** しかも呼び手の非目標の文書は
出所の本の §3.3.3 を根拠に引いており、同じ本から同じ判断をすでに下していた。

一般だけは形が違う。**一般とは作らないと決めたものであり、作らないものに仕様は無い。**
呼び手の一般の四項（統治の規則そのもの・フロントマターの解析・拡張の枠組み・グラフ走査の常道）
は、四つとも上流か土台へ委ねた決定であって、呼び手の木に文書を持たない。
**だから項を文書に付けても、一般は決して現れない。**

この体系自身の木も測った。

| 測ったこと | 結果 |
|---|---|
| `内製`・`外注`・`買う`・`差別化`・`競争優位` の出現 | **0 件** |
| `コア` の出現（`plugin/scripts/`） | 19 件。**すべて「共有コア」= 共有モジュールの意味**（ADR-021・ADR-024） |
| ドメインごとに一つ在る文書 | `ICD` が 8 ドメインに 8 件（`_system` は ICD を持たない。ADR-091） |
| 呼び手の木のドメイン数 | **1。そこに三種類が同居している** |

**この体系では買う選択肢が無い**（標準ライブラリだけで動く。確定事実7）。だから種類の判断を
自分の木で使う場面は薄い。それでも語彙を上流が持たないと、木ごとに別の語彙が生まれる。

## 却下した選択肢

**同じ `domain` の中の種類の食い違いを検査する（報告の提案C）。** 実測が反対する。
**呼び手の木はドメインが一つで、その中に三種類が同居している。** 検査を入れれば、
**正しい状態を疑わしいと言う。** 中核と補完と一般が一つの区画に混在するのは異常ではなく、
一つの区画を三つの投資に分けているという普通の姿である。

**項に `review_by` と再点検の周期と期限切れの検査を要求する（報告の提案B）。**
報告は「分類は頻繁に変わるのに変遷を追う仕掛けが無い」と言う。**変遷は追えていた。**
呼び手で中核が入れ替わったとき、8 文書が `deprecated`／`superseded` へ移り、うち 6 件は
`superseded_by` で後継を指した（決定・仕様・受入がそれぞれ対で入れ替わっている）。
報告自身が「この 8 件は退いた区画と一件も余らず一致する」と書いている。
**文書で表せば遷移の機構がそのまま効き、項で表すと効かない** —— 項の値は上書きできて、
上書きは機械に見えない。追えないものに期限を課すのは、守れない約束である。

**項に投資の判断そのものを持たせる。** 一般が表せない（上記）。しかも判断の在処が二つになる
—— `NONGOAL` が「作らないと決めた」を持ち、項が「一般である」を持つ。同じ事実を二箇所に
持つ形であり、2026-08-02 に ADR-089 で消したばかりの形である。

**新しい型を足す（`SUBDOMAIN` など）。** ADR-091 で同じ判断をした。型を一つ足すと登録簿・
リンタ・雛形・投影・技能・受入の全面に手が入る。**払う費用に対して置きたい内容は一語である。**

**用語辞書へ 中核・補完・一般 を承認語として足す。** `コア` を禁止同義語にすると
**「共有コア」19 箇所が鳴る** —— 長い語に含まれる部分文字列の取り違えであり、
WATCH-001 第2項がまさに戻すなと定めた形である。実測でこの三語は用語チェッカーに
一件も掛からない（普通の語として通る）。**辞書を触る理由が無い。**

**何もしない。** 呼び手が語彙を自分の実装に持つ。呼び手は「統治の規則を二重定義しない」を
要求として持っており、木ごとに違う語彙が生まれれば正本が分散する。
**語彙の正本は上流にしか置けない。**

## 決定

**ドメインの種類は、語彙だけを登録簿の正本に持つ。項は標識に留め、投資の判断は
決定（ADR）と非目標（NONGOAL）が持ち続ける。**

1. **語彙を `_registry.py` に一度だけ置く**（確定事実1）。値は `core`・`supporting`・`generic`
   の三語とし、英語の識別子とする。既存の語彙の項と同じ形であり、日本語の名は付けない
   （辞書を触らない理由は上記）。
2. **`subdomain` を省略可の項として認める。** 省略は「未分類」であり、咎めない。
   値が語彙に無ければ誤り（error）とする（`llm_context` と同じ形。`docs-linter.py`）。
   **検める項だけを足す** —— `LEVEL4_KEYS` は試験で凍結されているのに消費者が無いので、
   そこへは足さない。
3. **一貫性の検査を入れない。** 同じドメインの中に三種類が同居してよい（上記の実測）。
4. **`review_by` を要求しない。周期も期限切れの検査も置かない。** 項の上書きは機械に
   見えないので、期限を課しても守られたことを確かめられない。
5. **投資の判断の在処を規約として書く。** 中核は要求の「優先度」が言い、一般は `NONGOAL` が
   言い、委ねたことは `ADR` が言う。**項はそのどれの代わりでもない。**
6. **節点に `subdomain` を載せる。** 未分類は空文字とし、値が化けないこと。
   入れ物（一覧・写像）が来ても内部表記を漏らさない —— これは一項の話ではなく、
   節点のスカラ項すべてを通る共有の補助の欠陥だったので、そこで直す。
7. **語彙を手書きの期待表で凍らせる**（ADR-060 の様式）。正本から生成しない。
8. **雛形には足さない。** 省略可の項は雛形に現れないのが既定である（`canonical_for`・
   `review_by` も現れない）。**埋める内容が無い欄を配らない**（ADR-084 の規律）。

## 帰結

- 呼び手は語彙を実装に持たずに引ける。木ごとに別の語彙が生まれる道が閉じる。
- `subdomain` を持たない木では、所見が一件も増えない（省略は未分類であり、検査は値が
  在るときだけ働く）。
- 節点のスカラ項に内部表記が出なくなる。題名でも `llm_context` でも起きていた。
- 保証限界: **一般は項では表せない。** 作らないと決めたものに文書は無く、
  付ける先が無い。一般の判断は `NONGOAL` が持つ。**項が語れるのは、作ったものの種類だけ
  である。**
- 保証限界: **項の値が変わったことは機械には見えない。** 上書きは痕跡を残さない
  （git の履歴は別である）。種類の入れ替わりを木の中で見たいなら、判断を文書の形で書く
  —— そのとき遷移の機構がそのまま効く。
- 保証限界: **何が中核かは機械が判じない。** 判定は木の作者がする（報告もそう求めている）。
  値の当否は `doc-review` と人が見る。
- 保証限界: この体系自身の木では、この項を使う場面が薄い。買う選択肢が無いからである
  （確定事実7）。**自分では埋めない欄を、呼び手のために置くという取引である。**
