# 統治はリポジトリ一つの内側に閉じ、組織を横断する統治は引き受けない

## 背景

外部レビューで、組織を横断する識別子・リポジトリ間の依存・複数リポジトリをまたぐ索引が提案された。近縁の道具でも、仕様が 50 件を超えると階層が要る、複数のリポジトリで置き場所が定まらない、といった報告がある。

いまの体系は、リポジトリ一つの内側に閉じて組み上がっている。統治木の解決はプロジェクト根から辿り、パスはすべて木からの相対で、監査要約の照合も木ごとである。リポジトリを越える経路はどこにも無い。

同じレビューで挙がった他の提案は、それぞれ着地している。構文解析器によるシンボルの同定は ADR-054 の却下した選択肢と RESEARCH-002 に、関係の多状態のモデルは ADR-055（記録するのは指紋だけ）に、編集画面の過剰な仕様は ADR-052 に、外部への送信の統制は DECIDED-001 事実7（通信に依存しない）によって論点そのものが生じない形に落ちている。**残っていたのは、この一件だけである。**

却下したまま記録しないと、同じ提案が同じ説得力で戻る。採用の記録だけを残して却下を捨てるのは、退行を招く。

## 却下した選択肢

- **いま組織を横断する識別子と名前空間を導入する**: 抽象の先取りである（`[R8]`）。この体系はリポジトリ一つで動いており、二つ目の痛みがまだ出ていない。衝突の解決規則・名前空間の切り方・どちらが正本かを、必要になる前に決めることになる。決め方を誤っても、痛みが出るまで気づけない。
- **何も決めずに置く**: 却下の記録が無い提案は再燃する。議論を毎回やり直す費用を、将来の自分に払わせる。

## 決定

統治の対象は、リポジトリ一つの内側に閉じる。NONGOAL の第10項として明記する。

- リポジトリを越えた参照が要るときは、EXT アンカー（出所の参照。ADR-026）で引く。相手のリポジトリの統治木を、直接の依存先にはしない。
- 二つ目のリポジトリで実際に痛みが出たときに、そのときの形で決め直す。そのときは本 ADR を置換する。

## 帰結

- 同じ提案が戻ったとき、この記録を示して短く終えられる。議論をやり直さない。
- 越境の唯一の経路が EXT アンカーに定まる。既にある機構で足り、新しい機構を増やさない。
- 外部レビューの提案が、採用・却下ともすべて統治木のどこかに着地した状態になる。宙に浮いた提案が残らない。
- 既知の限界: 本 ADR は「いま引き受けない」を定めるものであって、永久にできないと言うものではない。痛みが出たら置換する道を開けてある。
