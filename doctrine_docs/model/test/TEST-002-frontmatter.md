# フロントマター解析契約のテスト計画

SPEC-002 のフロントマター解析契約を検証する。実装テストは `plugin/tests/test_frontmatter.py`（解析の事例 T1（解析行列の事例番号）から T27（同）までの解析行列）。[R3][R8]

## 受入基準への対応

- `parse` がどの入力でも例外を投げない。
- フロントマター無しなら `({}, text, [])` を返す。閉じ無しなら残りを解析し、body を空とし、`missing_close` を記録する。
- 真偽値（true/false だけ）・None・空文字・空リストを区別する。
- 本文の CRLF をそのまま残す。重複キーは後のものを採り、`duplicate_key` を併記する。
- フローリスト・引用・行内の注記を正しく扱う。`as_list` が None・スカラ・リストを正しく変換する。
- `body_start_line` が本文の開始行を 1 起点で返す。フロントマターの有無と長さを変えて確かめ、フロントマターが無いときは 1 を返すこと、文字列でない入力でも例外を投げないことを見る（ADR-083）。
- ADR-075: 通常ファイルでないもの（名前付きパイプ・デバイス）を `parse_file`／`read_text` が開かず `OSError` を返すこと。呼び手が捕捉して黙って飛ばすこと。

- 読み取りの門（ADR-107）: 寛容に読む経路（語の抽出）が非通常ファイルで**門の文言**を返すこと（以前は素の `open` の例外だった。**文言が変わることが門を通った証拠である**）、UTF-8 でない内容を置き換えて読めること（意図された寛容さが残ること）、不在は警告で落ちないこと。正本が門を呼び、復号の方針の既定が厳密であること。**歯止め自身の実効を実測してある**（2026-08-03）: 自前の `open` へ戻す／正本から門を外す／既定を寛容へ替える、の三通りで落ち、いずれも戻すと通った。
- スカラへの正規化（ADR-101）: 文字列はそのまま、`None`・真偽値・入れ物（一覧・写像・組）は空文字、その他のスカラは `str()` になること。
- 日付の解釈（ADR-099）: `parse_date` が `2026-01-01` を解し、`2026-01-01xyz`（終端の錨）・`2026-02-30`（実在しない日）・`26-1-1`・空・非文字列を `None` にすること。前後の空白を削ること。`PlaceholderFieldsTest` と併せて `test_frontmatter.py` が確認する。
- 雛形の指示文（ADR-098）: 値の全体でも一部でも一致し、一覧の要素も見て、非文字列は無視し、`<>`・`< >` を指示文としないこと。鍵の順に返すこと。

## 退行観点

- **共有の判定の写しをコアの外に持たないこと**（ADR-099・ADR-101）。手で書いた表（関数名 → 正本のモジュール）で凍らせる。**写しが生まれるたびに「一箇所だけ直す」事故が起きる** —— 実際に二度起きた（日付の解釈は四写しのうち一つが終端の錨を欠き、スカラへの正規化は入れ物の直しが一箇所しか届かなかった）。
- **日付の解釈をこのコアの外に持たないこと**（ADR-099）。関数（`_parse_date`／`parse_date`）も日付の正規表現も、正本の外に在ればメタの受入が落ちる。**薄い前面すら置かない** —— 前面を置くと後からそこで挙動を変えられる（実際、緩い写しが一つ在って `2026-01-01xyz` を受けていた）。

- `入出力` の中の `出力` のような複合語を誤検出しないのは用語チェッカー側の役目だが、解析が本文を改変しないことを確認し、下流に誤検出の元を作らない（WATCH-001 と整合する）。
- `missing_open` を `parse` が出さないこと。
- `parse_file` が、内容では例外を投げず、読み書きや復号の失敗のときだけ例外を投げること。

## 合否基準

T1–T27 の全ケースが期待どおりの (fm, body, errors) を返し、どの入力でも例外を投げないことと、CRLF をそのまま残すことが成り立ったとき合格とする。
