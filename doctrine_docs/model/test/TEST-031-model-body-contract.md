# 意味モデルの本文の形と担保のテスト計画

SPEC-031 の契約を検証する。実装テストは `plugin/tests/test_model.py`。[R2][R6][R8]

## 受入基準への対応

- 解析: 六つの節の塊が節ごとに拾われること（`ParseTest`）。必須節の外の塊が値にならないこと。
  読めない塊が所見になり、その塊だけが落ちること。
- 担保: 必須欄の欠落・語彙の外れ・id の重複・見出しと id の食い違い・文書の中に無い参照
  （流れの端・シナリオの段）・理由の無い自己ループ・空の出所・出所の verdict の外れが、
  それぞれ固有の名の所見になること（`StructureTest`）。
- 確定の同値: `status` が `current` で値が `proposed` なら所見、全ての値が `confirmed` で
  `status` が `current` でなければ所見、両方が揃えば所見なし（`ConfirmationTest`）。
  アンカーは確定を担わないこと。
- 描画: 最上位が八つの欄を持ち、`target` が最上位へ持ち上がり、解析の覚え書きが JSON へ
  出ず、同じ入力から同じ文字列になり、文書の中の出現順が保たれること（`RenderTest`）。
- 口: `render-projection.py model` が正本の .md の隣へ .json を書くこと。`--check` が未生成と
  ドリフトを非ゼロで落とすこと。壊れた模型を描かないこと。`--id` の指し先が無ければ 3、
  `--out` を単独で使えば 2 を返すこと。`all` が MODEL の投影を含むこと（`RendererCliTest`）。
- 二重定義の不在: リンタが同じ規則で MODEL の本文を咎めること（`LinterWiringTest`）。
  必須節の検査（登録簿の側）と本文の検査（この部品の側）が重ならないこと。

- 硬化（ADR-164）: 配列でない `realized_by`・`null` の必須欄・空でない文字列でない id・
  塊を持たない見出し（囲みの綴りの取り違えを含む）が、それぞれ固有の名の所見になり、
  **例外を漏らさない**こと。引退した位置づけでは確定の同値を検めないこと。
  `MODEL_CONFIRMED_NOT_CURRENT` が WARN で、その文面が機械へ確定を指示しないこと。
  節名が登録簿から導かれていること。`prose_values` が散文の欄だけを返すこと
  （`HardeningTest`）。

- 器からの導出（ADR-165）: 必須欄・段の必須欄・出所の必須欄・語彙が、同梱した器の一枚と
  一致すること。器の一枚を読めないときに `MODEL_SCHEMA_UNREADABLE` だけを返すこと
  （`SchemaDerivationTest`）。

## 退行観点

- **壊れた模型を描かない**こと。所見の在る本文から JSON を書き出すと、消費者が壊れた値を
  読む（門の所見が出た後で、古い JSON が残り続ける形にしない）。
- **必須節の外の塊を値にしない**こと。散文の例示を値へ格上げすると、書き手が説明を書けなく
  なる。
- 語彙の写しが増えていないこと。`map-draft-check.py` が自前の列挙を持ち直していないこと
  （ADR-163 決定8。以前は門の側に写しが在った）。
- 兄弟文書を読む経路が入っていないこと（per-turn の規律）。
- **節名の手写しが戻っていないこと**（WATCH-001 第2項と同じ形の退行。登録簿から導く）。
- **器の必須欄・語彙の手写しが戻っていないこと**（ADR-165。散文の手引きから採る形へ戻すと、
  名乗った器に適合しない投影が緑で通る。実測: Scenario の必須欄が器の九つに対し五つで、
  上流の門が落とした）。
- **確定の同値が引退の道を塞いでいないこと**。確定を経た模型を廃止・置換・退避へ移せること。
- **助言が機械へ確定を指示していないこと**（`status` を動かすのは人だけである）。
- 確定の同値の検査が、値を一つも持たない文書で発火しないこと（空の模型を「全て confirmed」と
  読まない）。

## 合否基準

`plugin/tests/test_model.py` の全テストが成功し、リンタと描き手が同じ所見の名を返したときに
合格とする。所見の名（SPEC-031 のエラー時挙動の一覧）が変わったときは、本計画と実装テストを
同じ変更で直す。
