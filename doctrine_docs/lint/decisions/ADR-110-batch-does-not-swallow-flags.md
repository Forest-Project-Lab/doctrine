# 点検の門は、使い方の誤りを場所として飲まない。見た数を必ず言う

## 背景

リンタの一括点検は、`--batch` の次の語を**無条件に統治木の場所として飲む**。
使い方を解く処理を持っていない。

測った。

```text
[0] --batch --root doctrine_docs  => 統治木が無い(--root)。点検対象なし。
[0] --batch --fail-on error       => 統治木が無い(--fail-on)。点検対象なし。
[0] --batch /nonexistent/xyz      => 統治木が無い(/nonexistent/xyz)。点検対象なし。
```

**旗のつもりで書いた語がそのまま場所になり、門は何も点検せずに緑を返す。**
CI に置けば、毎回そうなる。

この体系は既に規約を持っている。**兄弟四本は、知らない旗を終了コード 2 で拒む。**

| 門 | 知らない旗 | 実在しない根 |
|---|---|---|
| 全件監査 | **2** | 0（意図した配慮） |
| 追跡の索引 | **2** | **3** |
| 依存グラフ | **2** | — |
| 語の抽出 | **2** | — |
| **リンタの一括点検** | **0（場所として飲む）** | **0** |

**一本だけが規約の外に在る。** しかも規約は散文にも書いてある —— 全件監査の仕様は
「使い方の誤りとして終了コード 2 を返す。黙ってシステム時刻に切り替えることはしない」
と定めている。**同じ判断が、この門にだけ届いていない。**

出所は利用者側である。**この形のまま門を回していた。** 正しく呼び直したところ、
85 文書に 241 件の ERROR（点検の所見のうち、マージ前に止める重さのもの）が出た。
**門は在ったが、効いていなかった。**

そして**この体系は、その形を雛形として配っている。** 可搬性の手引きの
pre-commit の例は `--batch doctrine_docs` と書いており、木の名が `docs/` の
導入先では実在しない場所を指す。測った。

```text
[0] （雛形どおり）--batch doctrine_docs => 統治木が無い。点検対象なし。
[1] --batch .                           => 1 文書に 8 件の ERROR。
```

**同じ木に、死んだ門と生きた門がある。** 配っているのは死んだほうである。

最後に、成功の文面が**何を見たかを言わない**。「ERROR なし」は、
85 文書を見て無かったのか、一つも見ていないのかを区別しない。
**見ていない門を緑と読む余地が残る。**

## 却下した選択肢

**`-` で始まる語だけを場所として受けない。** 報告された欠陥は塞がるが、
場所の綴り違い（`doctrne_docs`）は塞がらない。**同じ出口から同じ黙りが出る。**

**実在しない場所も 0 のままにする（註記だけ足す）。** 註記は誤った呼び方を止めない。
実際、利用者側は頭注を読める場所に置いたまま、その形で回していた。

**すべての場所不在を非ゼロにする（統治木でない場所も落とす）。**
**素の `docs/` を持つ導入先を CI で落とす。** これは全件監査が明示的に避けた配慮であり
（仕様が「所見ゼロと同じ扱いにして終了コード 0」と定める）、**緩める側ではなく、
配慮の範囲を正しく切る側で直す。**

**使い方の解析を共有コアへ出し、五本で共有する。** 五本は受ける旗がまったく違い、
**共有できるのは「知らない旗を拒む」という一行の判断だけ**である。
写しの統合の類型（同じ判定が二箇所に在る）ではなく、**一本が規約を実装していない**
だけである。器を先に作らない。

**見た数を言わない（終了コードだけ直す）。** 終了コードは呼び方の誤りを捕らえるが、
**正しく呼んで空振りしている場合**（木が実在して空、または `.md` が無い）は
依然として 0 と「ERROR なし」だけになる。**門が何件見たかは、門にしか言えない。**

## 決定

**リンタの一括点検が、使い方を解く。空振りは文面と終了コードで見えるようにする。**

1. **知らない旗と余分な語を、場所として飲まない。** 使い方を出して終了コード 2
   —— **兄弟四本と同じ規約である**（新しい規約を作らない）。
2. **実在しない場所は根の不在として非ゼロ。** 追跡の索引と同じ 3 を返す。
3. **実在するが統治木でない場所だけが 0 に残る。** 素の `docs/` への配慮は
   もともとここを指していた。**配慮は狭めるのではなく、正しく切る。**
4. **見た数を必ず言う。** 成功も失敗も、点検した文書の数を文面に出す。
5. **同梱の雛形を、木の名に依らない呼び方へ直す。** 配る門が死んでいてはならない。

## 帰結

- 旗の綴り違いで門が静かに無効になる道が閉じる。
- CI の記録を見た人が、門が何件見たかを読める。
- **素の `docs/` を持つ導入先は、いままでどおり落ちない**（3 の面）。
- 保証限界: **正しく呼んで木が空のときは、依然として 0 である。**
  「点検 0 文書」と文面に出るが、**それを読むのは人であって機械ではない。**
  この体系は「木が空であること」を欠陥とは判じない（そう判ずると、統治を始める前の
  導入先を叱ることになる）。
- 保証限界: **終了コード 3 は、場所が実在しないことだけを言う。** 権限が無くて開けない
  場合など、実在するのに読めない場合は 3 に含まれない。
- 保証限界: **利用者側が終了コードを読むかどうかは、この体系の外である。**
  報告された事例は 0 を緑と読んでいた。**言うところまでが保証で、読ませることはできない。**
