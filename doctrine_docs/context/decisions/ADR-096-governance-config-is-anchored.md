# 統治の設定を指紋で見張る。変えるには打ち直しが要る

## 背景

報告の RFC（設計方針の提案）は不変条件の一つに
`G(config_hash_changed -> protected_action_denied_until_reattested)` を挙げた。
**設定が変わったら、打ち直すまで守られた操作を拒む**という形である。

測った。**この体系の設定は、何にも見張られていない。**

`_system/.context-config.json` を読むスクリプトは五本ある。

| 読む側 | 何を読むか |
|---|---|
| `collect-context.py` | パックの上限 |
| `inject-contract.py` | **常時投入の上限**（既定 12000。確定事実6） |
| `docs-audit.py` | 調整値・追跡の様式・適用除外 |
| `gov-heartbeat.py` | 追跡の様式 |
| `_audit_trace` 経由の走査 | 適用除外の道 |

つまりこの一枚は、**常時投入の上限・追跡の悉皆の様式・走査の適用除外**を握っている。
静かに書き換えると、上限が動き、残高の警告が消え、任意の道が走査から外れる。
**確定事実12 は「フックの境界は沈黙して開かない」と定めているのに、境界を決める設定
そのものが沈黙して開く。**

そして測ると、**見張る機構は既に在って、この一枚だけが乗っていなかった。**

| アンカー | 対象 | 検査 |
|---|---|---|
| `EXT-002` | `.claude/settings.json` | exists |
| `EXT-004` | 継続的結合の定義 | exists |
| `EXT-003` | 上位設計書 | **hash** |
| —— | **`_system/.context-config.json`** | **無い** |

雛形は対象の例として「`.claude/settings.json` のマーケットプレイス登録、上位設計書、
**CI の定義、実行環境の仕様**」を挙げている。**設定ファイルは最初から想定された対象で
あった。** 外側の設定は二つとも繋いであり、**統治の設定だけが繋がれていなかった。**

## 却下した選択肢

**打ち直すまで操作を拒む（RFC の逐語）。** 拒むには「何を打ち直したか」を機械が
確かめる必要があり、それは attestation の信頼根を要する。ADR-093 で断った理由と同じ
—— 標準ライブラリだけで動き通信もしない体系に信頼根は無い。**拒否の代わりに、
人の目が一度入ることを保証する**（EXT-003 が同じ言い方で立てた期待である）。

**新しい検査を書く（`config_changed`）。** 前回の要約と比べる形になる。**継続的結合では
前回の要約が無いので、その検査は CI で一度も働かない。** 一方この体系の門は CI であり、
働かない検査は飾りである（2026-08-02 に三度直した形）。

**要約に指紋を載せるだけにする。** 載っても誰も比べない。実際、適用除外の件数
（`exempt_files: 51`）は既に要約に載っているのに、**増えても誰も気づかない。**
**在ることと効くことを分けない。**

**検査を `exists` にする。** 存在は変わらない。変わるのは中身である。
外側の二つ（`EXT-002`・`EXT-004`）が `exists` なのは、あちらが「繋がっていること」を
見るためであり、こちらは**中身の変化**を見る。

**設定を凍らせる（変更を禁じる）。** 適用除外は正当に変わる（呼び手は持ち込んだ道具の
ぶんだけ狭めた）。禁じるのではなく、**変えたことが目に入る**ようにする。

## 決定

**統治の設定 `_system/.context-config.json` を、指紋で見張る外部アンカーの対象にする。**

1. `EXT-005` を置く。**対象は `doctrine_docs/_system/.context-config.json`、検査は hash**
   とする。既存の機構（ADR-026 のアンカー、ADR-039 の hash 検査）だけを使い、
   **新しい検査もコードも足さない。**
2. **指紋が動いたら監査が warn を出す**（`ext_anchor_broken`）。止まるのは門であり、
   操作ではない。**打ち直しは人手** —— 設定を変えた人が、変えた内容を確かめて指紋を
   打ち直す。その打ち直しは差分に現れる。
3. **指紋は内容の正しさを保証しない。** 変化に人の目が一度入ることだけを保証する
   （EXT-003 と同じ言い方）。
4. 置き場所は `context/external/` とする。この一枚が握る最も重い値は常時投入の上限で
   あり、その正本は context の ICD が持つ（確定事実6）。
5. **セッション途中の設定の差し替えは、依然として検知しない**（非目標 第16項）。
   こちらが見るのは、監査が走る時点での**ファイルの中身**である。二つは別の問いである。

## 帰結

- 上限・悉皆の様式・適用除外のどれが動いても、門が一度止まる。**差分に打ち直しが現れる。**
- 新しい検査が増えない。**機構は在ったので、乗せるだけで済んだ。**
- 呼び手の木でも同じことができる（あちらのアンカーはあちらが置く。こちらは強制しない）。
- 保証限界: **指紋は中身の当否を見ない。** 危ない値へ変えても、打ち直せば通る。
  見ているのは「黙って変わらないこと」だけである。
- 保証限界: **設定が無い木では何も見ない。** アンカーは対象の不在を error にするので、
  設定を消すと止まる —— それは意図した挙動である（握っている値が既定へ戻ることは
  黙って起きてよい変化ではない）。
- 保証限界: 監査が走らなければ何も起きない。門は継続的結合とセッションの区切りに立つ。
- 保証限界: セッション途中の差し替えは見ない（非目標 第16項）。**攻撃者が監査の直後に
  書き換え、次の監査までに戻せば、機械には見えない。**
