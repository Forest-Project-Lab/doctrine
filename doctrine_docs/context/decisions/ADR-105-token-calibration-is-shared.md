# トークンの見積りを共有コアに一度だけ置き、較正を二つの上限の両方に効かせる

## 背景

トークンの見積りが**二箇所に別々に在り、較正の設定が片方にしか効いていなかった。**

`collect-context` の見積りの説明文はこう書いている。

> 較正が要る導入先は設定の `model_chars_per_token` を下げる。

**読んでいない。** 呼び出しは二箇所とも既定の 4.0 のままで、設定を見ない。設定を読むのは
`inject-contract` だけである。測った（設定に `model_chars_per_token: 2.0` を置いて、
同じ 1000 文字を与えた）。

| 見積り | 答え |
|---|---|
| 注入（較正を読む） | **500** トークン |
| パック（較正を読まない） | **250** トークン |

**同じ内容の重さが二通りある。** パックの上限は**未較正の見積り**で判じられており、
較正した木では**意図の二倍の量が入る。**

確定事実6 は「注入の上限とパックの上限は別々の二つのキーで持つ」と定める。**それは
上限の話であって、較正の話ではない** —— `model_chars_per_token` はモデルの性質であり、
どちらの上限を判ずるときも同じ値であるべきである。

**もう一つ、壊れた値への頑健さが違う。**

| 較正の値 | `collect-context` | `inject-contract` |
|---|---|---|
| `0` | **例外（零除算）** | 既定へ退避（250） |
| `-1` | **-1000（負のトークン数）** | 既定へ退避（250） |
| `'x'` | **例外** | 既定へ退避（250） |

**負のトークン数がいちばん悪い。** 上限との比較が必ず通るので、**上限が黙って無効になる。**
いまは較正を読んでいないので届かないが、**較正を読ませる（この決定の主眼）と同時に
届くようになる。** だから先に頑健な側へ揃える。

日付の解釈（ADR-099）・スカラへの正規化（ADR-101）・設定の読み取り（ADR-104）に続いて、
**同じ写しの類型の四件目**である。

## 却下した選択肢

**`collect-context` にも設定を読ませるだけ（写しは二つのまま）。** 頑健でない側が設定の
値を受け取るようになる。**零を書いた木でパックの組み立てが落ち、負を書いた木で上限が
黙って無効になる。** 直すべきは「読まないこと」だけではない。

**説明文を直して挙動を残す（較正はパックに効かないと書く）。** 較正はモデルの性質であり、
片方の上限にだけ効く理由が無い。**説明文の側が正しい。**

**確定事実6 を根拠に、較正も上限ごとに別々にする。** 事実6 が別々にすると定めたのは
**上限**である。較正まで分けると、同じ木の同じ内容が二通りの重さを持つ状態を**設計として
認める**ことになる。それはいま起きている欠陥そのものである。

**見積りを `_config` へ置く。** ADR-104 は「調整値の意味と既定は呼び手に残す」と決めた。
較正の解釈をあちらへ入れると、その線を自分で崩す。**較正は二つの呼び手が共有する調整値**
なので、共有の場所は要るが、それは設定の読み取りの正本ではない。

**新しいコアを作らず、どちらかの実装を正本と呼ぶ。** 入口のスクリプトを別の入口が取り込む
形になる。共有の判定は `_` で始まるコアに置くのが既存の作法である（ADR-104 で `_config` を
置いた前例がある）。

## 決定

**トークンの見積りと較正の解釈を共有コアに一度だけ置く。較正は二つの上限の両方に効く。**

1. **`_tokens.py` を置き、そこが正本とする。** 既定の文字数／トークン、見積り、
   **較正の解釈**（設定から `model_chars_per_token` を解く）を持つ。
2. **二つの写しを消し、呼び手は正本を呼ぶ。** 薄い前面も置かない（ADR-099・ADR-101・
   ADR-104 と同じ理由）。
3. **較正は両方に効かせる。** パックの見積りも較正を読む。**上限は別々のまま**
   （確定事実6 は守る）—— 分けるのは上限であって、較正ではない。
4. **壊れた較正の値は既定へ退避する。** 例外を投げない。**負のトークン数を返さない**
   （上限が黙って無効になるので、これが芯である）。零・負・非数・真偽値はすべて既定へ。
5. **機械が写しを咎める。** 見積りを正本の外に定義したら、メタの受入が落ちる。

## 帰結

- 同じ内容の重さが、木の中で一つになる。較正した木でパックが意図の二倍にならない。
- 上限の分離（確定事実6）は変わらない。**変えたのは較正の届く範囲だけである。**
- 保証限界: **見積りは文字数の近似であり、実トークンではない。** 4 文字／トークンは
  英語の近似で、日本語では実トークンを下回りうる（ADR-075 が記録した限界であり、
  ここでは変えない）。
- 保証限界: **較正の値が妥当かは見ない。** `2.0` が正しいかは測らない。壊れた値を
  既定へ退避させるだけである。
- 保証限界: **較正を設定した木では、パックの内容が変わる**（同じ上限でより少なく入る）。
  意図した変更であり、較正した木でだけ起きる。
- 保証限界: 機械が咎めるのは名前の形である。別の名前で同じことをすれば掴めない。
