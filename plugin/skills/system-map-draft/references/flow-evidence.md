# Flow の根拠（M-08 の徹底）

依存グラフは Flow の根拠にしない。`dep-graph.py` の辺（`depends_on`・`impacts`）は文書が文書を前提とする関係であり、実行のとき何かが流れる証拠ではない。辺を Flow へ機械変換した模型は M-08 で落ちる。

## 根拠になる記述の例

- subprocess の呼び出し — コードが CLI を起動する行（何を・どんな引数で呼ぶか）。
- hook の配線 — settings の配線（どの事象で・どのスクリプトが動くか）。
- 文書の記述 — 「A が B へ渡す」「B は A の返す JSON を読む」という文そのもの。

いずれの場合も、読んだ場所を Flow の `provenance` に書く。

## 根拠が取れないとき

- 原則: 書かない。「流れが在りそう」という推測だけの Flow を作らない。
- 「流れが在るはずだが確かめられない」という判断自体を残す価値があるなら、Flow ではなく `unknown` の contract として、負の出所（どこを見て・いつ・`silent` だったか。M-11）とともに残す。

## 子の越境 Flow（M-04）

子要素が親の境界を越える Flow は、親の外部入出力へ集約できる形にする。親どうしの Flow を先に書き、子どうしの Flow は `condition` などで親の Flow への集約を示す（手本: `target-1` の `cf-bridge-invoke` は親の `f-invoke` へ集約される）。
