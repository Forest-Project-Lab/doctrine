# 統治木の外の .md ファイルの取り込み

統治木の外にも .md ファイルは在る。README・CONTRIBUTING・AGENTS・CLAUDE、仕様の下書きなど。これらは管理対象の文書とは限らない。この案内は、それらを検出し、分類して扱い、判断の結果を記録する。監査(`docs-audit.py` の `stray_document` 検査、ADR-021)は記録に無い .md と期限切れの保留を挙げ続けるので、統治木の外に .md が生まれ続けても、分類されないまま埋もれることはない。

## 検出

まず統治木の名前を解決する。既定は `doctrine_docs/`。`_system/` を持つ `docs/` も後方互換で統治木と認める(ADR-022)。以下の `<統治木>` は解決した名前で読み替える(この解決を飛ばして `doctrine_docs/` を決め打ちすると、後方互換の `docs/` 木では統治下の全文書を「外」として誤って列挙してしまう)。

`git ls-files '*.md' ':!:<統治木>/**'` で統治木の外の追跡下の .md を出す。git は .gitignore を尊ぶので node_modules は出ない。git が無い・使えない、または git 管理でないときは `find . -name '*.md' -not -path './<統治木>/*' -not -path '*/node_modules/*' -not -path './.git/*'` を使う。追跡下だけを見る git ls-files と、すべてのファイルを見る find では、結果がずれることがある(追跡されていないファイルは find にだけ出る)。除外の `:!:<統治木>/**` は最上位の統治木だけに掛かる。`plugin/doctrine_docs/x.md` のような入れ子は出る。これは `docs-audit.py` の `--root <統治木>` の範囲と揃う。監査の `stray_document` も同じ範囲を機械で走査する(dot ディレクトリと node_modules は見ない)。この検出は作業一覧を作るだけで、何も動かさない。要否は各ファイルごとに人間が判断する。

## 分け方

- 投影: モデルから描き直せる派生表示。正本ではない。倉庫へ退避するか、そのまま残す。
- 出所: 管理対象にすべき事実を持つ。doc-author を呼び、型・ドメイン・フロントマターを正して統治木の `<domain>/` の下へ書く。元のファイルは倉庫へ退避し、後から引けるようにする。
- ビュー(ADR-073): 正本をある時点で人向けに解釈した文書。README・報告・引き継ぎメモなど、正本から導かれた主張を含むもの。そのまま残すが、刻印(`<!-- doctrine:view src=<出所> as-of=<版> date=YYYY-MM-DD refs=<id,…> -->` の一行。書式の正本は audit の ICD-005)を必ず打つ。監査(view_stale)が刻印の欠落を警告し、参照先の古びを助言する。
- 非文書: LICENSE（ライセンス本文のファイル）・変更履歴など、正本から導かれた主張を持たないもの。そのまま残す。

ビューか非文書かの見分けは「正本が変わったら書き直しが要るか」で判じる。要るならビュー(刻印で古びを見えるようにする)、要らないなら非文書。迷ったらビューに倒す — 刻印は安く、欠落は後から復元できない。

型・ドメインの割り当ては人間の判断を要する。自動の規則にしない。doc-author への取り込みでは、その手順とリンタがフロントマターと置き場所を正す。

## 判断の結果を記録する(ADR-021)

下した判断は `doctrine_docs/_system/.md-intake` に一行で記録する。形式は `パス: 非文書|投影|保留|ビュー [YYYY-MM-DD]`。末尾 `/` の項目は配下全体に効く(例: `plugin/: 非文書`)。照合は完全一致がプレフィクスに勝つ(ADR-073。一括分類の配下から一件だけを別分類に取り出せる。例: `plugin/README.md: ビュー` を `plugin/: 非文書` と並べてよい)。保留には期限を必ず書く。監査は、記録に無い .md を「未分類」(助言)として、期限を過ぎた保留を「再浮上」(警告)として、ビューの刻印の欠落を警告として挙げる。記録された非文書・投影と、刻印の新しいビューは挙げない。これは検出を隠す除外の一覧ではなく、下した判断の記録である。記録しなければ、未決だけを機械で選り分けられない。記録の分類が正しいままかは、docs-curate の定例で見直す。

## 途中導入の回し方(移行キャンペーン、ADR-034)

成熟したリポジトリでは未分類が数十件になる。一括で片づけず、次のように回す。

- 台帳は増やさない。進捗の正本は `.md-intake` だけで、未分類の一覧は監査から毎回導出する(二重の台帳を作らない)。
- 1鼓動1件。`gov-heartbeat.py` が、より重い義務が無いときに未分類の先頭1件を統治率(分類済み/対象)つきで促す。SessionStart の注入は残数を常時表示する。促されたら、その1件だけを分類して台帳へ記録する。
- どれから手を付けるかの見立て(判断)。機械の並びは決定的(整列)であり、優先を変えたいときは人が選ぶ。目安は二つ: 被参照の多さ(`git grep -l <ファイル名>` で引用元を数える)と、活動の新しさ(`git log -1 --format=%cs -- <パス>`)。生きていて他が寄りかかる知識から取り込む。
- 中断してよい。台帳が真実を保つので、再開は自動で続きから。分類が進むたびに督促の数は減る。

## 戻せる操作だけ

doctrine_docs/ の外のファイルを自動で消さない。退避・取り込み・そのまま残す・記録するの四つだけを行う。いずれも後から戻せる。抹消は §3.8 の階段を経た管理対象の文書にだけ許す。
