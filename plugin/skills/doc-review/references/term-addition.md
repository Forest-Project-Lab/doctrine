# 承認語の追加（§1）

承認語を増やす、または意味を変えるときは、`ADR` で決め、用語辞書（§1）の表を更新する。各文書はこの表を二重定義しない。`[R6][R8]`

## 流れ

1. 新しい承認語が要る兆候を見つける。同じ語が二つの意味を持つなら、ドメインを分ける合図でもある（§3.1）。
2. `term-extract.py`（`c-TF-IDF`）の候補を証跡にする。これはドメイン特徴語の素案を出すだけで、確定はしない。
3. `ADR` を起こして決める（背景・却下した選択肢・決定・帰結、1文書1決定）。
4. 用語辞書の正本（`doctrine_docs/_system/glossary.md`）の表に一行足す。承認語・唯一の意味・禁止する同義語。
5. 自分で承認しない。`ADR` と辞書更新を必須にする。

## 固有名の登録（`ADR` 不要の例外、§1）

外部の規格・法令・他体系の公式名に、禁止同義語が埋め込まれることがある。固有名は、運用正本（`_system/glossary.md`）の承認語の表へ、意味欄に「固有名」と記して一行足す。用語チェッカーはその語を照合から外す（ADR-018）。固有名の登録は語の意味体系を変えないため、`ADR` は要らない。地の文では承認語を使う。

## 新しいカルク

新しい訳語臭を見つけたら、別ファイルを作らず、運用正本（`_system/glossary.md`）のカルク表に一行足す。使わない表現・直す表現・なぞった英語の三列で書く。カルクの追加に `ADR` は要らない（§1）。

## 連番の払い出し

新しい文書の連番は、体系全体（全ドメイン）で見た同じ型の既存最大に 1 を足す。欠番（割り当て済みの番号）は再利用しない。`ADR` の連番はドメインを跨いで一意である。
